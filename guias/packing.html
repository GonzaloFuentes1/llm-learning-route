Sequence Packing

Técnica para eliminar el padding en batches de pretraining: combinar múltiples documentos en una sola secuencia de longitud fija. Puede recuperar 30-50% de tokens que de otra forma serían desperdiciados.

1. El problema: padding ineficiente

En pretraining, los documentos tienen longitudes variadas. Para formar batches, el estándar es truncar al máximo y rellenar con tokens de padding los documentos más cortos. Esto desperdicia compute:

ejemplo sin packing
max_seq_len = 2048

Doc A: [tok1, tok2, ..., tok120,  PAD, PAD, ..., PAD]  ← 120 tokens útiles, 1928 padding
Doc B: [tok1, ..., tok2048]                              ← 2048 tokens útiles (raro)
Doc C: [tok1, ..., tok350,  PAD, ..., PAD]              ← 350 tokens útiles, 1698 padding

Eficiencia real: (120 + 2048 + 350) / (3 * 2048) = 40.5%
→ 59.5% del compute se gasta en tokens de padding inútiles

Con packing: combinamos A + C en una sola secuencia de 2048 tokens (120 + 350 + algo más), eliminando casi todo el padding.

2. Greedy bin-packing

El algoritmo más simple: para cada secuencia en construcción, agregar documentos hasta que no quepan más. Separar documentos con el token EOS.

python — packing.py
from typing import Iterator


def greedy_pack(
    token_sequences: list[list[int]],
    max_seq_len: int,
    eos_token_id: int,
    pad_token_id: int,
) -> Iterator[dict]:
    """
    Combina secuencias de tokens en bloques de max_seq_len.
    Cada documento termina con eos_token_id. Los docs más largos que
    max_seq_len se parten en trozos (no se pierden tokens).
    El relleno final usa pad_token_id con labels=-100 y attention_mask=0,
    así el modelo nunca entrena sobre tokens de padding.
    """
    current: list[int] = []
    doc_lengths: list[int] = []

    def emit() -> dict:
        n_pad = max_seq_len - len(current)
        return {
            "input_ids": current + [pad_token_id] * n_pad,
            "labels": current + [-100] * n_pad,          # -100: ignorado por la loss
            "attention_mask": [1] * len(current) + [0] * n_pad,
            "doc_lengths": doc_lengths,                  # para la máscara por documento (sección 3)
        }

    for seq in token_sequences:
        # Agregar EOS al final del documento
        seq_with_eos = seq + [eos_token_id]

        # Partir docs largos en trozos de a lo más max_seq_len
        for i in range(0, len(seq_with_eos), max_seq_len):
            piece = seq_with_eos[i : i + max_seq_len]

            # Si no cabe en el bloque actual, emitir el bloque y empezar uno nuevo
            if len(current) + len(piece) > max_seq_len:
                yield emit()
                current, doc_lengths = [], []
            current.extend(piece)
            doc_lengths.append(len(piece))

    # Emitir el último bloque si tiene contenido
    if current:
        yield emit()


# Uso: toma EOS y PAD del tokenizer (no los hardcodees)
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B-Base")
pad_id = tokenizer.pad_token_id if tokenizer.pad_token_id is not None else tokenizer.eos_token_id

all_token_sequences = [...]  # lista de listas de token IDs

    all_token_sequences,
    max_seq_len=2048,
    eos_token_id=tokenizer.eos_token_id,
    pad_token_id=pad_id,

3. Attention mask por documento

Sin una máscara adecuada, los tokens de un documento ven los tokens del documento anterior en la misma secuencia, lo que introduce cross-document attention leakage. Para evitarlo, necesitas una máscara de bloque diagonal.

Flash Attention 2+ soporta nativamente secuencias con múltiples documentos usando el parámetro cu_seqlens (cumulative sequence lengths), que es la forma más eficiente.

python — attention mask por documento
import torch


def build_document_attention_mask(doc_lengths: list[int], max_seq_len: int) -> torch.Tensor:
    """
    Crea una máscara de atención causal que bloquea el cross-document attention.
    Returns: (max_seq_len, max_seq_len) bool mask. True = permitir atención.
    Vectorizada: sin loops de Python sobre L x L.
    """
    doc_ids = torch.repeat_interleave(
        torch.arange(len(doc_lengths)), torch.tensor(doc_lengths)
    )[:max_seq_len]
    # Posiciones de padding al final: id -1 (solo se ven entre sí)
    n_pad = max_seq_len - doc_ids.numel()
    if n_pad > 0:
        doc_ids = torch.cat([doc_ids, torch.full((n_pad,), -1)])

    same_doc = doc_ids[:, None] == doc_ids[None, :]
    causal = torch.ones(max_seq_len, max_seq_len, dtype=torch.bool).tril()
    return same_doc & causal


# Uso en tu propio modelo (SDPA acepta máscaras bool, True = atender):
#   out = torch.nn.functional.scaled_dot_product_attention(q, k, v, attn_mask=mask[None, None])
# Ojo: los modelos de transformers NO aceptan esta máscara L x L como attention_mask;
# ahí usa position_ids / DataCollatorWithFlattening (sección 4).


# Para FlashAttention-2: usar cu_seqlens directamente
def get_cu_seqlens(doc_lengths: list[int]) -> torch.Tensor:
    """Cumulative sequence lengths para flash_attn_varlen_func."""
    cumsum = [0]
    for length in doc_lengths:
        cumsum.append(cumsum[-1] + length)
    return torch.tensor(cumsum, dtype=torch.int32)
En la práctica: La mayoría de frameworks modernos (OLMo, LLaMA) implementan esto internamente. Si usas Flash Attention con el argumento cu_seqlens, el modelo maneja automáticamente el bloqueo entre documentos sin necesidad de construir la máscara explícitamente.

4. Integración con HuggingFace

Si usas el ecosistema HuggingFace, la forma más simple es pre-procesar tu dataset con packing antes del entrenamiento (concatenar y cortar, estilo GPT). Ojo: esta variante no aísla documentos; los tokens de un documento atienden al anterior dentro del bloque (el EOS solo marca el límite).

python — dataset con packing
from datasets import Dataset
from transformers import AutoTokenizer, default_data_collator


def pack_dataset(
    examples: dict,
    tokenizer,
    max_seq_len: int = 2048,
) -> dict:
    """Función de map para empacar un dataset de HuggingFace."""
    all_tokens = []
    for text in examples["text"]:
        tokens = tokenizer(text, add_special_tokens=False)["input_ids"]
        tokens.append(tokenizer.eos_token_id)
        all_tokens.extend(tokens)

    packed_input_ids = []
    packed_labels = []
    for i in range(0, len(all_tokens) - max_seq_len + 1, max_seq_len):
        chunk = all_tokens[i : i + max_seq_len]
        if len(chunk) == max_seq_len:
            packed_input_ids.append(chunk)
            packed_labels.append(chunk)  # CLM: labels = input_ids

    return {"input_ids": packed_input_ids, "labels": packed_labels}


# Usar en el pipeline de training
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen3-0.6B-Base")
raw_dataset = Dataset.from_json("data/raw/es_sample.jsonl")

packed = raw_dataset.map(
    lambda examples: pack_dataset(examples, tokenizer, max_seq_len=2048),
    batched=True,
    batch_size=1000,
    remove_columns=raw_dataset.column_names,
    num_proc=16,
)

# Todos los bloques miden max_seq_len y ya traen labels: no hace falta padding.
# (DataCollatorForLanguageModeling exigiría pad_token y, si pad == eos,
#  pondría labels=-100 en todos los EOS.)
collator = default_data_collator
print(f"Sequences packed: {len(packed):,}")

Para packing sin contaminación entre documentos y sin padding, usa DataCollatorWithFlattening: concatena el mini-batch en una sola fila, reinicia position_ids en cada documento y pone -100 en el primer label de cada uno. Con attn_implementation="flash_attention_2", transformers deriva los límites de documento (cu_seqlens) de los position_ids y aplica la máscara por documento de la sección 3.

    out = []
    for text in examples["text"]:
        ids = tokenizer(text, add_special_tokens=False)["input_ids"] + [tokenizer.eos_token_id]
        out.extend(ids[i : i + MAX_SEQ_LEN] for i in range(0, len(ids), MAX_SEQ_LEN))
    return {"input_ids": out}

5. Comparativa de eficiencia

python — medir eficiencia
import numpy as np

def measure_packing_efficiency(doc_lengths: list[int], max_seq_len: int) -> dict:
    """Compara la fracción de tokens reales (no padding) con vs sin packing."""
    real_tokens = sum(l + 1 for l in doc_lengths)  # +1 para EOS

    # Sin packing: cada doc (partido en trozos de max_seq_len) se rellena hasta max_seq_len
    n_rows_without = sum(-(-(l + 1) // max_seq_len) for l in doc_lengths)  # ceil
    efficiency_without = real_tokens / (n_rows_without * max_seq_len)

    # Con greedy packing (sección 2): docs largos se parten, el resto del bloque es padding
    n_blocks, used = 0, 0
    for l in doc_lengths:
        remaining = l + 1  # +1 para EOS
        while remaining > 0:
            piece = min(remaining, max_seq_len)
            if used + piece > max_seq_len:
                n_blocks += 1
                used = 0
            used += piece
            remaining -= piece
    if used:
        n_blocks += 1
    efficiency_greedy = real_tokens / (n_blocks * max_seq_len)

    # Concatenar + cortar (sección 4): todos los bloques son tokens reales (100%);
    # solo se descarta el resto final (< max_seq_len tokens).
    efficiency_concat = 1.0

    return {
        "sin_packing": f"{efficiency_without:.1%}",
        "greedy": f"{efficiency_greedy:.1%}",
        "concat": f"{efficiency_concat:.1%}",
        "mejora": f"{efficiency_greedy / efficiency_without:.2f}x",
    }

# Simular documentos web: distribución de cola larga (muchos docs cortos, pocos muy largos)
rng = np.random.default_rng(42)
doc_lengths = np.maximum(rng.lognormal(mean=6.0, sigma=1.2, size=100_000), 1).astype(int).tolist()

resultado = measure_packing_efficiency(doc_lengths, max_seq_len=2048)
print(f"Sin packing:     {resultado['sin_packing']}")
print(f"Greedy packing:  {resultado['greedy']}")
print(f"Concat + cortar: {resultado['concat']}")
print(f"Mejora (greedy): {resultado['mejora']}")
