Entrenamiento de Tokenizadores para es/pt

Entrenar un tokenizador BPE desde cero y extender el vocabulario de LLaMA/Mistral para español y portugués latinoamericano — reduciendo la fertility rate y acelerando el entrenamiento.

1. Por qué el tokenizador de LLaMA es subóptimo para es/pt

El tokenizador de LLaMA 3 (128k tokens) fue entrenado sobre un corpus dominado por inglés. Es bastante más eficiente en español que el de 32k de LLaMA 2, pero muchas palabras frecuentes en español o portugués (sobre todo con tildes, conjugaciones y términos regionales) se siguen partiendo en varios tokens, mientras que sus equivalentes en inglés suelen ser un solo token. Esto tiene consecuencias directas:

MétricaTokenizador centrado en inglésTokenizador es/pt dedicado
Fertility rate (es)más altamenor (menos tokens por palabra)
Contexto efectivo100%mayor con el mismo window, proporcional a la reducción de tokens
Costo de inferencia100%menor, proporcional a la reducción de tokens

Las magnitudes dependen del corpus y del tokenizador base: no copies cifras de otros, mídelas con el script de la sección 6 sobre una muestra fija (anota fecha, corpus y número de documentos).

Fertility rate: promedio de tokens por palabra en un corpus de referencia. Menor fertility = tokenizador más eficiente para ese idioma.

¿Siempre hay que cambiar el tokenizador? No. Para fine-tuning sobre pocas épocas, el costo de extender vocabulario (reentrenar embeddings) puede no compensar. Vale la pena cuando: (1) se hace continual pretraining extenso (miles de millones de tokens) o pretraining desde cero, (2) el vocabulario de inglés tiene menos del 30% de overlap con el corpus objetivo, (3) el presupuesto de inference es una restricción dura.

2. Preparar corpus de entrenamiento

Para entrenar un buen tokenizador necesitamos texto representativo del dominio objetivo: web en español/portugués, documentos técnicos, y algo de código. Un corpus de ~10GB es suficiente para converger.

bash
pip install -U tokenizers datasets transformers
# CulturaX y Llama 3.1 son repos gated: acepta las condiciones en Hugging Face y autentícate
hf auth login   # o exporta HF_TOKEN=...
Acceso: uonlp/CulturaX requiere aceptar sus condiciones de uso en la página del dataset, y meta-llama/Llama-3.1-8B (secciones 4-7) requiere aceptar la licencia de Llama 3.1. Sin eso, load_dataset/from_pretrained fallan con 401/403.
python
from datasets import load_dataset
from itertools import islice

def get_training_corpus(batch_size: int = 1000, max_docs: int = 3_000_000):
    """Iterador perezoso sobre corpus multilingüe es/pt/en.

    max_docs limita el total de documentos: sin límite recorrería CulturaX es/pt
    completo + FineWeb 10BT (cientos de GB). ~3M docs web son del orden de 10GB.
    """

    # CulturaX: web crawl limpio en es y pt
    es_ds = load_dataset("uonlp/CulturaX", "es", split="train", streaming=True)
    pt_ds = load_dataset("uonlp/CulturaX", "pt", split="train", streaming=True)

    # FineWeb: texto web en inglés de calidad (para mantener capacidad en inglés)
    en_ds = load_dataset("HuggingFaceFW/fineweb", "sample-10BT",
                         split="train", streaming=True)

    # Intercalar en ratio 40% es, 30% pt, 30% en
    sources = [
        (es_ds, 0.40),
        (pt_ds, 0.30),
        (en_ds, 0.30),
    ]

    iterators = [(iter(ds), weight) for ds, weight in sources]

    n_docs = 0
    while n_docs < max_docs:
        batch = []
        for it, weight in iterators:
            n = max(1, int(batch_size * weight))
            for ex in islice(it, n):
                batch.append(ex["text"])
        if not batch:
            break
        n_docs += len(batch)
        yield batch

3. Entrenar BPE desde cero

Usamos la librería tokenizers de HuggingFace para entrenar un tokenizador BPE (Byte-Pair Encoding) optimizado para español y portugués.

python
# Continúa el bloque anterior (usa get_training_corpus)
from tokenizers import Tokenizer, decoders
from tokenizers.models import BPE
from tokenizers.trainers import BpeTrainer
from tokenizers.pre_tokenizers import ByteLevel
from tokenizers.normalizers import NFC
from tokenizers.processors import TemplateProcessing

# Configurar el tokenizador base (byte-level: cualquier texto es representable, no hay <unk> real)
tokenizer = Tokenizer(BPE(unk_token="<unk>"))
tokenizer.normalizer = NFC()           # normalizar Unicode (importante para acentos)
tokenizer.pre_tokenizer = ByteLevel(add_prefix_space=False)
tokenizer.decoder = decoders.ByteLevel()  # sin esto, decode() devuelve Ġ/Ċ en vez de espacios/saltos

# Tokens especiales
SPECIAL_TOKENS = [
    "<unk>", "<s>", "</s>", "<pad>",
    # Chat template tokens
    "<|user|>", "<|assistant|>", "<|system|>", "<|end|>",
]

trainer = BpeTrainer(
    vocab_size=65_536,           # 64k tokens (LLaMA 3 usa 128k)
    special_tokens=SPECIAL_TOKENS,
    min_frequency=2,             # ignorar n-gramas con <2 apariciones
    initial_alphabet=ByteLevel.alphabet(),  # los 256 símbolos de byte siempre en el vocabulario
    show_progress=True,
)

# Entrenar — puede tomar 1-3 horas sobre ~10GB de texto
tokenizer.train_from_iterator(get_training_corpus(), trainer=trainer)

# Post-processor: añadir solo BOS. Si añadiera </s> a cada encode, los prompts
# de generación terminarían en EOS; el EOS se agrega al empaquetar los documentos.
tokenizer.post_processor = TemplateProcessing(
    single="<s> $A",
    pair="<s> $A $B:1",
    special_tokens=[("<s>", tokenizer.token_to_id("<s>"))],
)

tokenizer.save("tokenizer-latamgpt-65k.json")
print(f"Vocabulary size: {tokenizer.get_vocab_size()}")

4. Extender el tokenizador de LLaMA 3 (opción recomendada)

En lugar de entrenar desde cero, podemos añadir nuevos tokens BPE al tokenizador de LLaMA 3. Esto preserva compatibilidad con pesos preentrenados y solo requiere inicializar embeddings para los tokens nuevos.

Ojo: tokenizer.add_tokens() no sirve para esto. Los tokens de un BPE byte-level viven en el alfabeto de bytes (p.ej. ĠeducaciÃ³n para " educación"), y add_tokens los registra como added tokens que se buscan literalmente en el texto crudo: nunca calzan, o calzan en medio de palabras. Lo correcto es extender el modelo BPE: agregar entradas a model.vocab y sus reglas a model.merges en tokenizer.json, manteniendo intactos los ids originales.

python
import json
from datasets import load_dataset, interleave_datasets
from transformers import AutoTokenizer

BASE_TOKENIZER = "meta-llama/Llama-3.1-8B"   # gated: requiere aceptar la licencia
MAX_NEW_TOKENS = 8_000

llama_tok = AutoTokenizer.from_pretrained(BASE_TOKENIZER)
n_orig = len(llama_tok)   # 128,256 = 128,000 BPE + 256 especiales/reservados

# 1. Corpus SOLO es/pt (acotado)
es_pt = interleave_datasets([
    load_dataset("uonlp/CulturaX", lang, split="train", streaming=True)
    for lang in ("es", "pt")
])

def es_pt_corpus(max_docs: int = 1_000_000, batch_size: int = 1000):
    batch = []
    for i, ex in enumerate(es_pt):
        if i >= max_docs:
            break
        batch.append(ex["text"])
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:
        yield batch

# 2. BPE auxiliar con el MISMO pipeline que Llama 3 (normalizer, pre-tokenizer
#    regex + byte-level): así sus merges son compatibles con el vocabulario base.
aux_tok = llama_tok.train_new_from_iterator(es_pt_corpus(), vocab_size=16_000)

# 3. Fusionar: recorrer los merges auxiliares en orden y agregar los que producen
#    un token nuevo cuyas dos partes ya existen (originales o recién agregadas).
base = json.loads(llama_tok.backend_tokenizer.to_str())
aux  = json.loads(aux_tok.backend_tokenizer.to_str())

def as_pair(m):
    # tokenizers >= 0.20 serializa merges como ["a", "b"]; versiones viejas como "a b"
    return tuple(m) if isinstance(m, list) else tuple(m.split(" ", 1))

vocab  = base["model"]["vocab"]
merges = [as_pair(m) for m in base["model"]["merges"]]
next_id = n_orig            # ids nuevos después de los especiales: los originales no cambian
new_tokens = []
for a, b in (as_pair(m) for m in aux["model"]["merges"]):
    tok = a + b
    if tok in vocab or a not in vocab or b not in vocab:
        continue
    vocab[tok] = next_id
    next_id += 1
    merges.append((a, b))   # al final: menor prioridad que los merges originales
    new_tokens.append(tok)
    if len(new_tokens) >= MAX_NEW_TOKENS:
        break
base["model"]["merges"] = [list(m) for m in merges]
print(f"Tokens nuevos añadidos: {len(new_tokens)}")

# 4. Guardar: config del tokenizador original + tokenizer.json extendido
OUT = "llama3-extended-tokenizer"
llama_tok.save_pretrained(OUT)
with open(f"{OUT}/tokenizer.json", "w", encoding="utf-8") as f:
    json.dump(base, f, ensure_ascii=False)
with open(f"{OUT}/new_tokens.json", "w", encoding="utf-8") as f:
    json.dump(new_tokens, f, ensure_ascii=False)

# 5. Validar antes de seguir
ext_tok = AutoTokenizer.from_pretrained(OUT)
texto = "La educación pública también es un derecho en América Latina."
print(llama_tok.tokenize(texto))
print(ext_tok.tokenize(texto))
assert ext_tok.decode(ext_tok.encode(texto, add_special_tokens=False)) == texto
print(f"Vocabulario original: {n_orig:,} · extendido: {len(ext_tok):,}")
Validación: antes de tocar el modelo, corre la sección 6 con el tokenizador extendido. Si la fertility en es/pt no baja, el problema está en la fusión, no en el entrenamiento.

5. Inicializar embeddings para nuevos tokens

Los nuevos tokens necesitan embeddings iniciales. La mejor estrategia es inicializarlos como el promedio de los embeddings de los subwords con los que se tokenizaba la misma palabra antes de la extensión.

python
import json
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

BASE_MODEL = "meta-llama/Llama-3.1-8B"
EXT_DIR = "llama3-extended-tokenizer"

orig_tok = AutoTokenizer.from_pretrained(BASE_MODEL)
ext_tok  = AutoTokenizer.from_pretrained(EXT_DIR)
with open(f"{EXT_DIR}/new_tokens.json", encoding="utf-8") as f:
    new_tokens = json.load(f)   # guardado en la sección 4

model = AutoModelForCausalLM.from_pretrained(BASE_MODEL, dtype=torch.bfloat16)

# Expandir embeddings de entrada y salida (lm_head) en una sola llamada
n_orig = len(orig_tok)   # 128,256
n_new  = len(ext_tok)    # 128,256 + nuevos tokens
model.resize_token_embeddings(n_new)

in_w  = model.get_input_embeddings().weight    # [vocab_size, hidden]
out_w = model.get_output_embeddings().weight   # lm_head
tied  = out_w is in_w                          # Llama 3.1 8B: no están atados

def subword_ids(new_token: str) -> list[int]:
    """Ids del tokenizador ORIGINAL para el texto que representa el token nuevo."""
    text = ext_tok.convert_tokens_to_string([new_token])   # "ĠeducaciÃ³n" -> " educación"
    return orig_tok.encode(text, add_special_tokens=False)

# Inicializar cada token nuevo como el promedio de sus subwords originales
with torch.no_grad():
    for new_token in new_tokens:
        new_id = ext_tok.convert_tokens_to_ids(new_token)
        if new_id < n_orig:
            continue
        ids = subword_ids(new_token)
        if not ids:
            continue   # queda la inicialización por defecto de resize_token_embeddings
        in_w[new_id] = in_w[ids].mean(dim=0)
        if not tied:
            out_w[new_id] = out_w[ids].mean(dim=0)

model.save_pretrained("llama3-extended-init")
ext_tok.save_pretrained("llama3-extended-init")
Importante: Los nuevos embeddings necesitan entrenarse. El modelo con vocabulario extendido debe pasar por continual pretraining antes de usarse para inferencia. Los embeddings inicializados por promedio son un buen punto de partida, pero el modelo necesita aprender a usarlos en contexto.

6. Evaluar la calidad del tokenizador

python
from transformers import AutoTokenizer
from datasets import load_dataset

def compute_fertility_rate(tokenizer, texts: list[str]) -> float:
    """Tokens generados / palabras totales. Menor = más eficiente."""
    total_tokens = 0
    total_words  = 0
    for text in texts:
        tokens = tokenizer.encode(text, add_special_tokens=False)
        words  = text.split()
        total_tokens += len(tokens)
        total_words  += len(words)
    return total_tokens / total_words if total_words > 0 else 0

# Preparar textos de evaluación (muestra fija: mismos 1000 docs por idioma)
eval_texts = {
    "es": load_dataset("uonlp/CulturaX", "es", split="train",
                       streaming=True).take(1000),
    "pt": load_dataset("uonlp/CulturaX", "pt", split="train",
                       streaming=True).take(1000),
    "en": load_dataset("HuggingFaceFW/fineweb", "sample-10BT",
                       split="train", streaming=True).take(1000),
}
eval_corpus = {lang: [ex["text"] for ex in ds] for lang, ds in eval_texts.items()}

# Comparar tokenizadores
tokenizers_to_compare = {
    "LLaMA 3 original":   AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B"),
    "LLaMA 3 extendido":  AutoTokenizer.from_pretrained("llama3-extended-init"),
    "BPE nativo 65k":     AutoTokenizer.from_pretrained("latamgpt-tokenizer-v1"),
}

print(f"{'Tokenizador':<25} {'es':<8} {'pt':<8} {'en':<8}")
print("-" * 50)
for name, tok in tokenizers_to_compare.items():
    rates = {lang: compute_fertility_rate(tok, texts)
             for lang, texts in eval_corpus.items()}
    print(f"{name:<25} {rates['es']:<8.3f} {rates['pt']:<8.3f} {rates['en']:<8.3f}")

7. Continual pretraining con vocabulario extendido

Con el modelo inicializado y el tokenizador extendido, el continual pretraining sigue el mismo flujo que la guía de Continual Pretraining con una diferencia: hay que congelar los embeddings de los tokens originales durante las primeras épocas para no degradar el inglés.

python
import torch
from transformers import AutoModelForCausalLM

model = AutoModelForCausalLM.from_pretrained("llama3-extended-init",
                                              dtype=torch.bfloat16)
n_orig = 128_256  # vocabulario original de LLaMA 3

def freeze_original_embeddings(model, n_orig_tokens: int):
    """Congela los embeddings de los tokens originales, deja libres los nuevos."""
    embed = model.get_input_embeddings()

    def make_hook(n_orig):
        def hook(grad):
            grad[:n_orig] = 0  # no actualizar tokens originales
            return grad
        return hook

    return embed.weight.register_hook(make_hook(n_orig_tokens))

# Activar durante las primeras ~1000 steps para estabilizar los nuevos embeddings
handle = freeze_original_embeddings(model, n_orig)

# Después de ~1000 steps, descongelar para permitir ajuste fino del vocabulario completo:
# handle.remove()
# Nota: el lm_head (no atado en Llama 3.1 8B) sigue actualizándose; congélalo igual si lo necesitas.
# Usa un optimizador sin weight decay sobre los embeddings, o el decay moverá igual las filas congeladas.
