Agentes con herramientas: SFT de tool calling y RL multi-turn

Cómo enseñarle a un modelo a usar herramientas en varios turnos: el formato de tool calling, un entorno de búsqueda 100% en español que se puntúa solo, un cold start con SFT sobre trayectorias verificadas y GRPO multi-turn con environment_factory de TRL 1.x. Cierra con recompensas a prueba de hacking, métricas de diagnóstico, escalado asíncrono y evaluación held-out.

1. Del chat al agente: el pipeline

Eval held-out + BFCL/τ²

Un agente es un modelo que, en lugar de responder de una, emite tool calls, recibe los resultados como mensajes de rol tool y decide si sigue llamando herramientas o responde. Las recetas abiertas actuales lo enseñan en dos fases: SFT sobre trayectorias sintéticas verificadas (APIGen-MT, xLAM) para fijar el formato, y RL multi-turn en entornos con herramientas reales para que aprenda cuándo y cómo usarlas (Search-R1, ReTool, SkyRL-Agent). En RL, la recompensa se calcula sobre la trayectoria completa, y los tokens que devuelven las herramientas se enmascaran en la loss: el modelo solo recibe gradiente por lo que él generó.

El caso práctico de esta guía es un agente de búsqueda en español: una herramienta buscar(consulta) sobre un índice BM25 de Wikipedia-es, preguntas de XQuAD-es y una recompensa F1 contra la respuesta de referencia. Es chico a propósito: todo corre en una GPU y el mismo esqueleto (entorno con estado + recompensas verificables) se aplica a SQL, APIs internas, normativa o ejecución de código.

Los tiempos son estimaciones de orden de magnitud: dependen de cuántos turnos usa cada trayectoria y de la latencia de las herramientas.

¿Hace falta el SFT? Si partes de un modelo instruct que ya hace tool calling (Qwen3, Llama 3.1+, gpt-oss), puedes ir directo a RL y usar el SFT solo para fijar el comportamiento en español. Si partes de tu propio modelo (por ejemplo, un base de LatamGPT después de continual pretraining) el cold start es obligatorio: con un modelo que nunca emitió un <tool_call> bien formado, todas las recompensas del grupo valen lo mismo y GRPO no tiene señal.

2. El formato de tool calling

En el ecosistema Hugging Face una herramienta se describe con un JSON schema estilo OpenAI ({"type": "function", "function": {...}}) que transformers.utils.get_json_schema genera a partir de los type hints y de un docstring estilo Google. La conversación usa tool_calls en el mensaje del assistant y el rol tool para el resultado. Lo que cambia por familia es cómo la plantilla de chat serializa eso en texto, y el servidor debe usar el parser que calza con esa plantilla.

python
# formato_tools.py — cómo ve el modelo una conversación con herramientas
from transformers import AutoTokenizer
from transformers.utils import get_json_schema


def buscar(consulta: str) -> str:
    """
    Busca pasajes relevantes en un índice de Wikipedia en español.

    Args:
        consulta: Palabras clave en español (entre 2 y 15 palabras).

    Returns:
        Los tres pasajes más relevantes, numerados.
    """
    return "..."


schema = get_json_schema(buscar)   # {"type": "function", "function": {"name": "buscar", ...}}
tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-1.7B")

messages = [
    {"role": "system", "content": "Eres un asistente que responde en español. Usa buscar antes de responder."},
    {"role": "user", "content": "¿En qué año se fundó la Universidad de Chile?"},
    {"role": "assistant", "content": "", "tool_calls": [
        {"type": "function", "function": {"name": "buscar",
                                          "arguments": {"consulta": "fundación Universidad de Chile año"}}}]},
    {"role": "tool", "name": "buscar", "content": "[1] Universidad de Chile: fundada en 1842 ..."},
    {"role": "assistant", "content": "En 1842."},
]

texto = tok.apply_chat_template(messages, tools=[schema], tokenize=False)
print(texto)   # Qwen3: <tool_call>{"name": ..., "arguments": ...}</tool_call> y <tool_response> en un turno user

# Test prefix-preserving: renderizar los primeros k mensajes debe dar un prefijo del render completo.
for k in range(2, len(messages)):
    parcial = tok.apply_chat_template(messages[:k], tools=[schema], tokenize=False)
    print(f"k={k} ({messages[k - 1]['role']}): prefijo={texto.startswith(parcial)}")

Plantillas prefix-preserving: el loop multi-turn de GRPO concatena ids de tokens turno a turno sin re-tokenizar. Si agregar un mensaje tool cambia cómo se renderizan los mensajes anteriores (Qwen3, por ejemplo, trata distinto el bloque <think> del último turno assistant), los logprobs del trainer no corresponden a lo que se generó. Para familias conocidas (Qwen3, DeepSeek-V3) TRL cambia automáticamente a una plantilla de entrenamiento parcheada cuando hay tools; para tu propio modelo, el test del bloque anterior debe dar prefijo=True en todos los k.

3. Un entorno de búsqueda en español

Primero, las dependencias. AsyncGRPOTrainer (sección 8) requiere vLLM ≥ 0.22 y transformers ≥ 5.2, y los dos paquetes tienen restricciones de versión que chocan: la documentación de TRL recomienda instalar vLLM primero y después forzar transformers.

El corpus combina los 240 párrafos de XQuAD-es (para que cada pregunta tenga respuesta en el índice) con pasajes reales de Wikipedia-es como distractores. BM25 con stemming en español corre en CPU y carga en segundos, ideal para miles de rollouts. En producción reemplázalo por Wikipedia-es completa o por fuentes locales (normativa, sitios de gobierno, documentación interna) y, si quieres retrieval denso, por el stack de la guía de RAG.

python
# build_index.py — corpus de búsqueda en español: contextos de XQuAD-es + distractores de Wikipedia-es
# pip install "bm25s[core]" PyStemmer datasets
import json

import bm25s
import Stemmer
from datasets import load_dataset

N_PASAJES = 200_000      # ~1-2 GB de RAM; Wikipedia-es completa son millones de pasajes (decenas de GB)
PALABRAS_POR_PASAJE = 200
DIR_INDICE = "indice_bm25_es"


def trocear(texto: str, titulo: str, n: int = PALABRAS_POR_PASAJE):
    palabras = texto.split()
    for i in range(0, len(palabras), n):
        yield f"{titulo}: " + " ".join(palabras[i:i + n])


# 1) Los párrafos de XQuAD-es garantizan que cada pregunta tenga su respuesta en el corpus
xquad = load_dataset("google/xquad", "xquad.es", split="validation")
corpus = sorted(set(xquad["context"]))

# 2) Distractores reales: artículos de Wikipedia-es en streaming (no descarga los ~1.8M artículos)
wiki = load_dataset("wikimedia/wikipedia", "20231101.es", split="train", streaming=True)
for articulo in wiki.shuffle(seed=0, buffer_size=10_000):
    corpus.extend(trocear(articulo["text"], articulo["title"]))
    if len(corpus) >= N_PASAJES:
        break

stemmer = Stemmer.Stemmer("spanish")
tokens = bm25s.tokenize(corpus, stopwords="es", stemmer=stemmer)
retriever = bm25s.BM25()
retriever.index(tokens)
retriever.save(DIR_INDICE)

# Guardamos los textos aparte: el entorno recupera ids y los resuelve contra esta lista
with open(f"{DIR_INDICE}/pasajes.jsonl", "w", encoding="utf-8") as f:
    for p in corpus:
        f.write(json.dumps({"text": p}, ensure_ascii=False) + "\n")
print(f"{len(corpus):,} pasajes indexados en {DIR_INDICE}/")

El entorno es una clase normal de Python con el contrato de environment_factory: reset(**kwargs) recibe las columnas de la fila del dataset y puede devolver None o un texto que se agrega al último mensaje del usuario; get_reward() (opcional) puntúa al entorno desde su propio estado, y todo método público restante se expone como herramienta, con el esquema derivado de sus type hints y su docstring. Si una herramienta lanza una excepción, TRL le devuelve el mensaje de error al modelo como respuesta de la tool y la cuenta en tools/failure_frequency: así se señalan acciones inválidas.

python
# env_busqueda.py — entorno con estado para TRL (environment_factory) y para evaluación
import json
import re
import unicodedata
from functools import lru_cache

import bm25s
import Stemmer

DIR_INDICE = "indice_bm25_es"
MAX_BUSQUEDAS = 4


@lru_cache(maxsize=1)
def _recursos():
    """Carga el índice una sola vez por proceso (TRL crea una instancia del entorno por rollout)."""
    retriever = bm25s.BM25.load(DIR_INDICE)
    with open(f"{DIR_INDICE}/pasajes.jsonl", encoding="utf-8") as f:
        pasajes = [json.loads(linea)["text"] for linea in f]
    return retriever, pasajes, Stemmer.Stemmer("spanish")


def normalizar(texto: str) -> str:
    texto = unicodedata.normalize("NFKD", texto.lower())
    texto = "".join(c for c in texto if not unicodedata.combining(c))   # quita tildes
    texto = re.sub(r"[^\w\s]", " ", texto)
    texto = re.sub(r"\b(el|la|los|las|un|una|unos|unas|de|del|o|a)\b", " ", texto)
    return " ".join(texto.split())


def f1(pred: str, gold: str) -> float:
    p, g = normalizar(pred).split(), normalizar(gold).split()
    comunes = sum(min(p.count(w), g.count(w)) for w in set(p))
    if comunes == 0:
        return 0.0
    precision, recall = comunes / len(p), comunes / len(g)
    return 2 * precision * recall / (precision + recall)


class BusquedaEnv:
    """reset() y get_reward() son métodos reservados; los demás métodos públicos son herramientas."""

    def reset(self, answer: str, **kwargs) -> None:
        # Las columnas del dataset (aquí "answer") llegan como kwargs
        self.gold = answer
        self.consultas: list[str] = []
        self.vistos: list[str] = []
        self.invalidas = 0
        return None   # None: el prompt del dataset se usa tal cual

    def buscar(self, consulta: str) -> str:
        """
        Busca pasajes relevantes en un índice de Wikipedia en español.

        Args:
            consulta: Palabras clave en español (entre 2 y 15 palabras).

        Returns:
            Los tres pasajes más relevantes, numerados.
        """
        if len(self.consultas) >= MAX_BUSQUEDAS:
            self.invalidas += 1
            raise ValueError("Límite de búsquedas alcanzado. Responde con lo que encontraste.")
        if not 2 <= len(consulta.split()) <= 15:
            self.invalidas += 1
            raise ValueError("La consulta debe tener entre 2 y 15 palabras.")
        if normalizar(consulta) in {normalizar(c) for c in self.consultas}:
            self.invalidas += 1
            raise ValueError("Consulta repetida: reformúlala con otras palabras.")
        self.consultas.append(consulta)

        retriever, pasajes, stemmer = _recursos()
        q = bm25s.tokenize([consulta], stopwords="es", stemmer=stemmer, show_progress=False)
        ids, _ = retriever.retrieve(q, k=3, show_progress=False)
        top = [pasajes[int(i)] for i in ids[0]]
        self.vistos.extend(top)
        return "\n\n".join(f"[{j + 1}] {p[:1200]}" for j, p in enumerate(top))

    def get_reward(self) -> float:
        # Recompensa propia del entorno: penaliza llamadas inválidas (TRL la suma con peso 1)
        return -0.1 * min(self.invalidas, 3)

Antes de entrenar, prueba el entorno a mano con un modelo servido. Este bucle es el mismo que vas a reutilizar para generar trayectorias de SFT y para evaluar:

python
# agente_loop.py — bucle agente ↔ herramienta contra un servidor OpenAI-compatible (vLLM)
# Sirve para: (a) probar el entorno antes de entrenar, (b) generar trayectorias SFT, (c) evaluar.
import json

from openai import OpenAI
from transformers.utils import get_json_schema

from env_busqueda import BusquedaEnv

SYSTEM = (
    "Eres un asistente de investigación que responde en español. "
    "Antes de responder usa la herramienta buscar (puedes llamarla varias veces). "
    "Responde con una frase breve que contenga solo la respuesta."
)
TOOLS = [get_json_schema(BusquedaEnv().buscar)]   # mismo esquema que TRL deriva del método


def correr_agente(client: OpenAI, modelo: str, pregunta: str, gold: str,
                  max_turnos: int = 5, temperature: float = 0.0):
    env = BusquedaEnv()
    env.reset(answer=gold)
    msgs = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": pregunta}]
    for _ in range(max_turnos):
        r = client.chat.completions.create(
            model=modelo, messages=msgs, tools=TOOLS, temperature=temperature, max_tokens=1024,
            extra_body={"chat_template_kwargs": {"enable_thinking": False}},
        )
        m = r.choices[0].message
        if not m.tool_calls:
            msgs.append({"role": "assistant", "content": m.content or ""})
            return m.content or "", msgs, env
        msgs.append({"role": "assistant", "content": m.content or "",
                     "tool_calls": [tc.model_dump() for tc in m.tool_calls]})
        for tc in m.tool_calls:
            try:
                args = json.loads(tc.function.arguments)
                if tc.function.name != "buscar":
                    raise ValueError(f"Herramienta desconocida: {tc.function.name}")
                salida = env.buscar(**args)
            except Exception as e:   # igual que TRL: el error vuelve al modelo como respuesta de la tool
                salida = f"Error: {e}"
            msgs.append({"role": "tool", "tool_call_id": tc.id, "name": tc.function.name, "content": salida})
    return "", msgs, env   # se quedó sin turnos


if __name__ == "__main__":
    client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
    resp, msgs, env = correr_agente(client, "Qwen/Qwen3-1.7B",
                                    "¿Cuántos puntos cedió la defensa de los Panthers?", "308")
    print(resp, "| búsquedas:", env.consultas, "| inválidas:", env.invalidas)

4. Cold start: SFT de tool calling

Casi no hay datos abiertos de function calling en español, así que la receta combina dos fuentes: APIGen-MT-5k (5000 trayectorias multi-turn en inglés con políticas de dominio estilo τ-bench, verificadas por ejecución) para el formato y la disciplina multi-turno, y trayectorias propias en español generadas por un modelo profesor sobre nuestro entorno y filtradas por rejection sampling. Primero, el split de XQuAD-es por párrafo, que todos los scripts siguientes reutilizan:

python
# datos_xquad.py — split por párrafo para que train y eval no compartan contexto
from datasets import load_dataset

from agente_loop import SYSTEM


def primera_respuesta(answers) -> str:
    # XQuAD guarda answers como {"text": [...], "answer_start": [...]}
    return answers["text"][0] if isinstance(answers, dict) else answers[0]["text"]


def cargar_splits(n_ctx_eval: int = 40):
    xquad = load_dataset("google/xquad", "xquad.es", split="validation")   # 1190 preguntas, 240 párrafos
    ctx_eval = set(sorted(set(xquad["context"]))[-n_ctx_eval:])

    def a_prompt(ej):
        return {
            "prompt": [{"role": "system", "content": SYSTEM}, {"role": "user", "content": ej["question"]}],
            "question": ej["question"],
            "answer": primera_respuesta(ej["answers"]),
        }

    train = xquad.filter(lambda e: e["context"] not in ctx_eval)
    test = xquad.filter(lambda e: e["context"] in ctx_eval)
    cols = xquad.column_names
    return train.map(a_prompt, remove_columns=cols), test.map(a_prompt, remove_columns=cols)
python
# generar_trayectorias_es.py — rejection sampling con un modelo profesor servido con vLLM
# Terminal aparte:  vllm serve Qwen/Qwen3-32B-FP8 --enable-auto-tool-choice --tool-call-parser hermes
import json

from openai import OpenAI

from agente_loop import TOOLS, correr_agente
from datos_xquad import cargar_splits
from env_busqueda import f1

PROFESOR = "Qwen/Qwen3-32B-FP8"
MUESTRAS_POR_PREGUNTA = 4
client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")


def a_formato_hf(msgs: list[dict]) -> list[dict]:
    """La API usa arguments como string JSON; para SFT los guardamos como dict."""
    out = []
    for m in msgs:
        m = dict(m)
        if m.get("tool_calls"):
            m["tool_calls"] = [{"type": "function", "function": {
                "name": tc["function"]["name"],
                "arguments": json.loads(tc["function"]["arguments"])}} for tc in m["tool_calls"]]
        m.pop("tool_call_id", None)
        out.append(m)
    return out


train, _ = cargar_splits()
aceptadas = 0
with open("trayectorias_es.jsonl", "w", encoding="utf-8") as f:
    for ej in train:
        for _ in range(MUESTRAS_POR_PREGUNTA):
            resp, msgs, env = correr_agente(client, PROFESOR, ej["question"], ej["answer"], temperature=0.7)
            # Filtro: respuesta correcta, sin llamadas inválidas y respaldada por un pasaje leído
            if f1(resp, ej["answer"]) >= 0.8 and env.invalidas == 0 and env.vistos:
                f.write(json.dumps({"messages": a_formato_hf(msgs), "tools": TOOLS}, ensure_ascii=False) + "\n")
                aceptadas += 1
                break   # una trayectoria por pregunta basta para el cold start
print(f"{aceptadas} trayectorias aceptadas de {len(train)} preguntas")

Con las dos fuentes, el SFT es directo: SFTTrainer acepta datasets conversacionales con tool_calls, mensajes tool y una columna tools que la plantilla usa para armar el system prompt. Los argumentos de las tools tienen esquemas arbitrarios, así que el dataset usa el tipo Json() de datasets (vía on_mixed_types="use_json").

python
# sft_tools.py — SFT de tool calling: APIGen-MT-5k (inglés, multi-turn) + trayectorias en español
import json

import torch
from datasets import Dataset, load_dataset
from trl import SFTConfig, SFTTrainer

ROL = {"human": "user", "gpt": "assistant"}


def convertir_apigen(ej) -> dict:
    """ShareGPT (human/gpt/function_call/observation) → messages con tool_calls y rol tool."""
    msgs = [{"role": "system", "content": ej["system"]}]
    ultima_tool = None
    for turno in ej["conversations"]:
        origen, valor = turno["from"], turno["value"]
        if origen == "function_call":
            call = json.loads(valor)   # {"name": ..., "arguments": {...}}
            ultima_tool = call["name"]
            msgs.append({"role": "assistant", "content": "", "tool_calls": [
                {"type": "function", "function": {"name": call["name"], "arguments": call["arguments"]}}]})
        elif origen == "observation":
            msgs.append({"role": "tool", "name": ultima_tool, "content": valor})
        else:
            msgs.append({"role": ROL[origen], "content": valor})
    while msgs[-1]["role"] == "tool":   # algunas terminan en una observación: la recortamos
        msgs.pop()
    tools = [{"type": "function", "function": t} for t in json.loads(ej["tools"])]
    return {"messages": msgs, "tools": tools}


apigen = load_dataset("Salesforce/APIGen-MT-5k", split="train")
data = [convertir_apigen(ej) for ej in apigen]

with open("trayectorias_es.jsonl", encoding="utf-8") as f:
    data_es = [json.loads(linea) for linea in f]
data += data_es * 2   # sobre-muestrear el español: es el comportamiento que queremos fijar

# Json() para tool_calls/tools: argumentos con esquemas arbitrarios (datasets >= 4.7)
ds = Dataset.from_list(data, on_mixed_types="use_json").shuffle(seed=0)

trainer = SFTTrainer(
    model="Qwen/Qwen3-1.7B",              # o tu modelo propio: "<TU_ORG>/<modelo>"
    train_dataset=ds,
    args=SFTConfig(
        output_dir="qwen3-1.7b-tools-sft",
        model_init_kwargs={"dtype": torch.bfloat16},   # explícito (en transformers v5 el default ya es el dtype del checkpoint)
        assistant_only_loss=True,         # loss solo en turnos assistant (tool calls incluidas)
        max_length=8192,                  # las políticas de APIGen-MT son largas
        per_device_train_batch_size=1,
        gradient_accumulation_steps=16,
        learning_rate=1e-5,
        lr_scheduler_type="cosine",
        warmup_steps=30,
        num_train_epochs=2,
        logging_steps=10,
        report_to="none",
    ),
)
trainer.train()
trainer.save_model()

No quemes las preguntas de RL en el SFT: XQuAD-es tiene solo ~1000 preguntas de entrenamiento. Si el profesor resuelve todas y el SFT las memoriza, en GRPO todos los rollouts del grupo aciertan, la varianza es cero y no hay gradiente. Reparte (por ejemplo, 40% de los párrafos para trayectorias SFT y 60% para RL) o, mejor, genera preguntas sintéticas sobre Wikipedia-es con la guía de pipeline sintético y deja XQuAD solo para evaluar. assistant_only_loss con tools: la loss cae en los turnos assistant, incluidas las tool calls, y no en las respuestas de las herramientas ni en las políticas del system prompt. Requiere bloques {% generation %} en la plantilla; TRL los parchea automáticamente para Qwen3 y otras familias conocidas. Si tu modelo usa una plantilla propia, agrégalos tú (la plantilla de SmolLM3 es un buen ejemplo) y verifica la máscara decodificando un ejemplo antes de entrenar.

5. GRPO multi-turn con environment_factory

En TRL 1.x el loop agéntico viene incluido: le pasas la clase del entorno y el trainer crea una instancia por rollout, llama a reset() con la fila del dataset, genera, parsea las tool calls, ejecuta los métodos, agrega los resultados y vuelve a generar hasta que el modelo responde sin herramientas, llega a max_tool_calling_iterations o agota max_completion_length, que cuenta toda la trayectoria (generaciones más resultados de las tools). Los tokens de las respuestas de las herramientas se enmascaran en la loss. Las recompensas reciben las columnas del dataset por nombre y, si las piden, la lista environments con el estado final de cada rollout.

python
# recompensas.py — funciones a nivel de módulo (picklables: sirven también para AsyncGRPOTrainer)
import re

from env_busqueda import f1, normalizar

ES = {"el", "la", "de", "que", "y", "en", "los", "se", "del", "las", "por", "un", "una", "es", "con", "para"}
EN = {"the", "of", "and", "is", "in", "to", "was", "for", "with", "by", "that", "it", "on"}


def respuesta_final(completion: list[dict]) -> str:
    """En modo conversacional la completion es la lista de mensajes generados (assistant/tool)."""
    ultimo = completion[-1]
    if ultimo.get("role") != "assistant" or ultimo.get("tool_calls"):
        return ""   # truncada o terminó pidiendo otra herramienta
    return ultimo.get("content") or ""


def f1_reward(completions, answer, **kwargs) -> list[float]:
    return [f1(respuesta_final(c), a) for c, a in zip(completions, answer)]


def evidencia_reward(completions, answer, environments=None, **kwargs) -> list[float]:
    """+0.2 solo si acierta Y la respuesta aparece en algún pasaje que el agente leyó."""
    envs = environments or [None] * len(completions)
    out = []
    for c, a, env in zip(completions, answer, envs):
        acierta = f1(respuesta_final(c), a) >= 0.5
        respaldada = env is not None and any(normalizar(a) in normalizar(p) for p in env.vistos)
        out.append(0.2 if acierta and respaldada else 0.0)
    return out


def formato_reward(completions, **kwargs) -> list[float]:
    out = []
    for c in completions:
        r = respuesta_final(c)
        if not r:
            out.append(-0.5)
        elif len(r.split()) > 30:   # respuestas largas inflan el recall del F1: hack clásico
            out.append(-0.3)
        else:
            out.append(0.0)
    return out


def idioma_reward(completions, **kwargs) -> list[float]:
    """Penaliza responder en inglés (Qwen3 tiende a cambiar de idioma). Para pt, cambia ES por stopwords pt."""
    out = []
    for c in completions:
        toks = re.findall(r"\w+", respuesta_final(c).lower())
        en, es = sum(t in EN for t in toks), sum(t in ES for t in toks)
        out.append(-0.3 if en > es else 0.0)
    return out


RECOMPENSAS = [f1_reward, evidencia_reward, formato_reward, idioma_reward]

6. Recompensas y reward hacking

Las recompensas verificables también se hackean. Con agentes el riesgo es mayor porque el modelo controla acciones y no solo texto. Diseña cada término pensando en qué atajo abre, y revisa a mano los rollouts con recompensa alta (log_completions=True) al menos cada 50 pasos.

El hacking generaliza: Anthropic mostró que un modelo que aprende reward hacks en entornos de código de producción desarrolla misalignment más amplio (alignment faking, sabotaje). Para herramientas con efectos (código, SQL, APIs que escriben), separa el verificador de entrenamiento del de evaluación, usa tests ocultos y nunca le des al entorno de RL credenciales reales.

8. Escalar: rollouts asíncronos, OpenEnv y frameworks

En modo colocate la GPU alterna entre generar y entrenar, y en multi-turn el tiempo ocioso crece porque cada turno espera a las herramientas. AsyncGRPOTrainer (en trl.experimental) desacopla las dos fases: un worker genera contra un servidor vLLM en otra GPU mientras el trainer consume la cola, y los pesos se sincronizan por NCCL. Restricciones: solo FSDP2 para multi-GPU, y recompensas, tools y environment_factory deben ser picklables (definidos a nivel de módulo, como en recompensas.py), porque el worker corre en otro proceso sin GPU.

API experimental: AsyncGRPOConfig no expone todos los parámetros de GRPOConfig y carga el modelo en float32 por defecto para reducir el mismatch numérico entre trainer y generador (si lo cambias con dtype, conviene que vLLM sirva con una precisión coherente). Antes de una corrida larga, valida con max_steps=5 que las recompensas por función no salgan todas en cero. Además, las tools síncronas corren en un thread pool de tamaño max_inflight_tasks, así que el estado compartido (como la caché del índice) debe ser thread-safe.

Entornos como servicio (OpenEnv): cuando el entorno es pesado (un índice de decenas de GB, un navegador, un contenedor de código), no conviene cargarlo dentro de cada instancia. OpenEnv lo empaqueta como servidor HTTP/WebSocket (un Space del Hub o una imagen Docker) y tu clase de environment_factory pasa a ser un cliente delgado. Para entrenar, duplica el Space en tu cuenta y configura max_concurrent_envs ≥ generation_batch_size: por defecto un servidor OpenEnv acepta una sola sesión. Es el patrón "un sandbox por rollout" que hoy usan las recetas agénticas.
