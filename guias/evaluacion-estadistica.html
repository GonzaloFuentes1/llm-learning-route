Evaluación estadísticamente rigurosa: error bars, tests pareados y poder estadístico

Casi todas las decisiones de un proyecto de LLM (qué checkpoint, qué mezcla de datos, qué receta de SFT o DPO) se toman con diferencias de 1-3 puntos que muchas veces están dentro del ruido. Esta guía enseña a cuantificar ese ruido con los logs por muestra que ya producen lm-eval e Inspect: intervalos de confianza, errores estándar clustered, comparaciones pareadas, poder estadístico y corrección por comparaciones múltiples, con ejemplos sobre benchmarks en español y portugués (Belebele, LatamQA, Trueque).

1. La evaluación como experimento

La idea central de Adding Error Bars to Evals (Miller, 2024) es tratar cada benchmark como una muestra de una super-población de preguntas posibles. La accuracy que reportas es un estimador, y como todo estimador tiene un error estándar. Para una métrica binaria (acierto/fallo) con n preguntas independientes:

SE = sqrt(p(1 - p) / n)  ·  IC95% ≈ p ± 1.96 · SE

Lo que eso implica para los tamaños típicos de benchmark:

n preguntasEjemploIC95% con p = 0.5IC95% con p = 0.8
30AIME 2025 / 2026± 17.9 pp± 14.3 pp
100benchmark interno chico± 9.8 pp± 7.8 pp
500Trueque beta 0.1± 4.4 pp± 3.5 pp
900Belebele (por idioma)± 3.3 pp± 2.6 pp
10,000MMLU completo (~14K)± 1.0 pp± 0.8 pp

Hay dos fuentes de varianza distintas: la del muestreo de preguntas (la de la tabla, que no desaparece aunque evalúes con temperatura 0) y la del muestreo de respuestas (temperatura > 0, semillas, orden de few-shot). La primera se ataca con más preguntas o con comparaciones pareadas; la segunda, con varias muestras por pregunta (sección 6).

Regla práctica: si dos checkpoints difieren en menos de ~2·SE en un benchmark de 500-1,000 preguntas, sin un test pareado no puedes afirmar que uno es mejor. Esto aplica a casi todas las tablas de ablación que se ven en reportes de modelos.

3. Intervalos de confianza para una métrica

Tres opciones, de más simple a más general: aproximación normal (buena con n grande y p lejos de 0 o 1), Wilson (la recomendada para proporciones: no se sale de [0, 1] y funciona con n chico) y bootstrap (sirve para cualquier métrica: F1, chrF, BLEU, pass@k). Este módulo es la base del resto de la guía; guárdalo como stats_utils.py.

python — stats_utils.py (parte 1)
"""stats_utils.py: utilidades estadísticas sobre logs por muestra (lm-eval / Inspect)."""
from __future__ import annotations

import glob
import math

import numpy as np
import pandas as pd
from scipy import stats
from statsmodels.stats.contingency_tables import mcnemar
from statsmodels.stats.proportion import proportion_confint


def load_lmeval_samples(run_dir: str, task: str, metric: str = "acc",
                        filter_key: str | None = None) -> pd.DataFrame:
    """Lee samples_<task>_<fecha>.jsonl de una corrida de lm-eval (toma el más reciente)."""
    files = sorted(glob.glob(f"{run_dir}/**/samples_{task}_*.jsonl", recursive=True))
    if not files:
        raise FileNotFoundError(f"No encontré samples_{task}_*.jsonl bajo {run_dir}")
    df = pd.read_json(files[-1], lines=True)
    if filter_key is not None:
        df = df[df["filter"] == filter_key]
    elif df["filter"].nunique() > 1:
        raise ValueError(f"{task} tiene varios filtros {list(df['filter'].unique())}: pasa filter_key")
    out = pd.DataFrame({
        "doc_id": df["doc_id"],
        "score": df[metric].astype(float),
        "prompt_hash": df["prompt_hash"],
        "doc": df["doc"],
    })
    return out.set_index("doc_id").sort_index()


def _z(level: float) -> float:
    return float(stats.norm.ppf(0.5 + level / 2))


def normal_ci(x, level: float = 0.95) -> tuple[float, float, float]:
    """Media, SE i.i.d. e IC normal (lo mismo que reporta lm-eval como acc_stderr)."""
    x = np.asarray(x, dtype=float)
    mean, se = x.mean(), x.std(ddof=1) / math.sqrt(len(x))
    return mean, se, (mean - _z(level) * se, mean + _z(level) * se)


def wilson_ci(x, level: float = 0.95) -> tuple[float, float]:
    """IC de Wilson para una proporción (scores 0/1)."""
    x = np.asarray(x, dtype=float)
    lo, hi = proportion_confint(int(x.sum()), len(x), alpha=1 - level, method="wilson")
    return float(lo), float(hi)


def bootstrap_ci(x, statistic=np.mean, level: float = 0.95,
                 n_resamples: int = 10_000, seed: int = 0) -> tuple[float, float]:
    """IC bootstrap BCa para cualquier estadístico por ítem."""
    res = stats.bootstrap((np.asarray(x, dtype=float),), statistic,
                          n_resamples=n_resamples, confidence_level=level,
                          method="BCa", rng=np.random.default_rng(seed))
    return float(res.confidence_interval.low), float(res.confidence_interval.high)

Bootstrap con n chico o datos degenerados: si todos los scores son iguales (0% o 100%), BCa no está definido y SciPy devuelve nan con una advertencia. Para proporciones usa Wilson; deja el bootstrap para métricas continuas o compuestas.

4. Errores estándar clustered: preguntas que comparten contexto

La fórmula i.i.d. supone preguntas independientes. No lo son cuando varias preguntas comparten un pasaje o un artículo: si el modelo no entiende el pasaje, falla todas las preguntas de ese pasaje a la vez. En ese caso el SE real es mayor. Ejemplos en nuestro contexto:

BenchmarkCluster naturalEstructura
Belebele (es/pt)flores_passage900 preguntas sobre 488 pasajes (1-2 por pasaje)
LatamQA (inria-chile/latamqa_mcq_es-la)article_id18.9K preguntas generadas desde artículos de Wikipedia
Trueque (latam-gpt/Trueque-Benchmark-beta-0.1)country / topic500 preguntas de 23 países

El estimador clustered de Miller (equivalente al sandwich CR0) suma los residuos dentro de cada cluster antes de elevar al cuadrado: SE_cl = sqrt( Σ_c (Σ_{i∈c} (x_i − x̄))² ) / n. Si cada cluster tiene un solo ítem se reduce al SE i.i.d.

# Continúa stats_utils.py (usa los imports de la parte 1)

def clustered_se(x, clusters) -> float:
    """SE clustered (Miller 2024 / sandwich CR0) para la media de x."""
    x = np.asarray(x, dtype=float)
    resid = pd.Series(x - x.mean())
    sums = resid.groupby(np.asarray(clusters)).sum()
    return math.sqrt(float((sums ** 2).sum())) / len(x)

for task in ["belebele_spa_Latn", "belebele_por_Latn"]:

    clusters = [doc["flores_passage"] for doc in df["doc"]]
    mean, se_iid, _ = normal_ci(df["score"])
    se_cl = clustered_se(df["score"], clusters)
    print(f"{task}: acc={mean:.3f}  SE iid={se_iid:.4f}  SE clustered={se_cl:.4f}  "
          f"ratio={se_cl / se_iid:.2f}  ({len(set(clusters))} pasajes)")

Miller reporta que en benchmarks con pasajes compartidos el SE clustered puede ser bastante mayor que el naive. En Belebele, con 1-2 preguntas por pasaje, el efecto es moderado; en LatamQA, donde un artículo genera muchas preguntas, la corrección importa más. Si el ratio sale cercano a 1, reporta igual el clustered: es el honesto.

Pocos clusters: el estimador sandwich subestima el SE con menos de ~30-50 clusters. Para Trueque (23 países) no uses country como cluster para el IC global; úsalo para desagregar resultados por país (sección 8) y ten presente que con ~20 preguntas por país el IC por país ronda ±20 pp: no ordenes países por esos números.

5. Comparar dos modelos: diferencias pareadas

Comparar dos IC separados ("se solapan, entonces no hay diferencia") es un test muy conservador y desperdicia información. Ambos modelos respondieron las mismas preguntas, así que lo correcto es analizar la diferencia pregunta a pregunta d_i = b_i − a_i. Como los scores de dos checkpoints están muy correlacionados (las preguntas difíciles son difíciles para ambos), la varianza de d es mucho menor que la suma de varianzas: Var(a − b) = Var(a) + Var(b) − 2·Cov(a, b).

Para scores binarios, solo importan las preguntas discordantes (una acierta y la otra no). El test exacto natural es McNemar; como alternativa no paramétrica sirve el bootstrap pareado.

# Continúa stats_utils.py (usa los imports y funciones de las partes 1 y 2)

def paired_diff(a, b, clusters=None, level: float = 0.95) -> dict:
    """Δ = mean(b − a) con SE pareado (opcionalmente clustered) e IC normal."""
    d = np.asarray(b, dtype=float) - np.asarray(a, dtype=float)
    se = clustered_se(d, clusters) if clusters is not None else d.std(ddof=1) / math.sqrt(len(d))
    delta = float(d.mean())
    z = _z(level)
    p = 2 * (1 - stats.norm.cdf(abs(delta) / se)) if se > 0 else 1.0
    return {"delta": delta, "se": se, "lo": delta - z * se, "hi": delta + z * se, "p_z": float(p)}


def mcnemar_exact(a, b) -> float:
    """p-valor exacto de McNemar para scores binarios pareados."""
    a = np.asarray(a).astype(bool)
    b = np.asarray(b).astype(bool)
    table = [[int(np.sum(a & b)), int(np.sum(a & ~b))],
             [int(np.sum(~a & b)), int(np.sum(~a & ~b))]]
    return float(mcnemar(table, exact=True).pvalue)


def paired_bootstrap_ci(a, b, level: float = 0.95, n_resamples: int = 10_000,
                        seed: int = 0) -> tuple[float, float]:
    """IC percentil para mean(b − a) remuestreando preguntas (pares)."""
    res = stats.bootstrap(
        (np.asarray(a, dtype=float), np.asarray(b, dtype=float)),
        lambda x, y, axis=-1: np.mean(y - x, axis=axis),
        paired=True, vectorized=True, n_resamples=n_resamples,
        confidence_level=level, method="percentile", rng=np.random.default_rng(seed),
    )
    return float(res.confidence_interval.low), float(res.confidence_interval.high)

Ahora el script que compara dos corridas de lm-eval tarea por tarea. Alinea por doc_id, verifica que los prompts sean idénticos (si cambiaste la plantilla o la semilla de few-shot, el pareo deja de ser válido) y aplica Holm sobre todas las tareas (sección 8).

python — compare_checkpoints.py
"""Uso: python compare_checkpoints.py runs/ckpt-a runs/ckpt-b"""
import sys

import pandas as pd
from statsmodels.stats.multitest import multipletests

from stats_utils import load_lmeval_samples, mcnemar_exact, paired_bootstrap_ci, paired_diff

# tarea -> campo del doc que define el cluster (None = ítems independientes)
TASKS = {
    "belebele_spa_Latn": "flores_passage",
    "belebele_por_Latn": "flores_passage",
    "xstorycloze_es": None,
    "openbookqa_es": None,
    "copa_es": None,
    "paws_es_spanish_bench": None,
    "xnli_es_spanish_bench": None,
    "assin_entailment": None,
}


def compare(run_a: str, run_b: str, metric: str = "acc") -> pd.DataFrame:
    rows = []
    for task, cluster_key in TASKS.items():
        a = load_lmeval_samples(run_a, task, metric)
        b = load_lmeval_samples(run_b, task, metric)
        common = a.index.intersection(b.index)
        a, b = a.loc[common], b.loc[common]
        if not (a["prompt_hash"] == b["prompt_hash"]).all():
            print(f"[aviso] {task}: los prompts difieren entre corridas; revisa plantilla y few-shot")
        clusters = [doc[cluster_key] for doc in a["doc"]] if cluster_key else None
        r = paired_diff(a["score"], b["score"], clusters=clusters)
        boot_lo, boot_hi = paired_bootstrap_ci(a["score"], b["score"])
        rows.append({
            "task": task, "n": len(common),
            "A": a["score"].mean(), "B": b["score"].mean(),
            "delta": r["delta"], "ic_lo": r["lo"], "ic_hi": r["hi"],
            "boot_lo": boot_lo, "boot_hi": boot_hi,
            "p_mcnemar": mcnemar_exact(a["score"], b["score"]),
        })
    df = pd.DataFrame(rows)
    df["p_holm"] = multipletests(df["p_mcnemar"], alpha=0.05, method="holm")[1]
    df["p_bh"] = multipletests(df["p_mcnemar"], alpha=0.05, method="fdr_bh")[1]
    return df


if __name__ == "__main__":
    table = compare(sys.argv[1], sys.argv[2])
    pd.set_option("display.width", 160)
    print(table.round(4).to_string(index=False))
    print("\nSignificativas tras Holm (α=0.05):", list(table.loc[table["p_holm"] < 0.05, "task"]))
Por qué esto cambia decisiones: en Belebele (900 preguntas) dos checkpoints con 71.0% y 73.0% tienen IC separados de ±3 pp que se solapan. Pero si solo discrepan en ~8% de las preguntas, el SE pareado es ≈ sqrt(0.08/900) ≈ 0.9 pp y la diferencia de 2 pp ya es significativa. El pareo no "inventa" significancia: usa la correlación que de verdad existe.

6. Varias muestras por pregunta: avg@k en AIME

Con modelos de razonamiento se reporta avg@k (accuracy promedio sobre k muestras con temperatura > 0). Más muestras reducen la varianza dentro de cada pregunta, pero no la varianza entre preguntas. Con solo 30 problemas, aunque promedies infinitas muestras, un 50% puede cargar ±18 pp si los problemas son casi todos "siempre bien" o "siempre mal". A Sober Look at Progress in LM Reasoning (Hochlehnert et al., 2025) muestra que muchas mejoras reportadas en AIME se diluyen al controlar semillas, parámetros de decodificación y hardware.

Descomposición: si p̂_i es la tasa de acierto del problema i con k muestras, Var(p̂_i) = σ²_entre + E[p_i(1 − p_i)] / k. El script genera 16 muestras por problema y proyecta cómo cambia el SE con k.

python — avgk_variance.py
import math
import re

import numpy as np
from datasets import load_dataset
from vllm import LLM, SamplingParams

MODEL = "Qwen/Qwen3-8B"      # presupuesto reducido: "HuggingFaceTB/SmolLM3-3B"
K = 16

ds = load_dataset("MathArena/aime_2026", split="train")   # 30 problemas; también MathArena/aime_2025
llm = LLM(model=MODEL, dtype="bfloat16", max_model_len=40960, seed=0)
params = SamplingParams(n=K, temperature=0.6, top_p=0.95, max_tokens=32768)

# Instrucción en español: medimos razonamiento matemático con consignas en nuestro idioma
convs = [[{"role": "user",
           "content": "Resuelve el siguiente problema paso a paso y escribe la respuesta final "
                      "(un entero entre 0 y 999) dentro de \\boxed{}.\n\n" + ex["problem"]}]
         for ex in ds]
outputs = llm.chat(convs, params)


def extract_boxed(text: str) -> int | None:
    hits = re.findall(r"\\boxed\{([^{}]*)\}", text)
    if not hits:
        return None
    digits = re.sub(r"[^0-9]", "", hits[-1])
    return int(digits) if digits else None


correct = np.array([[extract_boxed(c.text) == int(ex["answer"]) for c in out.outputs]
                    for ex, out in zip(ds, outputs)], dtype=float)   # (30, K)

n, k = correct.shape
p_i = correct.mean(axis=1)
score = p_i.mean()
se = p_i.std(ddof=1) / math.sqrt(n)
within = float(np.mean(p_i * (1 - p_i)) * k / (k - 1))   # estimador insesgado de E[p_i(1-p_i)]
between = max(float(p_i.var(ddof=1)) - within / k, 0.0)

print(f"avg@{k} = {score:.3f} ± {1.96 * se:.3f}  (n={n} problemas)")
print(f"varianza entre problemas = {between:.4f} · dentro (por muestra) = {within:.4f}")
for kk in [1, 2, 4, 8, 16, 64, 1024]:
    se_k = math.sqrt((between + within / kk) / n)
    print(f"  k={kk:>4}: IC95% ≈ ± {1.96 * se_k * 100:.1f} pp")
Hardware y tiempo: 30 problemas × 16 muestras con hasta 32K tokens de razonamiento para un modelo de 8B toma del orden de 1-2 h en 1× A100 80GB. Con SmolLM3-3B entra en una GPU de 24 GB (baja max_model_len y max_tokens si falta memoria). Típicamente el IC deja de achicarse pasado k≈8-16: a partir de ahí conviene gastar el cómputo en más problemas (AIME 2025 + 2026, HMMT, o MGSM en español) en vez de más muestras.

7. Poder estadístico y efecto mínimo detectable

Antes de correr (o de construir) un benchmark conviene preguntarse: ¿qué diferencia puedo detectar? El efecto mínimo detectable (MDE) con nivel α y poder 1 − β es MDE ≈ (z_{1−α/2} + z_{1−β}) · SE. En comparaciones pareadas binarias, Var(d) ≈ tasa de discordancia (fracción de preguntas donde los modelos difieren), típicamente 5-20% entre checkpoints de un mismo entrenamiento.

# Continúa stats_utils.py (usa los imports de la parte 1)

def _zz(alpha: float, power: float) -> float:
    return float(stats.norm.ppf(1 - alpha / 2) + stats.norm.ppf(power))


def mde_paired(n: int, discordance: float = 0.15, alpha: float = 0.05, power: float = 0.8) -> float:
    """Δ mínimo detectable comparando dos modelos sobre las mismas n preguntas."""
    return _zz(alpha, power) * math.sqrt(discordance / n)


def mde_unpaired(n: int, p: float = 0.6, alpha: float = 0.05, power: float = 0.8) -> float:
    """Δ mínimo detectable si cada modelo se evalúa con preguntas distintas (o sin parear)."""
    return _zz(alpha, power) * math.sqrt(2 * p * (1 - p) / n)


def n_required_paired(delta: float, discordance: float = 0.15,
                      alpha: float = 0.05, power: float = 0.8) -> int:
    """Preguntas necesarias para detectar delta en una comparación pareada."""
    return math.ceil(discordance * (_zz(alpha, power) / delta) ** 2)

8. Comparaciones múltiples: muchas tareas, muchos checkpoints

Si comparas dos checkpoints en 20 tareas con α = 0.05, esperas ~1 "diferencia significativa" aunque los modelos sean idénticos. Las dos correcciones estándar, ambas en statsmodels.stats.multitest.multipletests:

MétodoControlaCuándo usarlo
Holm-Bonferroni ("holm")FWER: probabilidad de al menos un falso positivoDecisiones de release, afirmaciones en un paper o model card
Benjamini-Hochberg ("fdr_bh")FDR: proporción esperada de falsos positivosExploración: barrer muchas ablaciones o tareas para elegir qué mirar

El mismo problema aparece al desagregar por país o por tema. Con los logs de Trueque evaluados con juez (sección 10), el análisis por país con IC de Wilson y Holm queda así:

    # ¿Este país se aparta del promedio global? (test binomial exacto)
    p = binomtest(int(g["score"].sum()), len(g), global_acc).pvalue
    rows.append({"pais": country, "n": len(g), "acc": g["score"].mean(), "lo": lo, "hi": hi, "p": p})

table = pd.DataFrame(rows).sort_values("acc")
table["p_holm"] = multipletests(table["p"], method="holm")[1]
print(f"Global: {global_acc:.3f} (n={len(df)})")
print(table.round(3).to_string(index=False))
Columnas de samples_df: los scores aparecen como score_<nombre_del_scorer> y la metadata de cada Sample como metadata_<campo>. Verifica los nombres con df.columns en tu versión de Inspect antes de filtrar.

9. Sensibilidad a la plantilla del prompt

Hay una tercera fuente de varianza que ni el IC ni el pareo capturan: la elección de plantilla. State of What Art? (Mizrahi et al., 2024) muestra que los rankings de modelos cambian según la paráfrasis de la instrucción, y FormatSpread (Sclar et al., 2023) encuentra diferencias de decenas de puntos solo por formato (separadores, mayúsculas, espacios). La práctica recomendada es evaluar con K plantillas y reportar el rango, no solo la mejor.

python — prompt_spread.py (LatamQA, 5 plantillas en español)
import random
import re

import numpy as np
from datasets import load_dataset
from vllm import LLM, SamplingParams

from stats_utils import mcnemar_exact, wilson_ci

MODEL = "Qwen/Qwen3-8B"
ds = load_dataset("inria-chile/latamqa_mcq_es-la", split="train").shuffle(seed=0).select(range(2000))

TEMPLATES = [
    "Pregunta: {q}\n{opts}\nRespuesta (solo la letra):",
    "Responde la siguiente pregunta de opción múltiple sobre América Latina.\n\n{q}\n\n{opts}\n\nIndica únicamente la letra correcta.",
    "{q}\nOpciones:\n{opts}\nLa respuesta correcta es la letra",
    "Eres un experto en historia y cultura latinoamericana. Elige la alternativa correcta.\n### Pregunta\n{q}\n### Alternativas\n{opts}\n### Respuesta (A, B, C o D):",
    "PREGUNTA: {q} | OPCIONES: {opts} | RESPUESTA:",
]


def build_items(ex: dict, idx: int):
    options = [ex["answer"], ex["distractor1"], ex["distractor2"], ex["distractor3"]]
    order = list(range(4))
    random.Random(idx).shuffle(order)          # mismo orden de opciones para todas las plantillas
    shuffled = [options[i] for i in order]
    gold = "ABCD"[order.index(0)]
    return shuffled, gold


items = [build_items(ex, i) for i, ex in enumerate(ds)]
llm = LLM(model=MODEL, dtype="bfloat16", max_model_len=4096, seed=0)
params = SamplingParams(temperature=0.0, max_tokens=8)

results = {}
for t_id, tpl in enumerate(TEMPLATES):
    convs = []
    for ex, (opts, _) in zip(ds, items):
        sep = " " if "|" in tpl else "\n"
        opts_txt = sep.join(f"{l}) {o}" for l, o in zip("ABCD", opts))
        convs.append([{"role": "user", "content": tpl.format(q=ex["question"], opts=opts_txt)}])
    outs = llm.chat(convs, params, chat_template_kwargs={"enable_thinking": False})
    preds = [(re.findall(r"\b([ABCD])\b", o.outputs[0].text) or [""])[0] for o in outs]
    results[t_id] = np.array([p == gold for p, (_, gold) in zip(preds, items)], dtype=float)
    lo, hi = wilson_ci(results[t_id])
    print(f"plantilla {t_id}: acc={results[t_id].mean():.3f}  IC95%=[{lo:.3f}, {hi:.3f}]")

accs = {t: r.mean() for t, r in results.items()}
best, worst = max(accs, key=accs.get), min(accs, key=accs.get)
print(f"min={min(accs.values()):.3f}  mediana={np.median(list(accs.values())):.3f}  max={max(accs.values()):.3f}")
print(f"McNemar mejor vs peor plantilla: p={mcnemar_exact(results[worst], results[best]):.2e}")

Si el rango entre plantillas supera el IC de una sola plantilla, la elección de prompt importa más que el ruido de muestreo y debes reportarla (o promediar sobre plantillas). Para modelos base y checkpoints de pretraining, preferir la formulación cloze sobre la de opción múltiple reduce esta sensibilidad, como estandarizan OLMES y lighteval (ver la guía de lighteval multilingüe).

10. Hacerlo nativo en Inspect AI

Para métricas de promedio como accuracy, lm-eval reporta el stderr i.i.d. (acc_stderr), sin clustering. Inspect AI (UK AISI) trae las métricas estadísticas integradas: stderr(cluster=...), bootstrap_stderr(), ci(level, method="t" | "bootstrap", cluster=...), ci_wilson(level, cluster=...) y grouped(metric, group_key), donde los clusters y grupos se toman de la metadata de cada Sample.

python — latamqa_ci.py
import random

from inspect_ai import Task, task
from inspect_ai.dataset import FieldSpec, Sample, hf_dataset
from inspect_ai.scorer import accuracy, choice, ci, grouped, model_graded_qa, stderr
from inspect_ai.solver import generate, multiple_choice

# Plantilla en español; mantiene el formato 'ANSWER: X' que parsea el scorer choice()
TEMPLATE_ES = (
    "Responde la siguiente pregunta de opción múltiple. Tu respuesta completa debe tener "
    "el formato 'ANSWER: $LETTER' (sin comillas), donde LETTER es una de {letters}.\n\n"
    "{question}\n\n{choices}"
)


def latamqa_record(record: dict) -> Sample:
    options = [record["answer"], record["distractor1"], record["distractor2"], record["distractor3"]]
    order = list(range(4))
    random.Random(f"{record['article_id']}|{record['question']}").shuffle(order)
    return Sample(
        input=record["question"],
        choices=[options[i] for i in order],
        target="ABCD"[order.index(0)],
        metadata={"article_id": record["article_id"], "title": record["title"]},
    )


@task
def latamqa_ci():
    return Task(
        dataset=hf_dataset("inria-chile/latamqa_mcq_es-la", split="train",
                           sample_fields=latamqa_record),
        solver=multiple_choice(template=TEMPLATE_ES),
        scorer=choice(),
        metrics=[
            accuracy(),
            stderr(cluster="article_id"),
            ci(level=0.95, method="bootstrap", cluster="article_id"),
        ],
    )


@task
def trueque_juez(judge: str = "openai/<modelo-juez>"):
    return Task(
        dataset=hf_dataset("latam-gpt/Trueque-Benchmark-beta-0.1", split="train",
                           sample_fields=FieldSpec(input="question", target="reference_answer",
                                                   metadata=["country", "topic"])),
        solver=generate(),
        scorer=model_graded_qa(model=judge),
        metrics=[accuracy(), stderr(), grouped(accuracy(), "country")],
    )
