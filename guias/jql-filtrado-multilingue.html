JQL: filtrado multilingüe de calidad para español y portugués

Replica JQL para español y portugués. Eliges LLM-jueces por Spearman contra un gold set humano, entrenas cabezas MLP sobre embeddings congelados de Arctic-Embed y filtras FineWeb2 por percentiles con un ensamble de tres cabezas. Para no recalcular lo caro, la guía reutiliza las anotaciones, cabezas, scores y embeddings que JQL publicó para spa_Latn y por_Latn.
1. Qué es JQL y qué resultados reporta
Gold set humano (511 docs × 35 idiomas)
→
Elegir jueces por Spearman
→
3 LLMs anotan 500k docs/idioma
→
Arctic-Embed congelado + 3 MLP
→
Percentil por cabeza + AND

JQL (Judging Quality across Languages, Ali et al., EMNLP 2025) es la receta de 2025 para filtrar por calidad educativa en muchos idiomas a la vez. Arranca con 511 documentos en inglés que anotaron humanos (tres anotaciones independientes por documento, de un grupo de 15 personas) y que luego se tradujeron a 35 idiomas: DeepL para los 22 idiomas que soporta y GPT-4o para el resto. En nuestros dos idiomas, el archivo de español es es_deepl y el de portugués es pt_openai. Con ese gold set se mide qué LLM ordena los documentos como lo harían los humanos. Se usa correlación de Spearman en vez de accuracy porque para filtrar importa el ranking, no acertar el entero exacto.

Los tres jueces elegidos, Gemma-3-27B-it, Mistral-Small-3.1-24B-it y Llama-3.3-70B-it, anotan ~500k documentos por idioma. Esas etiquetas se destilan en cabezas MLP de ~0.8M parámetros (768 → 1000 → 1) que van sobre embeddings congelados de Snowflake/snowflake-arctic-embed-m-v2.0, un encoder multilingüe con contexto de 8192 tokens. Como el embedding ya está alineado entre idiomas, una sola cabeza funciona en todos ellos e incluso transfiere a idiomas que no vio. La selección final no usa un umbral absoluto. Cada cabeza tiene su propio percentil, calculado sobre FineWeb2 sin filtrar de ese idioma, y un documento entra solo si las tres cabezas superan el suyo.

Los proxies son modelos densos de 2B con arquitectura Llama, entrenados con 27B o 14B tokens monolingües y evaluados con versiones multilingües de MMLU, HellaSwag y ARC. Lo interesante para LatamGPT es que JQL mejora la calidad sin perder volumen. En español, que tiene mucho texto pero no infinito, eso pesa más que en inglés.

2. JQL frente a la guía FineWeb-Edu

La guía FineWeb-Edu: etiquetar con LLM y clasificador BERT enseña la receta original de 2024. Sigue siendo útil para entender el patrón LLM → clasificador, pero tiene tres debilidades que JQL resuelve.

¿Por qué percentiles y no un umbral fijo? Cada juez usa la escala 0-5 a su manera: en los scores publicados de FineWeb2 español, la cabeza de Gemma suele dar valores más altos que la de Llama para el mismo documento. Un umbral ≥ 3 retiene entonces volúmenes muy distintos según la cabeza y el idioma. Con el percentil fijas el volumen de antemano, y el AND entre jueces hace de "votación" que descarta los documentos en que los jueces no coinciden.

El join con el texto no es trivial. En fw2_edu_scores y fw2_embeddings la clave es document_id con el formato "<hash>_<n>". Ese no es el id de FineWeb2 (<urn:uuid:...>), y los shards (000_000_00000.jsonl) no coinciden con los parquet actuales de FineWeb2 (000_00000.parquet), porque JQL trabajó sobre una versión anterior al re-sharding de FineWeb2 v2.1. Los cards no documentan cómo volver al texto. Úsalos sin riesgo para lo que no necesita texto: calibrar percentiles, comparar cabezas y medir la distribución de cabezas nuevas. Para materializar el subconjunto final, puntúa tú el texto (§10) o valida primero un mapeo sobre una muestra.

6. Elegir LLM-jueces por Spearman (Ruta B)

Solo hace falta si quieres jueces más nuevos que los del paper (por ejemplo google/gemma-4-31B-it o Qwen/Qwen3.6-27B) o validar a los originales contra tu gold nativo. Igual que JQL, se usa el prompt de FineWeb-Edu en inglés también para documentos en es/pt. Así la rúbrica es la misma en todos los idiomas y los puntajes se pueden comparar; la guía fineweb-edu, en cambio, traduce el prompt. Corre este bloque en el entorno .venv-annot, un juez a la vez.

python
import re
import sys
from collections import Counter
from pathlib import Path

import numpy as np
import pandas as pd
from huggingface_hub import hf_hub_download
from scipy.stats import spearmanr
from vllm import LLM, SamplingParams

JUDGE = sys.argv[1] if len(sys.argv) > 1 else "google/gemma-3-27b-it"
TP = int(sys.argv[2]) if len(sys.argv) > 2 else 1          # 4 para Llama-3.3-70B en 80 GB

prompt_path = hf_hub_download("HuggingFaceFW/fineweb-edu-classifier", "utils/prompt.txt")
PROMPT = open(prompt_path, encoding="utf-8").read()       # contiene el marcador <EXAMPLE>
SCORE_RE = re.compile(r"Educational score:\s*([0-5])")

gold = pd.read_parquet("gold_jql_es_pt.parquet")
if Path("gold_nativo_es_pt.parquet").exists():                  # gold nativo de la §5, si ya lo tienes
    native = pd.read_parquet("gold_nativo_es_pt.parquet").assign(lang=lambda d: d["lang"] + "-nativo")
    gold = pd.concat([gold, native[["document_id", "text", "score", "lang"]]], ignore_index=True)

llm = LLM(model=JUDGE, tensor_parallel_size=TP, max_model_len=8192,
          enable_prefix_caching=True, gpu_memory_utilization=0.90)
tok = llm.get_tokenizer()

def truncate(text: str, max_tokens: int = 2000) -> str:
    return tok.decode(tok.encode(text, add_special_tokens=False)[:max_tokens])

convs = [[{"role": "user", "content": PROMPT.replace("<EXAMPLE>", truncate(t))}]
         for t in gold["text"]]
params = SamplingParams(n=3, temperature=0.6, max_tokens=256, seed=0)
extra = {"enable_thinking": False} if "Qwen3" in JUDGE else None   # Qwen3.x híbridos: sin thinking
outs = llm.chat(convs, params, chat_template_kwargs=extra, use_tqdm=True)

def aggregate(output) -> tuple[float, int]:
    votes = [int(m.group(1)) for c in output.outputs if (m := SCORE_RE.search(c.text))]
    if not votes:
        return np.nan, 3
    value, count = Counter(votes).most_common(1)[0]
    score = float(value) if count >= 2 else float(np.mean(votes))   # mayoría, o promedio
    return score, 3 - len(votes)

res = [aggregate(o) for o in outs]
gold["judge"] = [r[0] for r in res]
gold["invalid"] = [r[1] for r in res]

for lang, g in gold.groupby("lang"):
    ok = g.dropna(subset=["judge"])
    rho = spearmanr(ok["judge"], ok["score"]).statistic
    print(f"{JUDGE:45s} [{lang:9s}] Spearman={rho:.3f}  inválidas={g['invalid'].sum() / (3 * len(g)):.1%}")
Criterio de selección: quédate con los 3 mejores por Spearman de familias distintas, porque el ensamble AND aprovecha que se equivocan de maneras diferentes. Mide es y pt por separado: la correlación de un mismo juez puede caer bastante en portugués. Descarta los que tengan más de ~5% de respuestas sin parsear. Si un juez se sale del formato con frecuencia, puedes restringir la salida con SamplingParams(structured_outputs=StructuredOutputsParams(regex=...)) (vLLM ≥ 0.12 eliminó guided_regex), pero pierdes la justificación previa al score.

8. Embeddings congelados con Arctic-Embed-m-v2.0

Hay que reproducir exactamente el embedding de JQL: token CLS de last_hidden_state, normalización L2, hasta 8192 tokens y sin el prefijo query: , que solo se usa para consultas de búsqueda. Si cambias cualquiera de esos detalles, las cabezas oficiales y los embeddings publicados dejan de ser compatibles con los tuyos. Guarda este bloque como jql_embed.py: las secciones siguientes lo importan.

python
"""jql_embed.py: embeddings Arctic-Embed-m-v2.0 compatibles con JQL (CLS + L2)."""
import numpy as np
import torch
import torch.nn.functional as F
from transformers import AutoModel, AutoTokenizer

MODEL_ID = "Snowflake/snowflake-arctic-embed-m-v2.0"


class ArcticEmbedder:
    def __init__(self, device: str = "cuda", max_length: int = 8192, fast_attention: bool = True):
        # fast_attention=True requiere xformers compatible; si falla, pásalo en False.
        self.device = device
        self.max_length = max_length
        self.tok = AutoTokenizer.from_pretrained(MODEL_ID)
        self.model = AutoModel.from_pretrained(
            MODEL_ID,
            trust_remote_code=True,          # GteModel aún no es nativo en transformers
            add_pooling_layer=False,
            dtype=torch.bfloat16,
            unpad_inputs=fast_attention,
            use_memory_efficient_attention=fast_attention,
        ).to(device).eval()

    @torch.inference_mode()
    def embed(self, texts: list[str]) -> torch.Tensor:
        batch = self.tok(texts, max_length=self.max_length, padding="longest",
                         truncation=True, return_tensors="pt").to(self.device)
        cls = self.model(**batch).last_hidden_state[:, 0]
        return F.normalize(cls.float(), p=2, dim=1)

    def embed_corpus(self, texts: list[str], max_chars: int = 400_000, max_batch: int = 256) -> np.ndarray:
        """Lotes por presupuesto de caracteres, de los textos más largos a los más cortos (OOM temprano)."""
        order = np.argsort([len(t) for t in texts])[::-1]
        out = np.empty((len(texts), 768), dtype=np.float16)
        batch, chars = [], 0
        for idx in order:
            n = min(len(texts[idx]), self.max_length * 6)
            if batch and (chars + n > max_chars or len(batch) == max_batch):
                out[batch] = self.embed([texts[j] for j in batch]).cpu().numpy()
                batch, chars = [], 0
            batch.append(int(idx))
            chars += n
        if batch:
            out[batch] = self.embed([texts[j] for j in batch]).cpu().numpy()
        return out

9. Entrenar las cabezas MLP

Usamos los hiperparámetros del paper: MLP 768 → 1000 → 1 con ReLU, pérdida MSE, AdamW con lr 5e-4 y schedule coseno, batch 1024, hasta 20 épocas, y early stopping si el Spearman de validación no mejora al menos 1e-3 en 5 épocas seguidas. Se entrena una cabeza por juez con es + pt juntos. La variante balanced sobremuestrea los scores altos (4-5), que son escasos en la web.

python
import numpy as np
import pandas as pd
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset, WeightedRandomSampler
from scipy.stats import spearmanr
from safetensors.torch import save_file

LANGS = ["spa_Latn", "por_Latn"]


def make_head() -> nn.Module:
    return nn.Sequential(nn.Linear(768, 1000), nn.ReLU(), nn.Linear(1000, 1))


def load_xy(judge: str):
    X = np.concatenate([np.load(f"annot_{l}.emb.npy") for l in LANGS]).astype(np.float32)
    y = np.concatenate([pd.read_parquet(f"annot_{l}.parquet", columns=[judge])[judge].to_numpy(np.float32)
                        for l in LANGS])
    return X, y


def train_head(judge: str, balanced: bool = True, epochs: int = 20, patience: int = 5,
               min_delta: float = 1e-3, device: str = "cuda") -> float:
    X, y = load_xy(judge)
    idx = np.random.default_rng(0).permutation(len(y))
    n_val = int(0.05 * len(y))
    va, tr = idx[:n_val], idx[n_val:]
    ds = TensorDataset(torch.from_numpy(X[tr]), torch.from_numpy(y[tr]))
    if balanced:
        cls = np.clip(np.rint(y[tr]), 0, 5).astype(int)
        freq = np.bincount(cls, minlength=6).astype(np.float64)
        weights = torch.from_numpy(1.0 / freq[cls])
        loader = DataLoader(ds, batch_size=1024,
                            sampler=WeightedRandomSampler(weights, num_samples=len(tr), replacement=True))
    else:
        loader = DataLoader(ds, batch_size=1024, shuffle=True)

    head = make_head().to(device)
    opt = torch.optim.AdamW(head.parameters(), lr=5e-4)
    sched = torch.optim.lr_scheduler.CosineAnnealingLR(opt, T_max=epochs * len(loader))
    loss_fn = nn.MSELoss()
    X_va = torch.from_numpy(X[va]).to(device)

    best, best_state, bad = -1.0, None, 0
    for ep in range(epochs):
        head.train()
        for xb, yb in loader:
            xb, yb = xb.to(device), yb.to(device)
            loss = loss_fn(head(xb).squeeze(-1), yb)
            opt.zero_grad(set_to_none=True)
            loss.backward()
            opt.step()
            sched.step()
        head.eval()
        with torch.no_grad():
            pred = head(X_va).squeeze(-1).cpu().numpy()
        rho = spearmanr(pred, y[va]).statistic
        print(f"{judge} ep{ep:02d} loss={loss.item():.3f} val_spearman={rho:.4f}")
        if rho > best + min_delta:
            best, bad = rho, 0
            best_state = {k: v.detach().cpu().clone() for k, v in head.state_dict().items()}
        else:
            bad += 1
            if bad >= patience:
                break
    tag = "balanced" if balanced else "unbalanced"
    save_file(best_state, f"head-{judge}-{tag}.safetensors")
    return best


for judge in ["gemma", "mistral", "llama"]:
    print(judge, "mejor Spearman de validación:", round(train_head(judge), 4))

10. Evaluar: cabezas oficiales, propias y el clasificador FineWeb-Edu

Todo se compara con la misma métrica, el Spearman contra los humanos, en el gold traducido y en el gold nativo. Los checkpoints oficiales vienen en formato Lightning, con capas layer1/layer2. Los mapeamos a nn.Sequential para no depender de Lightning.

python
from pathlib import Path

import numpy as np
import pandas as pd
import torch
from torch import nn
from huggingface_hub import hf_hub_download
from safetensors.torch import load_file
from scipy.stats import spearmanr
from transformers import AutoModelForSequenceClassification, AutoTokenizer


def make_head() -> nn.Module:
    return nn.Sequential(nn.Linear(768, 1000), nn.ReLU(), nn.Linear(1000, 1))


def load_official(judge: str, tag: str = "balanced") -> nn.Module:
    path = hf_hub_download("JQL-AI/JQL-Edu-Heads", f"checkpoints/edu-{judge}-snowflake-{tag}.ckpt")
    # Checkpoint de Lightning: weights_only=False SOLO porque es un archivo de confianza.
    ckpt = torch.load(path, map_location="cpu", weights_only=False)
    sd = {k.replace("layer1.", "0.").replace("layer2.", "2."): v.float()
          for k, v in ckpt["state_dict"].items() if k.startswith(("layer1.", "layer2."))}
    head = make_head()
    head.load_state_dict(sd)
    return head.eval()


def load_own(judge: str, tag: str = "balanced") -> nn.Module:
    head = make_head()
    head.load_state_dict(load_file(f"head-{judge}-{tag}.safetensors"))
    return head.eval()


rows = []
for gold_name in ["gold_jql_es_pt", "gold_nativo_es_pt"]:
    if not Path(f"{gold_name}.emb.npy").exists():
        continue
    gold = pd.read_parquet(f"{gold_name}.parquet")
    X = torch.from_numpy(np.load(f"{gold_name}.emb.npy").astype(np.float32))
    y = gold["score"].to_numpy()
    preds = {}
    for judge in ["gemma", "mistral", "llama"]:
        with torch.no_grad():
            preds[f"JQL oficial {judge}"] = load_official(judge)(X).squeeze(-1).numpy()
            preds[f"propia {judge}"] = load_own(judge)(X).squeeze(-1).numpy()

    # Línea base de la guía fineweb-edu: clasificador inglés, 512 tokens.
    tok = AutoTokenizer.from_pretrained("HuggingFaceFW/fineweb-edu-classifier")
    clf = AutoModelForSequenceClassification.from_pretrained("HuggingFaceFW/fineweb-edu-classifier").eval()
    fw = []
    with torch.no_grad():
        for i in range(0, len(gold), 32):
            enc = tok(gold["text"].iloc[i:i + 32].tolist(), truncation=True, max_length=512,
                      padding=True, return_tensors="pt")
            fw.append(clf(**enc).logits.squeeze(-1).float().numpy())
    preds["fineweb-edu-classifier"] = np.concatenate(fw)

    for name, p in preds.items():
        for lang in gold["lang"].unique():
            m = (gold["lang"] == lang).to_numpy()
            rows.append({"modelo": name, "gold": f"{gold_name}:{lang}",
                         "spearman": spearmanr(p[m], y[m]).statistic})

print(pd.DataFrame(rows).pivot(index="modelo", columns="gold", values="spearman").round(3))

Qué esperar. Tus cabezas deberían quedar muy cerca de las oficiales en el gold traducido, porque usan los mismos datos y el mismo embedding; una diferencia grande indica un bug en el embedding. El clasificador FineWeb-Edu suele perder correlación fuera del inglés. Lo más informativo es la columna del gold nativo: si ahí todas las cabezas caen, el problema es el criterio "educativo" aplicado a la web latinoamericana, no la arquitectura. Otras líneas base que valen la pena: HuggingFaceFW/finepdfs_edu_classifier_spa_Latn / _por_Latn, utter-project/EuroFilter-v1 y Polygl0t/portuguese-bertimbau-edu-classifier.

11. Umbrales por percentil con los scores publicados

JQL calcula el percentil de cada cabeza sobre FineWeb2 sin filtrar (filtered + removed) de cada idioma. Con fw2_edu_scores no hace falta GPU: basta con descargar algunos shards de cada split y ponderarlos por el tamaño real del split, porque en portugués removed es más grande que filtered.

python
import random
import numpy as np
import pandas as pd
from huggingface_hub import HfApi, hf_hub_download

REPO = "JQL-AI/fw2_edu_scores"
COLS = ["score_Gemma_Snowflake", "score_Mistral_Snowflake", "score_Llama_Snowflake"]
DOCS = {  # documentos por split, según el dataset card
    "spa_Latn": {"filtered": 441_287_261, "removed": 431_159_798},
    "por_Latn": {"filtered": 199_737_979, "removed": 285_961_147},
}
FILES = HfApi().list_repo_files(REPO, repo_type="dataset")


def sample_split(lang: str, split: str, n_shards: int = 2, rows_per_shard: int = 500_000) -> pd.DataFrame:
    shards = sorted(f for f in FILES if f.startswith(f"{lang}/{split}/"))
    parts = []
    for f in random.Random(0).sample(shards, n_shards):          # ~1.3-1.5 GB por shard
        path = hf_hub_download(REPO, f, repo_type="dataset")
        parts.append(pd.read_json(path, lines=True, nrows=rows_per_shard)[COLS])
    df = pd.concat(parts, ignore_index=True)
    df["split"] = split
    df["w"] = DOCS[lang][split] / len(df)                          # peso = docs reales / docs muestreados
    return df


def weighted_quantile(x: np.ndarray, w: np.ndarray, q: float) -> float:
    o = np.argsort(x)
    cw = np.cumsum(w[o])
    return float(np.interp(q, cw / cw[-1], x[o]))


thresholds = {}
for lang in DOCS:
    df = pd.concat([sample_split(lang, "filtered"), sample_split(lang, "removed")], ignore_index=True)
    w = df["w"].to_numpy()
    for q in (0.6, 0.7):
        thr = {c: weighted_quantile(df[c].to_numpy(), w, q) for c in COLS}
        thresholds[(lang, q)] = thr
        keep = np.all([df[c].to_numpy() > t for c, t in thr.items()], axis=0)   # AND de 3 cabezas
        kept_docs = (w * keep).sum()
        rescued = (w * keep)[df["split"].eq("removed").to_numpy()].sum()
        print(f"{lang} p{q}: umbrales={ {c.split('_')[1]: round(t, 3) for c, t in thr.items()} }")
        print(f"   retiene {kept_docs / w.sum():.1%} del total = {kept_docs / DOCS[lang]['filtered']:.0%} "
              f"de los docs de FW2 filtered; {rescued / kept_docs:.1%} vienen de FW2 removed")
    print(df[COLS].corr(method="spearman").round(3))

Fíjate en dos cosas. La primera es la fracción de documentos que JQL "rescata" de _removed: las heurísticas de FineWeb2 descartan texto bueno, y por eso JQL puede ganar tokens. La segunda es la correlación entre cabezas, que suele ser alta pero no perfecta; ese desacuerdo es justamente lo que el AND aprovecha. Los volúmenes salen en documentos; para hablar de tokens necesitas el texto (§12).

Cabezas nuevas sobre fw2_embeddings, sin re-embeber

Continúa el bloque anterior, en la misma sesión. Si entrenaste una cabeza propia (por ejemplo, con jueces 2026 o con un criterio regional), sus percentiles salen de los embeddings publicados sin volver a correr el encoder: es una multiplicación de matrices por shard de ~5.4 GB.

python
# Continúa el bloque anterior (usa random, np, HfApi, hf_hub_download y weighted_quantile).
import h5py
import torch
from torch import nn
from safetensors.torch import load_file

EMB_REPO = "JQL-AI/fw2_embeddings"
emb_files = HfApi().list_repo_files(EMB_REPO, repo_type="dataset")
head = nn.Sequential(nn.Linear(768, 1000), nn.ReLU(), nn.Linear(1000, 1))
head.load_state_dict(load_file("head-gemma-balanced.safetensors"))
head = head.cuda().eval()

scores, weights = [], []
for split, n_docs in DOCS["spa_Latn"].items():
    shard = random.Random(1).choice(sorted(f for f in emb_files if f.startswith(f"spa_Latn/{split}/")))
    path = hf_hub_download(EMB_REPO, shard, repo_type="dataset")
    with h5py.File(path, "r") as f:
        E = f["train/embeddings"]
        part = []
        for i in range(0, E.shape[0], 1_000_000):
            x = torch.from_numpy(E[i:i + 1_000_000].astype(np.float32)).cuda()
            with torch.no_grad():
                part.append(head(x).squeeze(-1).cpu().numpy())
    part = np.concatenate(part)
    scores.append(part)
    weights.append(np.full(len(part), n_docs / len(part)))

s, w = np.concatenate(scores), np.concatenate(weights)
print("p60 de la cabeza propia:", round(weighted_quantile(s, w, 0.6), 3),
      "| p70:", round(weighted_quantile(s, w, 0.7), 3))
12. Puntuar el texto con datatrove y seleccionar

Para materializar el subconjunto necesitas el score junto al texto. Este PipelineStep de datatrove 0.10 embebe, aplica las tres cabezas y escribe score_<cabeza> en los metadatos sin filtrar todavía. Guardar todos los scores te deja cambiar de percentil o agregar cabezas sin volver a pasar por la GPU. Ejecuta una task por GPU; en un cluster, cambia LocalPipelineExecutor por SlurmPipelineExecutor.

python
# jql_score.py (necesita jql_embed.py en el mismo directorio)
import torch
from datatrove.data import DocumentsPipeline
from datatrove.executor import LocalPipelineExecutor
from datatrove.pipeline.base import PipelineStep
from datatrove.pipeline.readers import ParquetReader
from datatrove.pipeline.writers import ParquetWriter
from datatrove.utils.batching import batched


class JQLScorer(PipelineStep):
    name = "JQL scorer"
    type = "Annotator"

    def __init__(self, head_paths: dict[str, str], batch_size: int = 1024):
        super().__init__()
        self.head_paths = head_paths
        self.batch_size = batch_size

    def run(self, data: DocumentsPipeline, rank: int = 0, world_size: int = 1) -> DocumentsPipeline:
        from safetensors.torch import load_file
        from torch import nn
        from jql_embed import ArcticEmbedder

        device = f"cuda:{rank % torch.cuda.device_count()}"
        embedder = ArcticEmbedder(device=device)
        heads = {}
        for name, path in self.head_paths.items():
            h = nn.Sequential(nn.Linear(768, 1000), nn.ReLU(), nn.Linear(1000, 1))
            h.load_state_dict(load_file(path))
            heads[name] = h.to(device).eval()

        for batch in batched(data, self.batch_size):
            with self.track_time(unit="batch"):
                emb = torch.from_numpy(embedder.embed_corpus([d.text for d in batch])).to(device).float()
                with torch.no_grad():
                    scores = {n: h(emb).squeeze(-1).cpu().numpy() for n, h in heads.items()}
            for i, doc in enumerate(batch):
                for n, s in scores.items():
                    doc.metadata[f"score_{n}"] = float(s[i])
                self.stat_update("scored")
                yield doc


if __name__ == "__main__":
    n_gpus = torch.cuda.device_count()
    heads = {j: f"head-{j}-balanced.safetensors" for j in ["gemma", "mistral", "llama"]}
    for subset in ["spa_Latn", "spa_Latn_removed"]:
        LocalPipelineExecutor(
            pipeline=[
                ParquetReader(f"hf://datasets/HuggingFaceFW/fineweb-2/data/{subset}/train",
                              limit=200_000),          # quita el limit para la corrida real
                JQLScorer(heads),
                ParquetWriter(f"jql_scored/{subset}"),
            ],
            tasks=n_gpus, workers=n_gpus,
            logging_dir=f"logs/jql_{subset}",
        ).run()

python
import glob
import numpy as np
import pandas as pd
import tldextract

HEADS = ["gemma", "mistral", "llama"]
LATAM = {"ar", "bo", "br", "cl", "co", "cr", "cu", "do", "ec", "gt", "hn", "mx",
         "ni", "pa", "pe", "py", "sv", "uy", "ve", "pr"}

frames = []
for split in ["spa_Latn", "spa_Latn_removed"]:
    for f in glob.glob(f"jql_scored/{split}/*.parquet"):
        df = pd.read_parquet(f)
        meta = pd.json_normalize(df["metadata"].tolist()) if "metadata" in df.columns else df
        meta["words"] = df["text"].str.split().str.len().to_numpy()
        meta["split"] = split
        frames.append(meta)
docs = pd.concat(frames, ignore_index=True)

# Percentiles sobre la población completa (filtered + removed), como en JQL
q = 0.6
thr = {h: docs[f"score_{h}"].quantile(q) for h in HEADS}
docs["keep"] = np.all([docs[f"score_{h}"] > thr[h] for h in HEADS], axis=0)

fw2_words = docs.loc[docs["split"] == "spa_Latn", "words"].sum()
jql_words = docs.loc[docs["keep"], "words"].sum()
print(f"JQL p{q}: {jql_words / fw2_words:.1%} de las palabras de FW2 filtered")

docs["tld"] = docs["url"].map(lambda u: tldextract.extract(u).suffix.split(".")[-1])
docs["region"] = np.where(docs["tld"].isin(LATAM), docs["tld"],
                          np.where(docs["tld"] == "es", "es (España)", "otros"))
by_region = docs.groupby("region").agg(docs_total=("keep", "size"), retencion=("keep", "mean"))
print(by_region.sort_values("docs_total", ascending=False).round(3).head(25))
Auditoría por país, obligatoria: si la retención de .cl, .pe o .bo queda muy por debajo de la de .es, el filtro está castigando temas o registros locales y no la calidad. Antes de aplicar un umbral global, inspecciona a mano 50 documentos descartados por país. Si el sesgo se confirma, una opción es usar percentiles por región o garantizar una cuota mínima por país. Para muestras pequeñas, aplica también rehydration por minhash_cluster_size, como en FineWeb2.
13. Validación downstream con modelos proxy

El Spearman no reemplaza a entrenar un modelo. 14. Extensiones y riesgos para Latam
TemaRecomendación
Cabezas extraSobre el mismo embedding puedes entrenar cabezas de toxicidad, dominio (salud, derecho, código) y relevancia regional. Cada una cuesta minutos y se aplica a los embeddings ya calculados
Registro coloquialEl criterio "educativo" castiga foros, diálogo y literatura. No todo el corpus de pretraining debe salir de este filtro: mézclalo con fuentes conversacionales y literarias
Lenguas originariasNo apliques JQL a guaraní, quechua, mapudungun o aimara (gug, quy, arn, ayr). Su volumen en FineWeb2 es mínimo, así que conviene conservarlo todo y solo deduplicar
Gold traducidoReporta siempre el Spearman en el gold nativo, además del traducido. Si los dos divergen, el nativo manda
Licencias y data cardFineWeb2 y las anotaciones de JQL (humanas y de LLM) se publican bajo ODC-By; los cards de fw2_edu_scores y fw2_embeddings no declaran licencia, así que confírmala con los autores antes de redistribuir derivados. Documenta en el data card qué versión de FW2, qué cabezas, qué percentiles y qué retención por país usaste
"Removing Noise, not Finding Gold"Hay evidencia de que estos filtros ganan sobre todo por eliminar ruido. Compara también con un filtro de ruido más barato antes de concluir que el criterio educativo es lo que suma
