RAG en español y portugués

Un pipeline de retrieval-augmented generation completo y medible para es/pt: BM25 con stemming español/portugués, embeddings multilingües, fusión RRF, reranker, generación con citas y abstención servida con vLLM, y evaluación por país con MessIRve (Chile, México, Argentina) y Quati (Brasil) en vez de benchmarks traducidos.

1. Arquitectura de un RAG moderno

Documentos es/pt
→
Chunking + contexto
→
BM25 + denso (top-100)
→
Fusión RRF
→
Reranker (top-50 → 5)
→
LLM con citas [n] o abstención
→
Evaluación por etapa

Un RAG no es "un vector store más un prompt". Es una cadena de etapas que fallan por separado: si el pasaje correcto nunca entra al top-100, ningún reranker ni LLM lo arregla. Por eso la guía mide cada etapa contra juicios de relevancia (qrels) antes de mirar la respuesta final. La receta que se sostiene a 2026 es híbrida: BM25 encuentra nombres propios, siglas, números de ley y RUT/CUIT/CPF que los embeddings difuminan, el bi-encoder denso encuentra paráfrasis y sinónimos, Reciprocal Rank Fusion combina ambos rankings sin calibrar scores y un cross-encoder reordena los candidatos. En los experimentos de Contextual Retrieval de Anthropic, sumar BM25 y contexto a los embeddings bajó 49% las fallas de recuperación en el top-20, y 67% al agregar reranking.

¿RAG, contexto largo o búsqueda agéntica? Si el corpus son unas decenas de documentos que caben en la ventana (Qwen3.5 soporta 262k tokens nativos) y se consulta poco, meter todo en el contexto es más simple; trabajos como QwenLong-L1.5 entrenan explícitamente el razonamiento sobre contextos largos. Pero cada consulta paga todos esos tokens y la precisión cae con distractores (Lost in the Middle). Con miles o millones de pasajes, RAG híbrido sigue siendo lo más barato y auditable; la búsqueda agéntica (el modelo decide qué buscar en varias vueltas) conviene para preguntas multi-hop y se trata en la guía de agentes con tool calling y MCP.

2. Datos de evaluación nativos: MessIRve y Quati

MessIRve trae consultas reales en español extraídas del autocompletado de Google en más de 20 países, cada una con el párrafo de Wikipedia que la respondía en el featured snippet, sobre un corpus de ~14M párrafos (spanish-ir/eswiki_20240401_corpus). Hay un subset por país (cl, mx, ar, co, pe...), más full y no_country. Eso permite algo que un benchmark traducido no puede: ver si tu retriever rinde distinto con consultas chilenas que con argentinas. El script arma un sub-corpus manejable: todos los párrafos relevantes de los países elegidos más 500k distractores aleatorios, y guarda consultas y qrels por país. Indexar una sola vez y evaluar por país hace comparables los resultados.

python
# 00_data_es.py — sub-corpus eswiki + consultas/qrels de MessIRve por país
import json
from collections import defaultdict

import numpy as np
from datasets import load_dataset

COUNTRIES = ["cl", "mx", "ar"]
N_DISTRACTORS = 500_000
SEED = 42

relevant = set()
for country in COUNTRIES:
    # datasets 5.x: un config por país, sin loading script
    ds = load_dataset("spanish-ir/messirve", country, split="test")
    queries, qrels = {}, defaultdict(dict)
    for row in ds:
        qid = str(row["id"])
        queries[qid] = row["query"]
        qrels[qid][row["docid"]] = 1          # párrafo del featured snippet
        relevant.add(row["docid"])
    with open(f"eval_{country}.json", "w", encoding="utf-8") as f:
        json.dump({"queries": queries, "qrels": qrels}, f, ensure_ascii=False)
    print(f"{country}: {len(queries):,} consultas")

# ~14M párrafos (3.1 GB en parquet); se descarga una vez y queda en caché
corpus = load_dataset("spanish-ir/eswiki_20240401_corpus", split="corpus")
docids = corpus.select_columns(["docid"]).to_pandas()["docid"]
mask = docids.isin(relevant).to_numpy()
rel_idx = np.flatnonzero(mask)
print(f"relevantes encontrados: {len(rel_idx):,} de {len(relevant):,}")

rng = np.random.default_rng(SEED)
dist_idx = rng.choice(np.flatnonzero(~mask), size=N_DISTRACTORS, replace=False)
sub = corpus.select(np.sort(np.concatenate([rel_idx, dist_idx])).tolist())
sub.select_columns(["docid", "title", "text"]).to_parquet("corpus_es.parquet")
print(f"sub-corpus: {len(sub):,} pasajes")

3. Chunking y contexto

Los corpus de evaluación ya vienen en párrafos. Tus documentos reales (leyes, fallos, licitaciones, guías clínicas) no: hay que cortarlos respetando su estructura. Reglas que funcionan: chunks de 300-500 tokens medidos con el tokenizer del embedder, cortes en límites naturales (párrafo, artículo, inciso) y un párrafo de solapamiento. En textos legales chilenos, argentinos o brasileños conviene cortar primero por Artículo N / Art. N y recién después por longitud.

python
import re
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen3-Embedding-0.6B")
ARTICLE_RE = re.compile(r"\n(?=(?:Artículo|Art\.)\s+\d+)")    # es; en pt también "Art. 5º"


def n_tokens(text):
    return len(tok(text, add_special_tokens=False)["input_ids"])


def chunk_document(text, max_tokens=400, overlap=1):
    """Agrupa párrafos hasta max_tokens; repite los últimos `overlap` párrafos en el siguiente chunk.
    Un párrafo más largo que max_tokens queda como chunk propio (revísalos aparte)."""
    units = []
    for block in ARTICLE_RE.split(text):
        units += [p.strip() for p in re.split(r"\n\s*\n", block) if p.strip()]
    chunks, cur = [], []
    for unit in units:
        if cur and sum(n_tokens(u) for u in cur) + n_tokens(unit) > max_tokens:
            chunks.append("\n\n".join(cur))
            cur = cur[-overlap:] if overlap else []
        cur.append(unit)
    if cur:
        chunks.append("\n\n".join(cur))
    return chunks

Un chunk aislado pierde su contexto: "El plazo será de 30 días hábiles" no dice de qué ley ni de qué trámite. Contextual retrieval le pide a un LLM una o dos oraciones que ubiquen el chunk dentro del documento y las antepone antes de indexar (tanto en BM25 como en el denso). En Wikipedia la versión gratuita es anteponer el título del artículo, que es lo que hacen los scripts de esta guía. La versión con LLM, contra el servidor de la sección 9:

python
import asyncio
from openai import AsyncOpenAI

client = AsyncOpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
MODEL = "Qwen/Qwen3.5-9B"

# El documento va PRIMERO: así todos los chunks del mismo documento comparten prefijo
# y el prefix caching de vLLM evita recalcularlo en cada llamada.
PROMPT = """<documento>
{doc}
</documento>

Este es un fragmento del documento anterior:
<fragmento>
{chunk}
</fragmento>

Escribe una o dos oraciones en el mismo idioma del documento que sitúen el fragmento
(qué norma, sección o tema trata) para mejorar su recuperación en un buscador.
Responde solo con ese contexto."""


async def contextualize(doc, chunks, max_concurrency=32):
    sem = asyncio.Semaphore(max_concurrency)

    async def one(chunk):
        async with sem:
            r = await client.chat.completions.create(
                model=MODEL,
                messages=[{"role": "user", "content": PROMPT.format(doc=doc, chunk=chunk)}],
                temperature=0.0,
                max_tokens=120,
                extra_body={"chat_template_kwargs": {"enable_thinking": False}},
            )
            return r.choices[0].message.content.strip() + "\n\n" + chunk

    return await asyncio.gather(*(one(c) for c in chunks))

# uso: textos_a_indexar = asyncio.run(contextualize(texto_ley, chunk_document(texto_ley)))
# El documento debe caber en --max-model-len (32k en la sección 9); si no, pasa solo la sección que contiene el chunk.
Late chunking es la alternativa sin LLM: se pasa el documento completo por un embedder de contexto largo y se hace pooling de los token embeddings de cada chunk, de modo que cada vector "vio" el documento. Requiere acceso a los token embeddings (no solo al vector final) y documentos que quepan en la ventana del embedder.

4. BM25 con stemming español y portugués

bm25s implementa BM25 con matrices dispersas en numpy y trae listas de stopwords para "es" y "pt"; el stemming lo pone PyStemmer (Snowball). Sin stemming, "licitación" y "licitaciones" no calzan; sin stopwords, "de", "la" y "que" dominan los scores de consultas cortas.

python
# 01_bm25.py — índice BM25 y runs top-100 por país
import json

import bm25s
import pandas as pd
import Stemmer

LANG = "es"                                     # "pt" para Quati
CORPUS = f"corpus_{LANG}.parquet"
EVALS = ["cl", "mx", "ar"] if LANG == "es" else ["pt"]
K = 100

stemmer = Stemmer.Stemmer("spanish" if LANG == "es" else "portuguese")
df = pd.read_parquet(CORPUS)
docids = df["docid"].tolist()
texts = (df["title"] + ". " + df["text"]).str.lstrip(". ").tolist()   # título como contexto

corpus_tokens = bm25s.tokenize(texts, stopwords=LANG, stemmer=stemmer)
retriever = bm25s.BM25()                        # método "lucene", k1=1.5, b=0.75
retriever.index(corpus_tokens)
retriever.save(f"bm25_{LANG}")

for name in EVALS:
    with open(f"eval_{name}.json", encoding="utf-8") as f:
        ev = json.load(f)
    qids = list(ev["queries"])
    q_tokens = bm25s.tokenize([ev["queries"][q] for q in qids], stopwords=LANG,
                              stemmer=stemmer, return_ids=False)
    idx, scores = retriever.retrieve(q_tokens, k=K)
    run = {qid: {docids[i]: float(s) for i, s in zip(idx[r], scores[r])}
           for r, qid in enumerate(qids)}
    with open(f"run_bm25_{name}.json", "w") as f:
        json.dump(run, f)
    print(name, "listo")
Identificadores latinoamericanos: el tokenizer por defecto de bm25s (\b\w\w+\b) parte "12.345.678-5" en "12", "345", "678" y descarta el dígito verificador, así que un RUT, CUIT o CPF deja de ser buscable como unidad. Normaliza antes de indexar y en la consulta, con la misma función, por ejemplo re.sub(r"(\d{1,3})\.(\d{3})\.(\d{3})-([\dkK])", r"\1\2\3\4", texto) para RUT, y algo equivalente para CPF (000.000.000-00) y CUIT (20-12345678-3).

5. Retrieval denso con embeddings multilingües

# 02_dense.py — embeddings del corpus, índice FAISS y runs top-100
import json

import faiss
import numpy as np
import pandas as pd
import torch
from sentence_transformers import SentenceTransformer

LANG = "es"
EVALS = ["cl", "mx", "ar"] if LANG == "es" else ["pt"]
MODEL = "Qwen/Qwen3-Embedding-0.6B"
K = 100

model = SentenceTransformer(
    MODEL,
    model_kwargs={"dtype": torch.bfloat16, "attn_implementation": "flash_attention_2"},  # sin flash-attn: borra attn_implementation
    tokenizer_kwargs={"padding_side": "left"},
)
model.max_seq_length = 512                      # pasajes de Wikipedia: sobra

df = pd.read_parquet(f"corpus_{LANG}.parquet")
docids = df["docid"].tolist()
texts = (df["title"] + ". " + df["text"]).str.lstrip(". ").tolist()

# encode_document / encode_query aplican los prompts definidos por el modelo
doc_emb = model.encode_document(texts, batch_size=128, normalize_embeddings=True,
                                convert_to_numpy=True, show_progress_bar=True).astype(np.float32)
np.save(f"emb_{LANG}.npy", doc_emb)

index = faiss.IndexFlatIP(doc_emb.shape[1])    # exacto; para millones: faiss.IndexHNSWFlat(d, 32, faiss.METRIC_INNER_PRODUCT)
index.add(doc_emb)
faiss.write_index(index, f"faiss_{LANG}.index")

for name in EVALS:
    with open(f"eval_{name}.json", encoding="utf-8") as f:
        ev = json.load(f)
    qids = list(ev["queries"])
    q_emb = model.encode_query([ev["queries"][q] for q in qids], batch_size=64,
                               normalize_embeddings=True, convert_to_numpy=True).astype(np.float32)
    scores, idx = index.search(q_emb, K)
    run = {qid: {docids[i]: float(s) for i, s in zip(idx[r], scores[r]) if i != -1}
           for r, qid in enumerate(qids)}
    with open(f"run_dense_{name}.json", "w") as f:
        json.dump(run, f)
Prompts de consulta: encode_query usa el prompt llamado "query" si el modelo lo define (Qwen3-Embedding sí). harrier-oss-v1 los nombra por tarea, así que con él usa model.encode(consultas, prompt_name="web_search_query"); si no, las consultas se codifican sin instrucción y el recall cae sin ningún error visible. Lo mismo al servir el embedder con vllm serve Qwen/Qwen3-Embedding-0.6B --runner pooling: el endpoint /v1/embeddings no agrega la instrucción, debes anteponerla tú.
Memoria del índice: 500k vectores de 1024 dimensiones en float32 son ~2 GB; los 14M de eswiki completos, ~57 GB. Con sentence_transformers.quantization.quantize_embeddings puedes pasar a int8 (4x menos) o binario (32x menos, con faiss.IndexBinaryFlat) y reordenar el top-k con los vectores float. No mezcles embeddings int8 generados con versiones de sentence-transformers anteriores a 5.7: cambió la cuantización.

6. Fusión RRF y reranking

Reciprocal Rank Fusion suma 1 / (k + rank) de cada documento en cada ranking, con k = 60. Solo usa posiciones, así que no importa que BM25 devuelva scores de 0 a 30 y el coseno de 0 a 1. Después, un cross-encoder lee consulta y pasaje juntos y reordena el top-50: es la etapa más cara por par pero la que más mueve nDCG@10.

python
# 03_fusion_rerank.py — RRF de BM25 + denso y rerank del top-50
import json
from collections import defaultdict

import pandas as pd
import torch
from sentence_transformers import CrossEncoder

LANG = "es"
EVALS = ["cl", "mx", "ar"] if LANG == "es" else ["pt"]
TOP_RERANK = 50


def rrf(runs, k=60, top=100):
    fused = defaultdict(lambda: defaultdict(float))
    for run in runs:
        for qid, docs in run.items():
            ranked = sorted(docs.items(), key=lambda x: x[1], reverse=True)
            for rank, (doc, _) in enumerate(ranked, start=1):
                fused[qid][doc] += 1.0 / (k + rank)
    return {qid: dict(sorted(d.items(), key=lambda x: x[1], reverse=True)[:top])
            for qid, d in fused.items()}


df = pd.read_parquet(f"corpus_{LANG}.parquet")
text_of = dict(zip(df["docid"], (df["title"] + ". " + df["text"]).str.lstrip(". ")))

# El prompt por defecto del reranker es de búsqueda web: calza con consultas tipo Google
reranker = CrossEncoder("Qwen/Qwen3-Reranker-0.6B", model_kwargs={"dtype": torch.bfloat16})

for name in EVALS:
    with open(f"eval_{name}.json", encoding="utf-8") as f:
        queries = json.load(f)["queries"]
    runs = []
    for system in ("bm25", "dense"):
        with open(f"run_{system}_{name}.json") as f:
            runs.append(json.load(f))
    hybrid = rrf(runs)
    with open(f"run_hybrid_{name}.json", "w") as f:
        json.dump(hybrid, f)

    pairs, owners = [], []
    for qid, docs in hybrid.items():
        for d in list(docs)[:TOP_RERANK]:
            pairs.append((queries[qid], text_of[d]))
            owners.append((qid, d))
    scores = reranker.predict(pairs, batch_size=32, show_progress_bar=True)

    reranked = defaultdict(dict)
    for (qid, d), s in zip(owners, scores):
        reranked[qid][d] = float(s)
    for qid, docs in hybrid.items():       # posiciones 51-100: debajo de todo lo reordenado
        floor = min(reranked[qid].values()) - 1.0
        for pos, d in enumerate(list(docs)[TOP_RERANK:]):
            reranked[qid][d] = floor - pos
    with open(f"run_rerank_{name}.json", "w") as f:
        json.dump(reranked, f)
Instrucción del reranker: Qwen3-Reranker acepta instrucciones propias (CrossEncoder(..., prompts={"legal": "Given a legal question, retrieve the article that answers it"}, default_prompt_name="legal")). Igual que en el embedder, el modelo card recomienda escribirlas en inglés aunque consultas y documentos estén en español o portugués.

7. Evaluar el retrieval por país

Con qrels y runs en disco, ranx calcula las métricas y compara sistemas con tests de significancia pareados. Tres métricas alcanzan: Recall@100 (¿el pasaje correcto llegó al reranker?), nDCG@10 (¿quedó arriba?) y MRR@10 (¿en qué posición quedó el primero?).

python
# 04_eval_retrieval.py — tabla BM25 vs denso vs híbrido vs híbrido+rerank por país
import json

from ranx import Qrels, Run, compare

SYSTEMS = ["bm25", "dense", "hybrid", "rerank"]

for name in ["cl", "mx", "ar", "pt"]:      # quita "pt" si no corriste Quati
    with open(f"eval_{name}.json", encoding="utf-8") as f:
        qrels = Qrels(json.load(f)["qrels"])
    runs = []
    for system in SYSTEMS:
        with open(f"run_{system}_{name}.json") as f:
            runs.append(Run(json.load(f), name=system))
    report = compare(
        qrels=qrels,
        runs=runs,
        metrics=["ndcg@10", "recall@100", "mrr@10"],
        max_p=0.01,              # t-test pareado; marca diferencias con p < 0.01
        make_comparable=True,    # consultas sin resultados cuentan como 0
    )
    print(f"\n=== {name} ===")
    print(report)

BM25 gana al denso en un paísConsultas con entidades locales o jergaSubir el peso de BM25 (RRF ponderado) o fine-tunear el embedder
Un país rinde mucho peorVariación dialectal o temas locales mal cubiertosRevisar 30 fallas a mano antes de cambiar modelos
Significancia por país: los subsets por país de MessIRve tienen entre ~4k y ~8k consultas de test, pero Quati solo 50 topics: ahí una diferencia de varios puntos de nDCG puede ser ruido. Reporta siempre la marca de significancia de compare y, si comparas muchos sistemas, corrige por comparaciones múltiples.

8. Opcional: late interaction con mLateOn

Un embedding de un solo vector tiene límites teóricos: LIMIT mostró que su dimensión acota cuántas combinaciones de documentos top-k puede representar. Los modelos late interaction (ColBERT) guardan un vector por token y puntúan con MaxSim; generalizan mejor fuera de dominio y en idiomas poco vistos. lightonai/mLateOn (307M, base mmBERT, Apache-2.0) tiene español y portugués entre sus idiomas de entrenamiento y sentence-transformers v6 lo carga con MultiVectorEncoder. La forma más barata de probarlo es como reranker de los candidatos del híbrido:

python
from sentence_transformers import MultiVectorEncoder

mv = MultiVectorEncoder("lightonai/mLateOn")

query = "¿quién escribió Cien años de soledad?"
candidates = [                                   # en el pipeline: el top-50 del híbrido
    "Cien años de soledad es una novela de Gabriel García Márquez publicada en 1967.",
    "Gabriel García Márquez nació en Aracataca, Colombia, en 1927.",
    "Cem anos de solidão é um romance do escritor colombiano Gabriel García Márquez.",
]
q_emb = mv.encode_query(query)                  # un vector de 128 dims por token
d_emb = mv.encode_document(candidates)
scores = mv.similarity(q_emb, d_emb)[0]          # MaxSim: mayor = más relevante
for score, doc in sorted(zip(scores.tolist(), candidates), reverse=True):
    print(f"{score:.3f}  {doc}")

Para usarlo como retriever de primera etapa sobre todo el corpus, PyLate (models.ColBERT + índice indexes.PLAID + retrieve.ColBERT) indexa los vectores por token; el índice ocupa bastante más que el denso, así que mídelo primero en el sub-corpus y compáralo con la misma tabla ranx.

9. Generación con citas y abstención

El generador recibe los 5 mejores pasajes numerados y tiene tres obligaciones: responder en el idioma de la pregunta, citar [n] cada afirmación y abstenerse con una frase fija cuando el contexto no alcanza. Sufficient Context mostró que los modelos grandes tienden a responder mal en lugar de abstenerse cuando el contexto es insuficiente, así que la abstención se pide explícitamente y se mide.

bash
# Qwen3.5 es image-text-to-text: --language-model-only carga solo la parte de texto
vllm serve Qwen/Qwen3.5-9B \
    --port 8000 \
    --max-model-len 32768 \
    --reasoning-parser qwen3 \
    --language-model-only
# 24 GB: cambia a Qwen/Qwen3.5-4B. Con tu modelo LatamGPT: vllm serve <TU_ORG>/<modelo>
python
# 06_generate.py — respuestas con citas para una muestra de consultas
import asyncio
import json
import random
import re

import pandas as pd
from openai import AsyncOpenAI

NAME, LANG = "cl", "es"                       # ("pt", "pt") para Quati
MODEL = "Qwen/Qwen3.5-9B"
TOP_K, N_SAMPLE = 5, 300

ABSTAIN = {"es": "No encontré información suficiente en los documentos.",
           "pt": "Não encontrei informações suficientes nos documentos."}
SYSTEM = {
    "es": ("Eres un asistente que responde en español usando SOLO los documentos entregados.\n"
           "- Cita cada afirmación con el número del documento entre corchetes, por ejemplo [2].\n"
           "- Si los documentos no bastan para responder, responde exactamente: \"{abstain}\"\n"
           "- No uses conocimiento propio ni cites documentos que no usaste."),
    "pt": ("Você é um assistente que responde em português usando APENAS os documentos fornecidos.\n"
           "- Cite cada afirmação com o número do documento entre colchetes, por exemplo [2].\n"
           "- Se os documentos não forem suficientes, responda exatamente: \"{abstain}\"\n"
           "- Não use conhecimento próprio nem cite documentos que não usou."),
}

client = AsyncOpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
df = pd.read_parquet(f"corpus_{LANG}.parquet")
text_of = dict(zip(df["docid"], (df["title"] + ". " + df["text"]).str.lstrip(". ")))
with open(f"eval_{NAME}.json", encoding="utf-8") as f:
    ev = json.load(f)
with open(f"run_rerank_{NAME}.json") as f:
    run = json.load(f)


async def answer(qid, sem):
    top = sorted(run[qid], key=run[qid].get, reverse=True)[:TOP_K]
    contexts = [text_of[d] for d in top]
    docs = "\n\n".join(f"[{i}] {c}" for i, c in enumerate(contexts, start=1))
    messages = [
        {"role": "system", "content": SYSTEM[LANG].format(abstain=ABSTAIN[LANG])},
        {"role": "user", "content": f"Documentos:\n{docs}\n\nPregunta: {ev['queries'][qid]}"},
    ]
    async with sem:
        r = await client.chat.completions.create(
            model=MODEL, messages=messages, max_tokens=512,
            temperature=0.7, top_p=0.8, presence_penalty=1.5,   # recomendados sin thinking
            extra_body={"top_k": 20, "chat_template_kwargs": {"enable_thinking": False}},
        )
    gold = list(ev["qrels"][qid])
    return {"qid": qid, "question": ev["queries"][qid], "contexts": contexts,
            "context_ids": top, "response": r.choices[0].message.content.strip(),
            "gold_in_context": any(g in top for g in gold),
            "reference": text_of.get(gold[0], "")}


async def main():
    sem = asyncio.Semaphore(32)
    qids = random.Random(0).sample(list(ev["queries"]), min(N_SAMPLE, len(ev["queries"])))
    rows = await asyncio.gather(*(answer(q, sem) for q in qids))
    for row in rows:
        cited = {int(n) for n in re.findall(r"\[(\d+)\]", row["response"])}
        row["abstained"] = ABSTAIN[LANG].rstrip(".") in row["response"]
        row["invalid_citation"] = any(n < 1 or n > TOP_K for n in cited)
        row["uncited"] = not cited and not row["abstained"]
    with open(f"gen_{NAME}.jsonl", "w", encoding="utf-8") as f:
        for row in rows:
            f.write(json.dumps(row, ensure_ascii=False) + "\n")


asyncio.run(main())

Antes de cualquier juez, cruza abstención con gold_in_context en una tabla 2x2 (pandas crosstab): si el pasaje correcto no llegó al top-5 y el modelo igual respondió sin abstenerse, esas respuestas son candidatas a alucinación; si llegó y se abstuvo, el modelo es demasiado conservador o el prompt de abstención está mal calibrado. Las columnas invalid_citation y uncited se cuentan sin LLM y detectan regresiones de formato al cambiar de modelo.

Orden de los pasajes: los LLM atienden peor el medio de contextos largos (Lost in the Middle). Con 5 pasajes cortos no es crítico, pero si subes a 20 pon los mejor rankeados al principio. Y trata el contenido recuperado como no confiable: un documento puede traer instrucciones inyectadas (ver guardrails en producción).

10. Evaluar la generación con RAGAS 0.4

RAGAS 0.4 trae las métricas en ragas.metrics.collections y acepta cualquier endpoint compatible con OpenAI como juez. Usamos tres: Faithfulness (¿cada afirmación de la respuesta está respaldada por los contextos?), ContextRecall (¿los contextos cubren la referencia? aquí la referencia es el pasaje gold de MessIRve) y ContextUtilization (¿los contextos útiles quedaron arriba?, sin referencia). El juez debe ser un modelo distinto del generador, idealmente de otra familia, para no premiar sus propios sesgos.

bash
# Juez en otro puerto (otra GPU o máquina). Elige un modelo de otra familia que el generador.
vllm serve <TU_ORG>/<modelo-juez> --port 8001 --max-model-len 32768
python
# 07_eval_generation.py — métricas RAGAS por respuesta (lee gen_cl.jsonl de la sección 9)
import asyncio
import json

import instructor
import pandas as pd
from openai import AsyncOpenAI
from ragas.llms import llm_factory
from ragas.metrics.collections import ContextRecall, ContextUtilization, Faithfulness

JUDGE_MODEL = "<TU_ORG>/<modelo-juez>"    # el mismo nombre que sirve vLLM en :8001
NAME = "cl"

judge_client = AsyncOpenAI(base_url="http://localhost:8001/v1", api_key="EMPTY")
# Mode.JSON (el default) usa response_format JSON: no exige tool calling en el servidor;
# si tu backend no soporta response_format, usa instructor.Mode.MD_JSON
llm = llm_factory(JUDGE_MODEL, client=judge_client, mode=instructor.Mode.JSON)

faithfulness = Faithfulness(llm=llm)
context_recall = ContextRecall(llm=llm)
context_util = ContextUtilization(llm=llm)

with open(f"gen_{NAME}.jsonl", encoding="utf-8") as f:
    rows = [json.loads(line) for line in f]


async def score(row, sem):
    async with sem:
        out = {"qid": row["qid"], "abstained": row["abstained"],
               "gold_in_context": row["gold_in_context"]}
        if not row["abstained"]:            # una abstención no tiene afirmaciones que verificar
            r = await faithfulness.ascore(user_input=row["question"], response=row["response"],
                                          retrieved_contexts=row["contexts"])
            out["faithfulness"] = r.value
        r = await context_recall.ascore(user_input=row["question"], retrieved_contexts=row["contexts"],
                                        reference=row["reference"])
        out["context_recall"] = r.value
        r = await context_util.ascore(user_input=row["question"], response=row["response"],
                                      retrieved_contexts=row["contexts"])
        out["context_utilization"] = r.value
        return out


async def main():
    sem = asyncio.Semaphore(16)
    results = await asyncio.gather(*(score(r, sem) for r in rows))
    df = pd.DataFrame(results)
    df.to_csv(f"ragas_{NAME}.csv", index=False)
    print(df[["faithfulness", "context_recall", "context_utilization"]].describe())
    print(df.groupby("gold_in_context")["abstained"].mean())


asyncio.run(main())
Valida el juez en español antes de creerle: los prompts internos de RAGAS están en inglés y el juez extrae y verifica afirmaciones en español o portugués; un juez débil en el idioma infla o castiga faithfulness sin que se note. MEMERAG publica juicios expertos nativos de faithfulness y relevancia en español (entre otros idiomas) justamente para medir esto: calcula el acuerdo de tu juez con esas etiquetas, o con 100 respuestas tuyas anotadas a mano, antes de usarlo para elegir modelos. Más detalle en LLM-as-a-judge calibrado y evaluación Latam.

AnswerRelevancy también existe en la colección, pero genera preguntas a partir de la respuesta y las compara con embeddings (AnswerRelevancy(llm=llm, embeddings=...)); si el juez genera esas preguntas en inglés, la similitud con la pregunta original en español baja artificialmente. Si la usas, revisa en qué idioma salen las preguntas generadas.

11. Llevarlo a producción con Qdrant

En producción no quieres dos índices y un RRF en Python: Qdrant guarda vector denso y vector disperso BM25 en el mismo punto y hace la fusión en el servidor con prefetch + RrfQuery. El BM25 disperso lo calcula fastembed con stemmer y stopwords en español; el IDF lo aplica Qdrant (Modifier.IDF), así que el índice se actualiza incrementalmente sin recalcular nada.

python
# 08_qdrant_hybrid.py — requiere: docker run -p 6333:6333 qdrant/qdrant
import pandas as pd
from fastembed import SparseTextEmbedding
from qdrant_client import QdrantClient, models
from sentence_transformers import SentenceTransformer

COLLECTION = "docs_es"
client = QdrantClient(url="http://localhost:6333")
dense = SentenceTransformer("Qwen/Qwen3-Embedding-0.6B", model_kwargs={"dtype": "auto"})
bm25 = SparseTextEmbedding("Qdrant/bm25", language="spanish")   # "portuguese" para pt

if not client.collection_exists(COLLECTION):
    client.create_collection(
        COLLECTION,
        vectors_config={"dense": models.VectorParams(size=1024, distance=models.Distance.COSINE)},
        sparse_vectors_config={"bm25": models.SparseVectorParams(modifier=models.Modifier.IDF)},
    )


def upsert(df, batch=256):
    """df con columnas docid, title, text. Reindexar un documento = upsert con el mismo id."""
    for start in range(0, len(df), batch):
        part = df.iloc[start:start + batch]
        texts = (part["title"] + ". " + part["text"]).str.lstrip(". ").tolist()
        d_vecs = dense.encode_document(texts, normalize_embeddings=True)
        s_vecs = list(bm25.embed(texts))
        points = [
            models.PointStruct(
                id=int(i),
                vector={"dense": d.tolist(),
                        "bm25": models.SparseVector(indices=s.indices.tolist(), values=s.values.tolist())},
                payload={"docid": docid, "text": t},
            )
            for i, docid, t, d, s in zip(part.index, part["docid"], texts, d_vecs, s_vecs)
        ]
        client.upsert(COLLECTION, points=points)


def search(query, limit=50):
    q_dense = dense.encode_query(query, normalize_embeddings=True).tolist()
    q_sparse = next(iter(bm25.query_embed(query)))
    res = client.query_points(
        COLLECTION,
        prefetch=[
            models.Prefetch(query=q_dense, using="dense", limit=100),
            models.Prefetch(query=models.SparseVector(indices=q_sparse.indices.tolist(),
                                                      values=q_sparse.values.tolist()),
                            using="bm25", limit=100),
        ],
        query=models.RrfQuery(rrf=models.Rrf(k=60)),   # weights=[...] para RRF ponderado
        limit=limit,
        with_payload=True,
    )
    return [(p.payload["docid"], p.score, p.payload["text"]) for p in res.points]


upsert(pd.read_parquet("corpus_es.parquet").head(10_000))
for docid, s, text in search("¿cuánto dura el permiso postnatal en Chile?")[:5]:
    print(f"{s:.4f} {docid} {text[:100]}")
