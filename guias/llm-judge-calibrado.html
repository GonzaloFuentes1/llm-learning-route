LLM-as-a-judge calibrado: rúbricas, validación humana y corrección estadística

Un juez LLM no es un oráculo: tiene sensibilidad y especificidad imperfectas, y eso sesga el puntaje que reportas. Esta guía arma el pipeline completo sobre Trueque (preguntas de conocimiento latinoamericano en español y portugués): rúbrica en español, juez abierto servido con vLLM, anotación humana doble, sondas de sesgo, corrección de Lee et al. (2025) e intervalos con PPI.

1. Cuándo usar un juez (y cuándo no)

Un juez LLM se justifica cuando la respuesta es abierta y no hay un verificador exacto: preguntas factuales con respuesta de referencia redactada (Trueque, CHOCLO), comparación de dos respuestas largas (m-ArenaHard v2.0 en es/pt) o rúbricas de estilo y adecuación cultural. Si la tarea tiene opción múltiple, una respuesta numérica o tests ejecutables, usa el verificador determinista: el juez solo agrega ruido y costo.

El problema central lo formalizan Lee et al. (2025): si el juez marca como correctas respuestas que no lo son (baja especificidad) o rechaza respuestas correctas (baja sensibilidad), la proporción de "correctas" según el juez es un estimador sesgado de la accuracy real, y además el reporte habitual no incluye la incertidumbre de haber medido al juez. La ficha de Trueque declara que su reporte se está ajustando siguiendo ese paper (con Qwen2.5-72B-Instruct como juez base): esta guía implementa ese ajuste de punta a punta.

2. Diseño del juez: anclado a la referencia y con tres clases

Tres decisiones bajan más el error del juez que cambiar de modelo: (1) anclarlo a la referencia (el juez compara, no "sabe"); (2) usar una rúbrica categórica con definiciones operativas en vez de una escala 1-10; y (3) separar la abstención ("no lo sé") de la alucinación (respuesta segura pero falsa). Para usos de alto riesgo, un modelo que se abstiene es mucho menos dañino que uno que inventa, y un puntaje binario los mezcla.

ClaseDefinición operativaEjemplo (pregunta: "¿Qué es la corpachada en Argentina?")
CORRECTAContiene el dato central de la referencia y no agrega hechos falsos relevantes"Ceremonia andina del 1 de agosto de ofrenda a la Pachamama en el noroeste argentino"
INCORRECTAContradice la referencia, omite el dato central o inventa hechos"Es un plato típico de Mendoza a base de maíz"
NO_RESPONDEDeclara no saber, se niega o pide contexto sin aportar un dato verificable"No tengo información suficiente sobre esa celebración"

La rúbrica va en español aunque haya preguntas en portugués (Trueque trae las de Brasil en portugués): así puedes medir después si el juez es más severo con un idioma (sección 5). Guarda este archivo como judge.py; otros scripts importan la rúbrica desde aquí.

python · judge.py
"""judge.py: juzga candidatas.jsonl con un juez servido por vLLM (API compatible con OpenAI)."""
import asyncio
import json
from typing import Literal

from openai import AsyncOpenAI
from pydantic import BaseModel

CLASES = ["CORRECTA", "INCORRECTA", "NO_RESPONDE"]

RUBRICA_ES = """Eres un evaluador estricto de conocimiento factual y cultural sobre América Latina.
Compara la RESPUESTA CANDIDATA con la RESPUESTA DE REFERENCIA, que fue verificada con fuentes.

Criterios:
- CORRECTA: contiene el dato central de la referencia y no agrega afirmaciones falsas relevantes.
  No penalices el estilo, la extensión ni detalles adicionales que sean correctos.
- INCORRECTA: contradice la referencia, omite el dato central o agrega hechos falsos,
  aunque suene plausible o esté bien redactada.
- NO_RESPONDE: el modelo declara no saber, se niega o pide más contexto sin dar un dato verificable.

La pregunta puede estar en español o en portugués: evalúa el contenido, no el idioma.
Escribe una justificación de máximo dos oraciones y después el veredicto.

PAÍS: {pais}
PREGUNTA: {pregunta}
RESPUESTA DE REFERENCIA: {referencia}
RESPUESTA CANDIDATA: {candidata}"""


class Veredicto(BaseModel):
    justificacion: str  # va primero: el juez "razona" antes de decidir
    veredicto: Literal["CORRECTA", "INCORRECTA", "NO_RESPONDE"]


FORMATO = {
    "type": "json_schema",
    "json_schema": {"name": "veredicto", "schema": Veredicto.model_json_schema()},
}


def prompt_juez(item: dict, plantilla: str = RUBRICA_ES) -> str:
    return plantilla.format(
        pais=item["country"], pregunta=item["question"],
        referencia=item["reference_answer"], candidata=item["respuesta"],
    )


async def juzgar(client: AsyncOpenAI, sem: asyncio.Semaphore, item: dict) -> dict:
    async with sem:
        r = await client.chat.completions.create(
            model="juez",                       # --served-model-name del servidor
            messages=[{"role": "user", "content": prompt_juez(item)}],
            temperature=0.0,
            max_tokens=400,
            response_format=FORMATO,            # salida estructurada de vLLM
        )
    v = Veredicto.model_validate_json(r.choices[0].message.content)
    return {**item, "juez": v.veredicto, "juez_justificacion": v.justificacion}


async def main(entrada: str = "candidatas.jsonl", salida: str = "veredictos.jsonl") -> None:
    client = AsyncOpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
    sem = asyncio.Semaphore(64)                 # vLLM hace el batching continuo
    with open(entrada, encoding="utf-8") as f:
        items = [json.loads(linea) for linea in f]
    resultados = await asyncio.gather(*(juzgar(client, sem, x) for x in items))
    with open(salida, "w", encoding="utf-8") as f:
        for r in resultados:
            f.write(json.dumps(r, ensure_ascii=False) + "\n")
    conteo = {c: sum(r["juez"] == c for r in resultados) for c in CLASES}
    print("Veredictos del juez:", conteo)


if __name__ == "__main__":
    asyncio.run(main())
Salida más barata: si no necesitas la justificación, cambia response_format por extra_body={"structured_outputs": {"choice": CLASES}}: el juez solo puede emitir una de las tres etiquetas. Los parámetros viejos guided_json/guided_choice fueron eliminados en vLLM v0.12; hoy todo pasa por structured_outputs o response_format.

"""generate_candidates.py: respuestas del modelo evaluado a las 500 preguntas de Trueque."""
import json
import os

os.environ.setdefault("CUDA_VISIBLE_DEVICES", "2")   # GPU libre (el juez usa 0-1)

from datasets import load_dataset
from vllm import LLM, SamplingParams

MODELO = "Qwen/Qwen2.5-7B-Instruct"
SISTEMA = {
    "es": "Responde en español, en dos o tres oraciones y con precisión. "
          "Si no conoces la respuesta, di explícitamente que no lo sabes.",
    "pt": "Responda em português, em duas ou três frases e com precisão. "
          "Se não souber a resposta, diga explicitamente que não sabe.",
}

ds = load_dataset("latam-gpt/Trueque-Benchmark-beta-0.1", split="train")
ds = ds.map(
    lambda x, i: {
        "id": i,
        "country": (x["country"] or "Latam").strip().title(),
        "lang": "pt" if (x["country"] or "").strip().title() == "Brasil" else "es",
    },
    with_indices=True,
)

llm = LLM(model=MODELO, dtype="bfloat16", max_model_len=4096)
params = SamplingParams(temperature=0.0, max_tokens=384)
conversaciones = [
    [{"role": "system", "content": SISTEMA[x["lang"]]},
     {"role": "user", "content": x["question"]}]
    for x in ds
]
salidas = llm.chat(conversaciones, params)

with open("candidatas.jsonl", "w", encoding="utf-8") as f:
    for x, out in zip(ds, salidas):
        x = dict(x, respuesta=out.outputs[0].text.strip())
        f.write(json.dumps(x, ensure_ascii=False) + "\n")
print("Listo:", len(ds), "respuestas en candidatas.jsonl")

4. Set de calibración humana: muestreo, anotación doble y acuerdo

La calibración responde una pregunta concreta: ¿con qué frecuencia el juez coincide con un humano en este benchmark, con este modelo evaluado? Cuatro reglas: muestra estratificada por país (la validez cultural cambia entre países y un juez puede ser bueno en México y malo en Bolivia); anotadores ciegos al veredicto del juez; dos anotadores independientes con la misma rúbrica; y adjudicación de los desacuerdos por una tercera persona. Con 500 ítems, 150-200 anotados es un buen equilibrio.

python · calibration_sample.py
"""calibration_sample.py: muestra estratificada por país para anotación humana doble y ciega."""
import pandas as pd

N_CAL = 180
MIN_POR_PAIS = 3
SEMILLA = 13

df = pd.read_json("veredictos.jsonl", lines=True)
cuota = (df["country"].value_counts(normalize=True) * N_CAL).round().clip(lower=MIN_POR_PAIS).astype(int)

partes = []
for pais, grupo in df.groupby("country"):
    partes.append(grupo.sample(n=min(len(grupo), int(cuota[pais])), random_state=SEMILLA))
cal = pd.concat(partes)

# Peso = proporción del país en los ítems NO anotados / proporción en la muestra anotada.
# Solo lo necesita PPI (sección 7), que estima la media sobre los no anotados;
# la corrección de Lee et al. no depende de cómo muestreaste.
p_resto = df.loc[~df["id"].isin(cal["id"]), "country"].value_counts(normalize=True)
p_cal = cal["country"].value_counts(normalize=True)
cal["peso"] = cal["country"].map(p_resto / p_cal).fillna(0.0)

cal.to_csv("calibracion_con_juez.csv", index=False)       # uso interno
ciego = cal[["id", "country", "lang", "question", "reference_answer", "respuesta"]]
ciego = ciego.sample(frac=1, random_state=SEMILLA)          # orden aleatorio
for anotador in ["A", "B"]:
    ciego.assign(etiqueta="").to_csv(f"anotar_{anotador}.csv", index=False)
print(len(cal), "ítems a anotar;", cal["country"].nunique(), "países")

Cada anotador llena etiqueta con una de las tres clases. Después se juntan en anotado.csv con columnas id, etiqueta_A, etiqueta_B y etiqueta_final (adjudicada). Antes de mirar al juez, mide el acuerdo entre humanos: es el techo de lo que puedes exigirle.

python · agreement.py
"""agreement.py: acuerdo humano-humano y juez-humano."""
import krippendorff
import numpy as np
import pandas as pd
from sklearn.metrics import cohen_kappa_score, confusion_matrix

CLASES = ["CORRECTA", "INCORRECTA", "NO_RESPONDE"]
COD = {c: i for i, c in enumerate(CLASES)}

an = pd.read_csv("anotado.csv")
cal = pd.read_csv("calibracion_con_juez.csv").merge(an, on="id")

# 1) Acuerdo entre humanos
kappa_hh = cohen_kappa_score(cal["etiqueta_A"], cal["etiqueta_B"])
datos = np.array([cal["etiqueta_A"].map(COD), cal["etiqueta_B"].map(COD)], dtype=float)  # anotadores x ítems
alpha_hh = krippendorff.alpha(reliability_data=datos, level_of_measurement="nominal")
print(f"Humano-humano: kappa={kappa_hh:.3f}  alpha={alpha_hh:.3f}")

# 2) Juez vs etiqueta adjudicada
kappa_jh = cohen_kappa_score(cal["etiqueta_final"], cal["juez"])
cm = confusion_matrix(cal["etiqueta_final"], cal["juez"], labels=CLASES)
print(f"Juez-humano:   kappa={kappa_jh:.3f}")
print(pd.DataFrame(cm, index=[f"humano={c}" for c in CLASES], columns=[f"juez={c}" for c in CLASES]))

# 3) Sensibilidad y especificidad para la clase positiva CORRECTA
humano_ok = cal["etiqueta_final"].eq("CORRECTA").to_numpy()
juez_ok = cal["juez"].eq("CORRECTA").to_numpy()
sens = (juez_ok & humano_ok).sum() / humano_ok.sum()
esp = (~juez_ok & ~humano_ok).sum() / (~humano_ok).sum()
print(f"Sensibilidad={sens:.3f}  Especificidad={esp:.3f}  (m1={humano_ok.sum()}, m0={(~humano_ok).sum()})")

# 4) Desglose por idioma: ¿el juez es más indulgente en portugués?
for lang, g in cal.groupby("lang"):
    print(lang, "kappa juez-humano =", round(cohen_kappa_score(g["etiqueta_final"], g["juez"]), 3), "n =", len(g))
Lee la matriz, no solo el kappa: el error más caro en Trueque es humano=INCORRECTA → juez=CORRECTA (el juez se deja convencer por una alucinación fluida). Eso es baja especificidad e infla la accuracy. Thakur et al. (2024) muestran que el porcentaje de acuerdo esconde estas diferencias y que kappa discrimina mejor entre jueces.

5. Sondas de sesgo: posición, longitud e idioma

La calibración mide el error promedio; las sondas buscan errores sistemáticos que pueden cambiar entre modelos evaluados. Los sesgos más documentados (Zheng et al. 2023; Ye et al. 2024) son posición en comparaciones pareadas, preferencia por respuestas largas, auto-preferencia (el juez favorece a su propia familia de modelos) y, para nosotros, idioma: MM-Eval muestra que los jueces rinden peor fuera del inglés y en idiomas de menos recursos.

python · bias_probes.py (requiere judge.py en el mismo directorio)
"""bias_probes.py: sondas de longitud, idioma y posición contra el juez servido en :8000."""
import pandas as pd
from openai import OpenAI

from judge import CLASES, prompt_juez

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")


def preguntar(prompt: str, opciones: list[str] | None = None, max_tokens: int = 8) -> str:
    extra = {"structured_outputs": {"choice": opciones}} if opciones else {}
    r = client.chat.completions.create(
        model="juez", messages=[{"role": "user", "content": prompt}],
        temperature=0.0, max_tokens=max_tokens, extra_body=extra,
    )
    return r.choices[0].message.content.strip()


cal = pd.read_csv("calibracion_con_juez.csv").merge(pd.read_csv("anotado.csv"), on="id")
incorrectas = cal[cal["etiqueta_final"] == "INCORRECTA"].to_dict("records")

# 1) Longitud: agregar relleno sin información nueva a respuestas incorrectas
RELLENO = (" Cabe destacar que este tema tiene una gran relevancia histórica y cultural para la región, "
           "y ha sido objeto de numerosos estudios y debates a lo largo de los años.")
flips = sum(preguntar(prompt_juez({**x, "respuesta": x["respuesta"] + RELLENO}), CLASES) == "CORRECTA"
            for x in incorrectas)
print(f"Sesgo de longitud: {flips}/{len(incorrectas)} incorrectas pasan a CORRECTA con relleno")

# 2) Idioma: la misma respuesta traducida al portugués debería recibir el mismo veredicto
es_items = cal[cal["lang"] == "es"].head(60).to_dict("records")
cambios = 0
for x in es_items:
    trad = preguntar("Traduce al portugués de Brasil, sin agregar ni quitar información:\n\n" + x["respuesta"],
                     max_tokens=512)
    v_es = preguntar(prompt_juez(x), CLASES)
    v_pt = preguntar(prompt_juez({**x, "respuesta": trad}), CLASES)
    cambios += v_es != v_pt
print(f"Sesgo de idioma: {cambios}/{len(es_items)} veredictos cambian al pasar la respuesta a portugués")

# 3) Posición (juez pareado): consistencia al intercambiar A y B
PAREADO = """¿Cuál respuesta responde mejor la pregunta, con precisión factual? Responde A, B o EMPATE.
PREGUNTA: {q}
RESPUESTA A: {a}
RESPUESTA B: {b}"""


def consistencia_posicion(pares: list[tuple[str, str, str]]) -> float:
    """pares = [(pregunta, respuesta_modelo_1, respuesta_modelo_2), ...]"""
    espejo = {"A": "B", "B": "A", "EMPATE": "EMPATE"}
    ok = 0
    for q, r1, r2 in pares:
        v1 = preguntar(PAREADO.format(q=q, a=r1, b=r2), ["A", "B", "EMPATE"])
        v2 = preguntar(PAREADO.format(q=q, a=r2, b=r1), ["A", "B", "EMPATE"])
        ok += v1 == espejo[v2]
    return ok / len(pares)

Para la sonda de posición genera respuestas de dos modelos a los prompts de CohereLabs/m-ArenaHard-v2.0 (configs es y pt, split test, columna prompt) y pásalas a consistencia_posicion. Si la consistencia baja de ~90%, reporta siempre el promedio de ambos órdenes y cuenta como empate los casos inconsistentes.

Auto-preferencia: en este ejemplo el juez (Qwen3) y el modelo evaluado (Qwen2.5) son de la misma familia. Si comparas un Qwen contra el SFT de LatamGPT con este juez, calibra por separado para cada modelo evaluado o usa un juez de otra familia. La calibración vale para el par (juez, modelo evaluado) en el que la mediste.

6. Corrección de sesgo con Lee et al. (2025)

Sea θ la accuracy real (según humanos), p la proporción de CORRECTA según el juez en el test, q₁ la sensibilidad y q₀ la especificidad del juez. Como p = θ·q₁ + (1 − θ)·(1 − q₀), despejando:

Estimador corregido: θ̂ = (p̂ + q̂₀ − 1) / (q̂₀ + q̂₁ − 1), truncado a [0, 1].
Varianza (método delta): Var(θ̂) ≈ [ p̂(1−p̂)/n + (1−θ̂)²·q̂₀(1−q̂₀)/m₀ + θ̂²·q̂₁(1−q̂₁)/m₁ ] / (q̂₀ + q̂₁ − 1)², con n ítems de test, m₀ negativos y m₁ positivos humanos en la calibración.

Es el estimador clásico de Rogan-Gladen para prevalencia con un test imperfecto, más un intervalo que suma las dos fuentes de incertidumbre: el test y la calibración. Una propiedad importante: como q₀ y q₁ están condicionados a la etiqueta verdadera, la calibración puede tener otra proporción de correctas que el test sin sesgar la corrección, siempre que la sensibilidad y la especificidad del juez no cambien entre estratos (si sobre-muestreaste países chicos y el juez es peor en ellos, q̂₀ y q̂₁ quedan sesgados: revisa el desglose por país). El código implementa la versión de Wald simple y un bootstrap estratificado como chequeo; la función confidence_interval del repo oficial agrega un suavizado tipo Agresti-Coull y un ajuste del centro del intervalo, mejor para muestras chicas.

"""correct.py: accuracy corregida por sensibilidad/especificidad del juez (Lee et al., 2025)."""
import numpy as np
import pandas as pd
from scipy.stats import norm


def corregir(p: float, q0: float, q1: float) -> float:
    return float(np.clip((p + q0 - 1) / (q0 + q1 - 1), 0.0, 1.0))


def ic_lee(juez_test: np.ndarray, juez_cal: np.ndarray, humano_cal: np.ndarray, alpha: float = 0.05):
    """juez_test: bool (juez dice CORRECTA) en el test; juez_cal/humano_cal: bool en la calibración."""
    n, p = len(juez_test), juez_test.mean()
    pos, neg = humano_cal, ~humano_cal
    m1, m0 = pos.sum(), neg.sum()
    q1 = juez_cal[pos].mean()              # sensibilidad
    q0 = (~juez_cal[neg]).mean()           # especificidad
    j = q0 + q1 - 1
    if j <= 0.3:
        print(f"Aviso: q0 + q1 - 1 = {j:.2f}; el juez discrimina poco y el IC será muy ancho")
    theta = corregir(p, q0, q1)
    var = (p * (1 - p) / n + (1 - theta) ** 2 * q0 * (1 - q0) / m0 + theta ** 2 * q1 * (1 - q1) / m1) / j ** 2
    z = norm.ppf(1 - alpha / 2)
    half = z * np.sqrt(var)
    return theta, max(0.0, theta - half), min(1.0, theta + half), {"p": p, "q0": q0, "q1": q1}


def ic_bootstrap(juez_test, juez_cal, humano_cal, b: int = 5000, seed: int = 0):
    """Bootstrap que remuestrea el test y, por separado, positivos y negativos de la calibración."""
    rng = np.random.default_rng(seed)
    pos_idx, neg_idx = np.flatnonzero(humano_cal), np.flatnonzero(~humano_cal)
    estimaciones = []
    for _ in range(b):
        p = rng.choice(juez_test, size=len(juez_test)).mean()
        q1 = juez_cal[rng.choice(pos_idx, size=len(pos_idx))].mean()
        q0 = 1 - juez_cal[rng.choice(neg_idx, size=len(neg_idx))].mean()
        if q0 + q1 - 1 > 0:
            estimaciones.append(corregir(p, q0, q1))
    return np.percentile(estimaciones, [2.5, 97.5])

    cal = pd.read_csv("calibracion_con_juez.csv").merge(pd.read_csv("anotado.csv"), on="id")

¿Dónde gastar las horas de anotación? La varianza tiene un término por la especificidad pesado por (1−θ)² y otro por la sensibilidad pesado por θ². Si el modelo evaluado acierta poco (θ bajo, típico en conocimiento local), el error en especificidad domina y conviene anotar más negativos. Lee et al. proponen una asignación adaptativa (muestra piloto y luego repartir el presupuesto) para achicar el intervalo; está implementada en el repo LLM-judge-reporting.
Independencia: el marco supone que test y calibración son muestras distintas. Con 500 ítems puedes usar todo el benchmark como test (incluidos los ítems anotados) y aceptar una dependencia pequeña, o usar como test solo los ítems no anotados. Elige una y repórtala.

7. Alternativa: prediction-powered inference (PPI)

PPI (Angelopoulos et al., 2023) ataca el mismo problema desde otro ángulo: estima la media humana con las etiquetas humanas y usa al juez sobre los ítems no anotados solo para reducir la varianza, corrigiendo con el error que el juez comete en el subconjunto anotado (el "rectificador"). PPI++ agrega un parámetro λ que decide cuánto confiar en el juez: si el juez es malo, λ → 0 y recuperas el intervalo clásico solo-humano, así que PPI++ (asintóticamente) no es peor que no usar juez. Boyeau et al. (2024) lo aplican justamente a evaluación de modelos (AutoEval).

8. Tres clases: correcta, abstención y alucinación

El caso binario se generaliza con la matriz de confusión del juez. Sea M[j, k] = P(juez = j | humano = k), estimada en la calibración (cada columna suma 1). La distribución de veredictos del juez en el test cumple p = M·θ, así que θ̂ = M⁻¹·p̂, proyectada al simplex. Con eso reportas tres números corregidos en vez de uno: accuracy, tasa de abstención y tasa de alucinación.

python · correct_3clases.py
"""correct_3clases.py: corrección multiclase por inversión de la matriz de confusión + bootstrap."""
import numpy as np
import pandas as pd

CLASES = ["CORRECTA", "INCORRECTA", "NO_RESPONDE"]
K = len(CLASES)


def matriz_confusion(juez: np.ndarray, humano: np.ndarray) -> np.ndarray:
    m = np.zeros((K, K))
    for j, h in zip(juez, humano):
        m[j, h] += 1
    m += 0.5                                   # suavizado: evita columnas vacías
    return m / m.sum(axis=0, keepdims=True)    # M[j, k] = P(juez=j | humano=k)


def corregir(p_juez: np.ndarray, m: np.ndarray) -> np.ndarray:
    theta = np.linalg.solve(m, p_juez)
    theta = np.clip(theta, 0, None)
    return theta / theta.sum()


test = pd.read_json("veredictos.jsonl", lines=True)
cal = pd.read_csv("calibracion_con_juez.csv").merge(pd.read_csv("anotado.csv"), on="id")
cod = {c: i for i, c in enumerate(CLASES)}
jt = test["juez"].map(cod).to_numpy()
jc, hc = cal["juez"].map(cod).to_numpy(), cal["etiqueta_final"].map(cod).to_numpy()

p_hat = np.bincount(jt, minlength=K) / len(jt)
theta = corregir(p_hat, matriz_confusion(jc, hc))

rng = np.random.default_rng(0)
boot = []
for _ in range(3000):
    it = rng.integers(0, len(jt), len(jt))
    ic = rng.integers(0, len(jc), len(jc))
    pb = np.bincount(jt[it], minlength=K) / len(jt)
    boot.append(corregir(pb, matriz_confusion(jc[ic], hc[ic])))
lo, hi = np.percentile(np.array(boot), [2.5, 97.5], axis=0)

for k, c in enumerate(CLASES):
    print(f"{c:12s} juez={p_hat[k]:.3f}  corregida={theta[k]:.3f}  IC95% [{lo[k]:.3f}, {hi[k]:.3f}]")
intentos = theta[0] + theta[1]
print(f"Alucinación condicionada a responder: {theta[1] / intentos:.3f}")
Por qué importa para LatamGPT: dos modelos con la misma accuracy en Trueque pueden ser muy distintos: uno que dice "no lo sé" cuando no conoce una tradición boliviana y otro que inventa una respuesta plausible. Para despliegues en educación o servicios públicos, la tasa de alucinación condicionada a responder es el número que más importa.

9. Integración con Inspect AI

Para correr esto de forma repetible sobre cada checkpoint, Inspect AI trae el scorer model_graded_fact, que usa el rol de modelo grader. La plantilla recibe {question}, {criterion} (la referencia), {answer} e {instructions}, y el veredicto se parsea con el patrón GRADE: C/I. Inspect entrega la accuracy ingenua con su error estándar; la corrección de las secciones 6-8 se aplica después sobre los logs.

python · trueque_task.py
"""trueque_task.py: Trueque con juez calibrable en Inspect AI."""
from inspect_ai import Task, task
from inspect_ai.dataset import Sample, hf_dataset
from inspect_ai.scorer import accuracy, grouped, model_graded_fact, stderr
from inspect_ai.solver import generate, system_message

PLANTILLA_ES = """Evalúa si la respuesta enviada es correcta comparándola con la respuesta de referencia.

[Pregunta]: {question}
[Respuesta enviada]: {answer}
[Respuesta de referencia]: {criterion}

{instructions}"""

INSTRUCCIONES_ES = """Es CORRECTA si contiene el dato central de la referencia sin agregar hechos falsos relevantes.
Es INCORRECTA si lo contradice, lo omite, inventa hechos o el modelo declara no saber.
Razona en una o dos oraciones y termina con una línea 'GRADE: C' (correcta) o 'GRADE: I' (incorrecta)."""


def a_sample(r: dict) -> Sample:
    pais = (r["country"] or "Latam").strip().title()
    return Sample(input=r["question"], target=r["reference_answer"],
                  metadata={"country": pais, "topic": r["topic"]})


@task
def trueque() -> Task:
    return Task(
        dataset=hf_dataset("latam-gpt/Trueque-Benchmark-beta-0.1", split="train", sample_fields=a_sample),
        solver=[system_message("Responde con precisión y brevedad. Si no sabes, dilo."), generate()],
        scorer=model_graded_fact(template=PLANTILLA_ES, instructions=INSTRUCCIONES_ES),
        metrics=[accuracy(), stderr(), grouped(accuracy(), "country")],
    )
