Encoders para español y portugués en 2026: de BETO a mmBERT
Cómo elegir, ajustar y servir encoders para español y portugués en 2026: BETO y BERTimbau como baseline, mmBERT, MrBERT-es, BERTomelo y EuroBERT para clasificación, toxicidad, NER y contexto largo con transformers v5. Todo el código usa las APIs vigentes (processing_class, eval_strategy, dtype) y datasets que cargan sin loading scripts.
1. ¿Cuándo usar un encoder y no un LLM?

Un encoder bidireccional de 150-300M parámetros sigue siendo la herramienta correcta para tareas discriminativas a escala: clasificar millones de documentos, extraer entidades o filtrar un corpus de pretraining. Cuesta órdenes de magnitud menos que un LLM generativo por documento y, con datos etiquetados, suele igualarlo o superarlo en clasificación. En LatamGPT los encoders cumplen dos roles: aplicaciones (sentimiento, NER, ruteo de tickets) y filtros de datos (calidad educativa, toxicidad, idioma) que corren sobre billones de tokens.

2. Panorama 2026: qué encoder usar para es/pt

Desde fines de 2024 la arquitectura ModernBERT (RoPE, atención local/global alternada, unpadding y FlashAttention, contexto de 8.192 tokens) se volvió la base de la mayoría de los encoders nuevos. Sobre ella aparecieron mmBERT (multilingüe, más de 1.800 idiomas) y variantes monolingües modernas para español (MrBERT-es, del BSC) y portugués (BERTomelo, de la UnB). BETO, BERTimbau y XLM-R quedan como línea base: siguen siendo fuertes y conviene compararlos siempre.

¿Cuál elegir? Para un solo modelo que cubra español y portugués (y variantes regionales con poco dato), empieza con jhu-clsp/mmBERT-base; si el throughput manda, mmBERT-small. Para español puro prueba BSC-LT/MrBERT-es; para portugués, BERTomelo y BERTimbau. EuroBERT es la alternativa multilingüe con tokenizer tipo Llama. NeoBERT y Ettin (encoders de 2025) son solo inglés: útiles como referencia de arquitectura, no para es/pt.
Ojo con RoBERTa-BNE: la model card de PlanTL-GOB-ES/roberta-base-bne lo marca como deprecado (los modelos del PlanTL migraron al BSC). Sigue descargándose y sirve como baseline histórico en un benchmark, pero no lo uses como default de un proyecto nuevo. Y BERTomelo tiene contexto de 1.024 tokens, no 8k: aunque usa la arquitectura ModernBERT, fue preentrenado con secuencias cortas.

4. Clasificación de sentimiento en español y portugués

Usamos cardiffnlp/tweet_sentiment_multilingual (negativo/neutro/positivo, splits en español y portugués). Su loading script ya no corre con datasets 4.x/5.x (se eliminaron los loading scripts), así que se cargan directamente los .jsonl vía hf://. La etiqueta viene como string ("0", "1", "2") y hay que convertirla a entero.

python — clasificacion.py
import numpy as np
from datasets import load_dataset
from sklearn.metrics import accuracy_score, f1_score
from transformers import (AutoModelForSequenceClassification, AutoTokenizer,
                          DataCollatorWithPadding, Trainer, TrainingArguments)

MODEL_ID = "jhu-clsp/mmBERT-base"   # o BSC-LT/MrBERT-es, dccuchile/bert-base-spanish-wwm-cased...
LANG = "spanish"                    # "portuguese" para pt-BR
BASE = f"hf://datasets/cardiffnlp/tweet_sentiment_multilingual/data/{LANG}"
LABELS = ["negativo", "neutro", "positivo"]

ds = load_dataset("json", data_files={s: f"{BASE}/{s}.jsonl" for s in ["train", "validation", "test"]})
ds = ds.map(lambda ex: {"label": int(ex["label"])})   # "0"/"1"/"2" -> 0/1/2

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)

def tokenize(batch):
    return tokenizer(batch["text"], truncation=True, max_length=256)

ds = ds.map(tokenize, batched=True, remove_columns=["text"])

model = AutoModelForSequenceClassification.from_pretrained(
    MODEL_ID,
    num_labels=len(LABELS),
    id2label=dict(enumerate(LABELS)),
    label2id={l: i for i, l in enumerate(LABELS)},
)

def compute_metrics(eval_pred):
    logits, labels = eval_pred
    preds = np.argmax(logits, axis=-1)
    return {
        "accuracy": accuracy_score(labels, preds),
        "f1_macro": f1_score(labels, preds, average="macro"),
    }

args = TrainingArguments(
    output_dir=f"models/sentimiento-{LANG}",
    learning_rate=5e-5,              # ModernBERT/mmBERT toleran 3e-5 a 8e-5; BETO/BERTimbau, 2e-5 a 5e-5
    per_device_train_batch_size=32, per_device_eval_batch_size=64,
    num_train_epochs=5, weight_decay=0.01,
    warmup_steps=0.1,                # v5: un float < 1 se interpreta como fracción (reemplaza warmup_ratio)
    eval_strategy="epoch", save_strategy="epoch", save_total_limit=1,
    load_best_model_at_end=True, metric_for_best_model="f1_macro",
    bf16=True,                       # fp16=True en T4/V100
    logging_steps=20, report_to="none", seed=42,
)

trainer = Trainer(
    model=model,
    args=args,
    train_dataset=ds["train"],
    eval_dataset=ds["validation"],
    processing_class=tokenizer,      # en v5 ya no existe tokenizer=
    data_collator=DataCollatorWithPadding(tokenizer),
    compute_metrics=compute_metrics,
)
trainer.train()
print(trainer.evaluate(ds["test"], metric_key_prefix="test"))
trainer.save_model(f"models/sentimiento-{LANG}/best")   # guarda también el tokenizer
Ángulo Latam: el split en español de este dataset es pequeño (~1,8k tweets de entrenamiento) y no está balanceado por país. Úsalo para comparar encoders, pero antes de producción agrega ejemplos propios de Chile, Argentina, México o Brasil: el voseo, los modismos y la ironía local son justamente donde los modelos fallan. Con un dataset tan chico, reporta la media de 3 semillas, no una sola corrida.
5. Clasificador de toxicidad con umbral calibrado

Un clasificador binario de toxicidad es la pieza típica de un filtro de datos. textdetox/multilingual_toxicity_dataset trae 5.000 ejemplos en español (columnas text y toxic) en un único split es, así que hacemos un 70/15/15 estratificado. La clave no es el argmax: elegimos el umbral en validación según el costo de cada error y lo guardamos junto al modelo.

python — toxicidad.py
import json
import numpy as np
from datasets import ClassLabel, DatasetDict, load_dataset
from sklearn.metrics import classification_report, f1_score
from transformers import (AutoModelForSequenceClassification, AutoTokenizer,
                          DataCollatorWithPadding, Trainer, TrainingArguments)

MODEL_ID = "BSC-LT/MrBERT-es"
OUT = "models/toxicidad-es"

raw = load_dataset("textdetox/multilingual_toxicity_dataset", split="es")
raw = raw.rename_column("toxic", "label")
raw = raw.cast_column("label", ClassLabel(names=["no_toxico", "toxico"]))
split = raw.train_test_split(test_size=0.3, seed=42, stratify_by_column="label")
held = split["test"].train_test_split(test_size=0.5, seed=42, stratify_by_column="label")
ds = DatasetDict(train=split["train"], validation=held["train"], test=held["test"])

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
ds = ds.map(lambda b: tokenizer(b["text"], truncation=True, max_length=256),
            batched=True, remove_columns=["text"])

model = AutoModelForSequenceClassification.from_pretrained(
    MODEL_ID, num_labels=2,
    id2label={0: "no_toxico", 1: "toxico"}, label2id={"no_toxico": 0, "toxico": 1},
)
args = TrainingArguments(
    output_dir=OUT, learning_rate=5e-5, num_train_epochs=4, warmup_steps=0.1,
    per_device_train_batch_size=32, per_device_eval_batch_size=64,
    eval_strategy="epoch", save_strategy="no", bf16=True, report_to="none", seed=42,
)
trainer = Trainer(model=model, args=args, train_dataset=ds["train"],
                  eval_dataset=ds["validation"], processing_class=tokenizer,
                  data_collator=DataCollatorWithPadding(tokenizer))
trainer.train()

def toxic_probs(split_ds):
    logits = trainer.predict(split_ds).predictions
    z = np.exp(logits - logits.max(axis=1, keepdims=True))
    return (z / z.sum(axis=1, keepdims=True))[:, 1]

# Elegir umbral en validación (aquí maximizando F1; para filtrar pretraining
# suele preferirse alta precisión sobre la clase "no tóxico")
p_val, y_val = toxic_probs(ds["validation"]), np.array(ds["validation"]["label"])
grid = np.linspace(0.05, 0.95, 91)
best_thr = max(grid, key=lambda t: f1_score(y_val, (p_val >= t).astype(int)))

p_test, y_test = toxic_probs(ds["test"]), np.array(ds["test"]["label"])
print(f"Umbral elegido: {best_thr:.2f}")
print(classification_report(y_test, (p_test >= best_thr).astype(int),
                            target_names=["no_toxico", "toxico"], digits=3))

trainer.save_model(OUT)
with open(f"{OUT}/threshold.json", "w", encoding="utf-8") as f:
    json.dump({"threshold": float(best_thr)}, f)
Portugués y vocabulario local: este dataset no tiene split en portugués; para pt-BR necesitas otro corpus (por ejemplo ToLD-Br) o anotación propia, y el insulto rioplatense, chileno o brasileño rara vez aparece en datasets genéricos. Para una cobertura completa de daño (no solo toxicidad léxica) y guardrails en serving, sigue con la guía de guardrails en producción.
6. NER con WikiANN en español y portugués

NER es clasificación a nivel de token. unimelb-nlp/wikiann trae configuraciones es y pt en parquet (20k/10k/10k oraciones) con etiquetas BIO de PER, ORG y LOC. El desafío es alinear la etiqueta de cada palabra con los subwords: solo el primer subword recibe la etiqueta real y el resto, -100, para que el loss lo ignore.

python — ner.py
import numpy as np
from datasets import load_dataset
from seqeval.metrics import f1_score, precision_score, recall_score
from transformers import (AutoModelForTokenClassification, AutoTokenizer,
                          DataCollatorForTokenClassification, Trainer, TrainingArguments)

LANG = "es"   # "pt"
MODEL_ID = {"es": "dccuchile/bert-base-spanish-wwm-cased",      # baseline BETO
            "pt": "neuralmind/bert-base-portuguese-cased"}[LANG]  # baseline BERTimbau
# Para comparar: MODEL_ID = "jhu-clsp/mmBERT-base"

ds = load_dataset("unimelb-nlp/wikiann", LANG)
label_list = ds["train"].features["ner_tags"].feature.names   # O, B-PER, I-PER, B-ORG, ...
id2label = dict(enumerate(label_list))
label2id = {l: i for i, l in id2label.items()}

# Los tokenizers BPE byte-level (p. ej. RoBERTa-BNE) necesitan add_prefix_space=True;
# BERT WordPiece y XLM-R (SentencePiece) no. Con otros BPE byte-level (EuroBERT, ModernBERT
# original) revisa a mano cómo quedan las palabras sueltas antes de comparar F1
tok_kwargs = {"add_prefix_space": True} if "roberta-base-bne" in MODEL_ID else {}
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, **tok_kwargs)

def tokenize_and_align(batch):
    enc = tokenizer(batch["tokens"], truncation=True, max_length=256, is_split_into_words=True)
    all_labels = []
    for i, tags in enumerate(batch["ner_tags"]):
        prev, ids = None, []
        for w in enc.word_ids(batch_index=i):
            if w is None:
                ids.append(-100)          # tokens especiales
            elif w != prev:
                ids.append(tags[w])       # primer subword de la palabra
            else:
                ids.append(-100)          # subwords siguientes
            prev = w
        all_labels.append(ids)
    enc["labels"] = all_labels
    return enc

tokenized = ds.map(tokenize_and_align, batched=True, remove_columns=ds["train"].column_names)

def compute_metrics(p):
    preds = np.argmax(p.predictions, axis=-1)
    y_true, y_pred = [], []
    for pr, lab in zip(preds, p.label_ids):
        keep = lab != -100
        y_true.append([id2label[int(x)] for x in lab[keep]])
        y_pred.append([id2label[int(x)] for x in pr[keep]])
    return {"precision": precision_score(y_true, y_pred),
            "recall": recall_score(y_true, y_pred),
            "f1": f1_score(y_true, y_pred)}

model = AutoModelForTokenClassification.from_pretrained(
    MODEL_ID, num_labels=len(label_list), id2label=id2label, label2id=label2id)

trainer = Trainer(
    model=model,
    args=TrainingArguments(
        output_dir=f"models/ner-{LANG}", learning_rate=3e-5, num_train_epochs=3,
        per_device_train_batch_size=32, per_device_eval_batch_size=64, warmup_steps=0.1,
        eval_strategy="epoch", save_strategy="epoch", save_total_limit=1,
        load_best_model_at_end=True, metric_for_best_model="f1",
        bf16=True, report_to="none"),
    train_dataset=tokenized["train"],
    eval_dataset=tokenized["validation"],
    processing_class=tokenizer,
    data_collator=DataCollatorForTokenClassification(tokenizer),
    compute_metrics=compute_metrics,
)
trainer.train()
print(trainer.evaluate(tokenized["test"], metric_key_prefix="test"))
trainer.save_model(f"models/ner-{LANG}/best")
Más allá de WikiANN: las etiquetas de WikiANN se generaron automáticamente desde enlaces de Wikipedia, así que sirven para comparar modelos, no como techo de calidad. Para dominios reales (legal, salud, prensa local) evalúa en un set anotado a mano; la model card de BERTomelo, por ejemplo, reporta resultados en LeNER-Br (NER legal en portugués).
7. Documentos largos: 8k tokens con FlashAttention 2

BETO y BERTimbau truncan a 512 tokens, lo que obliga a trocear contratos o sentencias en ventanas y agregar logits. mmBERT, MrBERT-es, EuroBERT y ModernBERT aceptan 8.192 tokens. En la arquitectura ModernBERT dos de cada tres capas usan atención local (ventana de 128 tokens), lo que mantiene el costo bajo control; attn_implementation="flash_attention_2" aprovecha esa ventana deslizante con kernels eficientes. Si pides flash_attention_2 sin tener flash-attn instalado, la carga falla: omite el argumento para usar SDPA (el default), que funciona pero es más lento y gasta más memoria a 8k. El unpadding del paper original de ModernBERT no es lo que ganas aquí: el beneficio práctico es la atención local más FA2, y ordenar o agrupar por largo para reducir padding.

python — long_context.py
from datasets import load_dataset
from transformers import (AutoModelForSequenceClassification, AutoTokenizer,
                          DataCollatorWithPadding, Trainer, TrainingArguments)

MODEL_ID = "jhu-clsp/mmBERT-base"   # o BSC-LT/MrBERT-es para español
MAX_LEN = 8192
# JSONL propio: {"text": "<sentencia completa>", "label": 0..N-1}
ds = load_dataset("json", data_files={"train": "data/legal_train.jsonl",
                                      "validation": "data/legal_val.jsonl"})
num_labels = len(set(ds["train"]["label"]))

tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
ds = ds.map(lambda b: tokenizer(b["text"], truncation=True, max_length=MAX_LEN),
            batched=True, remove_columns=["text"])

model = AutoModelForSequenceClassification.from_pretrained(
    MODEL_ID,
    num_labels=num_labels,
    attn_implementation="flash_attention_2",   # requiere flash-attn y GPU Ampere+
)

args = TrainingArguments(
    output_dir="models/legal-8k",
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,     # batch efectivo de 16 documentos
    gradient_checkpointing=True,       # cambia cómputo por memoria
    learning_rate=3e-5, num_train_epochs=3, warmup_steps=0.1,
    bf16=True,                         # FA2 corre en bf16 bajo autocast
    eval_strategy="epoch", save_strategy="epoch", save_total_limit=1, report_to="none",
)
Trainer(model=model, args=args, train_dataset=ds["train"], eval_dataset=ds["validation"],
        processing_class=tokenizer, data_collator=DataCollatorWithPadding(tokenizer)).train()
Memoria: con 8k tokens, batch 2 y gradient checkpointing, un modelo base cabe en una L4 de 24 GB; sin checkpointing apunta a 40-80 GB. Antes de pagar contexto largo, mide cuántos de tus documentos superan realmente 512 o 1.024 tokens: si son pocos, truncar o trocear con un encoder más chico puede ser más barato con igual F1.
8. Inferencia batch y throughput

Para unos cientos de textos basta el pipeline. Para millones (filtros de corpus) conviene un loop propio: ordenar por largo para minimizar padding, torch.inference_mode(), pesos en bf16 y batches grandes.

Versión simple: pipeline

Versión batch con medición de throughput
python — inferencia_batch.py
import json
import time
import torch
from transformers import AutoModelForSequenceClassification, AutoTokenizer

MODEL_DIR = "models/sentimiento-spanish/best"
BATCH_SIZE, MAX_LEN = 128, 512
device = "cuda" if torch.cuda.is_available() else "cpu"
dtype = torch.bfloat16 if device == "cuda" else torch.float32

tokenizer = AutoTokenizer.from_pretrained(MODEL_DIR)
model = AutoModelForSequenceClassification.from_pretrained(MODEL_DIR, dtype=dtype).to(device).eval()
id2label = model.config.id2label

@torch.inference_mode()
def classify(texts: list[str]) -> list[dict]:
    order = sorted(range(len(texts)), key=lambda i: len(texts[i]))   # menos padding
    out: list[dict] = [{} for _ in texts]
    for start in range(0, len(order), BATCH_SIZE):
        idx = order[start:start + BATCH_SIZE]
        enc = tokenizer([texts[i] for i in idx], truncation=True, max_length=MAX_LEN,
                        padding=True, return_tensors="pt").to(device)
        probs = model(**enc).logits.float().softmax(dim=-1)
        conf, pred = probs.max(dim=-1)
        for i, p, c in zip(idx, pred.tolist(), conf.tolist()):
            out[i] = {"label": id2label[p], "score": round(c, 4)}
    return out

with open("data/textos.txt", encoding="utf-8") as f:
    texts = [line.strip() for line in f if line.strip()]

t0 = time.perf_counter()
preds = classify(texts)
if device == "cuda":
    torch.cuda.synchronize()
elapsed = time.perf_counter() - t0
print(f"{len(texts) / elapsed:,.0f} textos/s en {device}")

with open("data/predicciones.jsonl", "w", encoding="utf-8") as f:
    for t, p in zip(texts, preds):
        f.write(json.dumps({"text": t, **p}, ensure_ascii=False) + "\n")

9. Benchmark comparativo: baseline vs encoders modernos

raw = raw.map(lambda ex: {"label": int(ex["label"])})

def run(model_id: str, seed: int) -> tuple[float, float]:
    tok = AutoTokenizer.from_pretrained(model_id)
    ds = raw.map(lambda b: tok(b["text"], truncation=True, max_length=128), batched=True)
    model = AutoModelForSequenceClassification.from_pretrained(model_id, num_labels=3)
    args = TrainingArguments(
        output_dir="tmp_bench", learning_rate=3e-5, num_train_epochs=4, warmup_steps=0.1,
        per_device_train_batch_size=32, per_device_eval_batch_size=128,
        eval_strategy="no", save_strategy="no", bf16=True, report_to="none", seed=seed)
    trainer = Trainer(model=model, args=args, train_dataset=ds["train"].remove_columns(["text"]),
                      processing_class=tok, data_collator=DataCollatorWithPadding(tok))
    trainer.train()
    test = ds["test"].remove_columns(["text"])
    preds = trainer.predict(test).predictions.argmax(-1)
    f1 = f1_score(np.array(test["label"]), preds, average="macro")
    # Throughput de inferencia pura sobre los textos de test
    model = trainer.model.to(torch.bfloat16).eval()
    texts = list(ds["test"]["text"])   # datasets 4+/5 devuelve un objeto Column; lo pasamos a list
    torch.cuda.synchronize()
    t0 = time.perf_counter()
    with torch.inference_mode():
        for i in range(0, len(texts), 128):
            enc = tok(texts[i:i + 128], truncation=True, max_length=128,
                      padding=True, return_tensors="pt").to(model.device)
            model(**enc)
    torch.cuda.synchronize()
    return f1, len(texts) / (time.perf_counter() - t0)

print("| modelo | F1 macro (media ± std) | textos/s |")
for mid in MODELS:
    scores = [run(mid, s) for s in SEEDS]
    f1s = np.array([s[0] for s in scores])
    tps = np.mean([s[1] for s in scores])
    print(f"| {mid} | {f1s.mean():.3f} ± {f1s.std():.3f} | {tps:,.0f} |")
Cómo leer los resultados: en tweets (textos cortos) la diferencia de velocidad depende sobre todo del tamaño del modelo y del vocabulario; las ventajas de unpadding y FlashAttention aparecen con textos largos y batches heterogéneos. Si las diferencias de F1 entre dos modelos quedan dentro de la desviación entre semillas, elige el más rápido. Las salvedades estadísticas (intervalos de confianza, test pareados) están en la guía de evaluación para Latam.
