Mid-training y annealing: diseñar la fase final del pretraining
El 10-20% final del pretraining, con el learning rate bajando a cero y datos de alto valor, es la fase que más rinde por token. Esta guía arma ese tramo para español y portugués. Cubre el schedule WSD, el pool de datos, los microanneals para decidir qué fuentes entran, la descontaminación con decon, el souping de checkpoints y una evaluación que mide ganancia, olvido y preparación para RL.
1. Qué es el mid-training (y qué no es)

Con un schedule WSD (warmup-stable-decay) el LR se mantiene constante durante casi todo el entrenamiento y cae a cero en un tramo final corto. Ese tramo es el anneal o cooldown. Como el checkpoint de la fase estable no depende de cuándo termina el entrenamiento, se pueden lanzar varios anneals desde el mismo punto con mezclas distintas y compararlos. El mid-training aprovecha eso: durante el decay se sobremuestrean matemáticas, código, QA, instrucciones y texto web de la mejor calidad, sin dejar de mezclar web general.

La evidencia es consistente. Blakeney et al. (2024) suben hasta +6.90 pp en MMLU, +8.26 pp en GSM8K y +6.17 pp en HumanEval en un 7B entrenado con 1T tokens, solo sobremuestreando datos de dominio al final. OLMo 2 dedica al mid-training el 5-10% de los FLOPs, con el LR decayendo linealmente a cero. Y para razonamiento hay un efecto de segundo orden: un buen mid-training hace al modelo base mucho más receptivo al RL (OctoThinker, Interplay of Pre-/Mid-Training and RL).

Si partes de un modelo público ya terminado (Llama, Qwen, Gemma), su LR ya terminó en ~0. Lo que harás es continual pretraining con re-warmup (ver la guía de continual pretraining). Para un anneal "de verdad" necesitas un checkpoint previo al decay final (la meseta de un WSD o, en OLMo 2, el punto donde se cortó el coseno de stage 1). OLMo 2, Olmo 3 y SmolLM3 publican checkpoints intermedios en el Hub, por ejemplo la rama stage1-step1907359-tokens4001B de allenai/OLMo-2-0425-1B, el último checkpoint de stage 1 antes de su anneal. Esta guía la usa como laboratorio.
2. Recetas publicadas (2024-2026)

Todas las recetas abiertas recientes separan una fase larga de pretraining general de un anneal corto con otra mezcla. No todas usan WSD estricto: OLMo 2 y Olmo 3 cortan un schedule coseno antes de terminarlo y desde ahí decaen linealmente a cero. Las diferencias importantes están en cuánto dura el anneal, qué entra y cómo se decide.

Momento y peso interactúan. Liu et al. (2025) encuentran que el beneficio del mid-training es mayor en dominios lejanos a la web (código, matemáticas). También muestran que el momento de introducción y el peso interactúan: introducir el dominio temprano tolera pesos altos, pero si entra tarde el peso debe ser bajo, y subir el peso al final no compensa la entrada tardía. Si quieres un peso alto de un dominio nuevo, introdúcelo antes (como en las etapas 2-3 de SmolLM3) y no solo en el último decay.

4. El schedule: WSD y el decay

La forma del decay importa menos que llegar a cero. Hägele et al. (2024) muestran que un cooldown de ~10-20% con forma 1-sqrt iguala o supera al coseno, y OLMo 2 encuentra que, tras decaer linealmente a cero durante 50B-100B tokens, corridas con distinto LR pico terminan con una loss equivalente. El problema real aparece cuando partes de pesos sin el estado del optimizador (lo normal con checkpoints del Hub): los momentos de AdamW arrancan en cero, así que conviene un re-warmup corto.

python — wsd_schedule.py
import math

import torch
from torch.optim.lr_scheduler import LambdaLR


def wsd_lambda(step: int, warmup: int, stable: int, decay: int, kind: str = "linear") -> float:
    """Multiplicador del LR pico: warmup lineal, meseta y decay a 0."""
    if step < warmup:
        return (step + 1) / warmup
    if step < warmup + stable:
        return 1.0
    t = min(1.0, (step - warmup - stable) / max(1, decay))  # progreso del decay en [0, 1]
    return {"linear": 1.0 - t, "1-sqrt": 1.0 - math.sqrt(t),
            "cosine": 0.5 * (1.0 + math.cos(math.pi * t))}[kind]


# Anneal de 10B tokens con batch global de ~1M tokens = ~9.5k pasos, partiendo de un
# checkpoint estable SIN estado del optimizador: re-warmup de 100 pasos y decay en el resto.
TOTAL, WARMUP = 9_500, 100
opt = torch.optim.AdamW(torch.nn.Linear(8, 8).parameters(), lr=4e-4)
sched = LambdaLR(opt, lambda s: wsd_lambda(s, WARMUP, 0, TOTAL - WARMUP))
for step in range(TOTAL):
    opt.step()
    sched.step()
    if step in (0, 99, 5_000, TOTAL - 1):
        print(f"paso {step:>5}: lr = {sched.get_last_lr()[0]:.2e}")
LR pico del anneal: usa el LR que tenía el modelo en el checkpoint del que partes: el LR de la meseta si fue WSD, o el valor del coseno en ese paso si fue un coseno truncado como en OLMo 2 (está en el paper o en la config y los logs de entrenamiento). Si no lo conoces, prueba 2-3 valores con microanneals pequeños. En transformers v5 no necesitas esta función: lr_scheduler_type="warmup_stable_decay" con lr_scheduler_kwargs={"num_decay_steps": ..., "decay_type": "linear"} hace lo mismo, y es lo que usa el script de la sección 7.
5. Materializar el pool con datatrove

Cada fuente se extrae por separado a JSONL. Así se descontamina cada una y las variantes de microanneal se arman combinando fuentes al entrenar, sin re-extraer nada. Las fuentes se declaran una vez y cada una pasa por su propio pipeline:

python — 01_build_pool.py
from dataclasses import dataclass
from typing import Callable

from datatrove.executor import LocalPipelineExecutor
from datatrove.pipeline.filters import LambdaFilter, SamplerFilter
from datatrove.pipeline.readers import ParquetReader
from datatrove.pipeline.writers import JsonlWriter


@dataclass
class Source:
    name: str
    path: str                                  # carpeta hf://datasets/... o local
    glob: str = "*.parquet"
    id_key: str = "id"
    read_metadata: bool = False                # True si el filtro necesita columnas extra
    keep: Callable[[dict], bool] | None = None # filtro sobre doc.metadata
    rate: float = 1.0                          # fracción de documentos a conservar
    adapter: Callable | None = None


def openthoughts_adapter(self, data: dict, path: str, id_in_file) -> dict:
    """Convierte una conversación de OpenThoughts3 en texto plano para pretraining."""
    turns = data["conversations"]
    question = next(t["value"] for t in turns if t["from"] == "human")
    answer = next(t["value"] for t in turns if t["from"] == "gpt")
    return {"text": f"Problem:\n{question}\n\nSolution:\n{answer}",
            "id": f"{path}/{id_in_file}", "metadata": {"domain": data.get("domain")}}


SOURCES = [
    # FineWeb2-HQ ya es el top 10%: leemos solo text/id (evita bajar la columna de embeddings)
    Source("fw2hq_spa", "hf://datasets/epfml/FineWeb2-HQ/spa_Latn", glob="000_000[0-4]?.parquet"),
    Source("fw2hq_por", "hf://datasets/epfml/FineWeb2-HQ/por_Latn", glob="000_000[0-4]?.parquet"),
    Source("latam_edu_spa", "hf://datasets/latam-gpt/fineweb2-spa_Latn-edu/data",
           glob="train-0000?-of-00256.parquet", read_metadata=True,
           keep=lambda m: m.get("int_score", 0) >= 3),
    Source("finepdfs_edu_spa", "hf://datasets/HuggingFaceFW/finepdfs-edu/data/spa_Latn/train"),
    Source("finepdfs_edu_por", "hf://datasets/HuggingFaceFW/finepdfs-edu/data/por_Latn/train"),
    Source("wiki_es", "hf://datasets/wikimedia/wikipedia/20231101.es"),
    Source("wiki_pt", "hf://datasets/wikimedia/wikipedia/20231101.pt"),
    Source("finemath4", "hf://datasets/HuggingFaceTB/finemath/finemath-4plus", id_key="url"),
    Source("openthoughts3", "hf://datasets/open-thoughts/OpenThoughts3-1.2M/data",
           read_metadata=True, adapter=openthoughts_adapter, rate=0.3),
    # Replay: una muestra de TU mezcla de la fase estable (placeholder)
    Source("replay_web", "hf://datasets/<TU_ORG>/<mezcla-fase-estable>", rate=0.02),
]

for src in SOURCES:
    pipeline = [
        ParquetReader(src.path, glob_pattern=src.glob, id_key=src.id_key,
                      read_metadata=src.read_metadata, adapter=src.adapter),
    ]
    if src.keep is not None:
        pipeline.append(LambdaFilter(lambda doc, keep=src.keep: keep(doc.metadata)))
    if src.rate < 1.0:
        pipeline.append(SamplerFilter(rate=src.rate, seed=42))
    # JSONL por fuente: decon lee un directorio de .jsonl (también .gz/.zst) en el paso siguiente
    pipeline.append(JsonlWriter(f"pool/raw/{src.name}", compression=None))

    LocalPipelineExecutor(pipeline=pipeline, tasks=32, workers=16,
                          logging_dir=f"logs/build_pool/{src.name}").run()
Cuánto extraer: para un microanneal necesitas ~5B tokens de la fuente evaluada y otros ~5B de web, así que no hace falta bajar todo. Los glob de arriba limitan FineWeb2-HQ a 50 archivos por idioma y el corpus edu de LatamGPT a 10. Amplíalos solo para el anneal final. Con read_metadata=False, datatrove lee únicamente las columnas text e id del parquet.
6. Descontaminar con decon (también contra benchmarks es/pt)

El anneal es justo donde más daño hace la contaminación: datos de alto valor, al final, con LR que todavía mueve los pesos. Olmo 3 usa decon (Rust). La herramienta muestrea 5-gramas cada 10 tokens contra un índice de los benchmarks y expande cada coincidencia. Luego puntúa pregunta, respuesta y pasaje, y elimina los documentos sobre el umbral (0.8 por defecto). Por defecto trae solo gsm8k, mmlu y agi_eval, así que hay que sumar los benchmarks en español y portugués en su formato de referencia:

python — make_decon_evals.py
import hashlib
import itertools
import json
from pathlib import Path

from datasets import load_dataset

OUT = Path("evals_es_pt")
OUT.mkdir(exist_ok=True)
doc_ids = itertools.count(10_000_000)  # lejos de los doc_id de bundled-evals


def record(key, cfg, i, question, answer=None, passage=None, is_correct=None, sub=None) -> dict:
    """Registro en el formato de referencia de decon (doc/eval-datasets.md)."""
    fp = hashlib.sha256(f"{passage or ''}{question}{answer or ''}".encode()).hexdigest()[:16]
    rec = {"eval_key": key, "config": cfg, "split": "test", "eval_instance_index": i,
           "doc_id": next(doc_ids), "question": question, "fingerprint": fp,
           "answer": answer, "passage": passage, "is_correct": is_correct, "sub_index": sub}
    return {k: v for k, v in rec.items() if v is not None}


def dump(name: str, rows: list[dict]) -> None:
    with open(OUT / f"{name}.jsonl", "w", encoding="utf-8") as f:
        f.writelines(json.dumps(r, ensure_ascii=False) + "\n" for r in rows)
    print(f"{name}: {len(rows):,} referencias")


mgsm = load_dataset("juletxara/mgsm", "es", split="test")
dump("mgsm_es", [record("mgsm_es", "es", i, ex["question"], str(ex["answer_number"]))
                 for i, ex in enumerate(mgsm)])

for lang in ("es", "pt"):  # Global-MMLU: una referencia por opción, marcando la correcta
    ds = load_dataset("CohereLabs/Global-MMLU", lang, split="test")
    dump(f"global_mmlu_{lang}", [
        record(f"global_mmlu_{lang}", lang, i, ex["question"], ex[f"option_{c}"],
               is_correct=(ex["answer"] == c.upper()), sub=j)
        for i, ex in enumerate(ds) for j, c in enumerate("abcd")])

for cfg in ("spa_Latn", "por_Latn"):  # Belebele: pasaje + pregunta + opciones
    ds = load_dataset("facebook/belebele", cfg, split="test")
    dump(f"belebele_{cfg}", [
        record(f"belebele_{cfg}", cfg, i, ex["question"], ex[f"mc_answer{k}"],
               passage=ex["flores_passage"], is_correct=(str(k) == str(ex["correct_answer_num"])), sub=k - 1)
        for i, ex in enumerate(ds) for k in range(1, 5)])

7. Tokenizar y correr microanneals

El protocolo de Olmo 3 es simple y barato. Desde el mismo checkpoint estable, se entrena una variante con 5B tokens de la fuente candidata más 5B de web y se compara contra un baseline de 10B de solo web, con el mismo número de tokens y el mismo LR. Así se mide el efecto de la fuente por encima del efecto de seguir entrenando. Primero se tokeniza cada fuente limpia con el tokenizer del modelo base:

El script de anneal arma cada variante a partir de los tokens por fuente, así que los pesos de la mezcla quedan exactos en tokens. Usa el Trainer de transformers v5 con el scheduler WSD nativo, que alcanza para modelos de hasta ~8B en un nodo. Si tu fase estable corrió en torchtitan, OLMo-core o nanotron, replica la misma lógica de mezcla y decay ahí y reanuda también el estado del optimizador.

python — 04_microanneal.py
import argparse
import os

import torch
from datatrove.utils.dataset import DatatroveFolderDataset
from torch.utils.data import ConcatDataset, Subset
from transformers import AutoModelForCausalLM, AutoTokenizer, Trainer, TrainingArguments

BASE = "allenai/OLMo-2-0425-1B"
REVISION = "stage1-step1907359-tokens4001B"  # último checkpoint de stage 1, antes del anneal
SEQ_LEN = 4096
TOKEN_SIZE = 4         # vocab de ~100k (más de 65k): datatrove guarda tokens de 4 bytes
PEAK_LR = 4e-4         # valor de ejemplo: usa el LR que tenía tu modelo en ese checkpoint
WARMUP = 100           # re-warmup corto: los pesos del Hub no traen estado de AdamW
PER_DEVICE, GRAD_ACC = 4, 8

# "Web" del protocolo: replay de la fase estable + web es/pt de alta calidad
WEB_MIX = {"replay_web": 0.5, "fw2hq_spa": 0.3, "fw2hq_por": 0.2}


def variant(target: str | None, total: float) -> dict[str, float]:
    """target=None: baseline de solo web. Si no: 50% fuente + 50% web."""
    web_tokens = total if target is None else total / 2
    mix = {name: w * web_tokens for name, w in WEB_MIX.items()}
    if target is not None:
        mix[target] = mix.get(target, 0.0) + total / 2
    return mix


def build_dataset(mix: dict[str, float], seed: int) -> ConcatDataset:
    g = torch.Generator().manual_seed(seed)
    parts = []
    for name, tokens in mix.items():
        ds = DatatroveFolderDataset(f"pool/tokens/{name}", seq_len=SEQ_LEN,
                                    token_size=TOKEN_SIZE, shuffle=True, seed=seed)
        n = int(tokens // (SEQ_LEN + 1))
        if n > len(ds):
            raise ValueError(f"{name}: se piden {n:,} secuencias y hay {len(ds):,}")
        idx = torch.randperm(len(ds), generator=g)[:n].tolist()
        parts.append(Subset(ds, idx))
        print(f"  {name:<18} {tokens / 1e9:5.2f}B tokens ({n:,} secuencias)")
    return ConcatDataset(parts)


def collate(batch: list[dict]) -> dict:
    ids = torch.stack([b["input_ids"] for b in batch]).long()
    return {"input_ids": ids, "labels": ids.clone()}  # el modelo desplaza los labels


parser = argparse.ArgumentParser()
parser.add_argument("--target", default=None, help="fuente candidata; omitir = baseline web")
parser.add_argument("--tokens", type=float, default=10e9)
parser.add_argument("--seed", type=int, default=0)
args = parser.parse_args()

run = f"anneal-{args.target or 'web'}-{args.tokens / 1e9:.0f}B-s{args.seed}"
train_ds = build_dataset(variant(args.target, args.tokens), args.seed)
world = int(os.environ.get("WORLD_SIZE", 1))
max_steps = len(train_ds) // (PER_DEVICE * GRAD_ACC * world)

model = AutoModelForCausalLM.from_pretrained(BASE, revision=REVISION, dtype=torch.float32)

targs = TrainingArguments(
    output_dir=f"ckpt/{run}",
    max_steps=max_steps,
    per_device_train_batch_size=PER_DEVICE,
    gradient_accumulation_steps=GRAD_ACC,
    learning_rate=PEAK_LR,
    warmup_steps=WARMUP,
    lr_scheduler_type="warmup_stable_decay",
    lr_scheduler_kwargs={"num_decay_steps": max_steps - WARMUP,
                         "decay_type": "linear", "min_lr_ratio": 0.0},
    weight_decay=0.1, adam_beta1=0.9, adam_beta2=0.95, max_grad_norm=1.0,
    bf16=True, gradient_checkpointing=True, optim="adamw_torch_fused",
    logging_steps=10, save_strategy="steps", save_steps=2_000, save_total_limit=1,
    seed=args.seed, data_seed=args.seed, dataloader_num_workers=4,
    remove_unused_columns=False, report_to="wandb", run_name=run,
)

trainer = Trainer(model=model, args=targs, train_dataset=train_ds, data_collator=collate)
trainer.train()
trainer.save_model(f"ckpt/{run}/final")
AutoTokenizer.from_pretrained(BASE).save_pretrained(f"ckpt/{run}/final")

8. Souping: promediar anneals

OLMo 2 7B corre tres anneals de 50B con distinto orden de datos y promedia los pesos. Olmo 3 hace dos corridas paralelas de 100B y las fusiona. Como todos parten del mismo checkpoint estable, los modelos quedan en la misma cuenca y el promedio suele igualar o superar al mejor individual. El script promedia checkpoints guardados con save_pretrained (mismo sharding):

python — 05_soup.py
"""Uso: python 05_soup.py ckpt/run-s0/final ckpt/run-s1/final ckpt/run-s2/final ckpt/soup"""
import shutil
import sys
from pathlib import Path

from safetensors.torch import load_file, save_file

*inputs, out = sys.argv[1:]
ckpts = [Path(p) for p in inputs]
out = Path(out)
out.mkdir(parents=True, exist_ok=True)

shards = sorted(p.name for p in ckpts[0].glob("*.safetensors"))
assert all((c / s).exists() for c in ckpts for s in shards), "mismo max_shard_size en todos"

for shard in shards:
    states = [load_file(str(c / shard)) for c in ckpts]
    avg = {k: (sum(s[k].float() for s in states) / len(states)).to(v.dtype)
           for k, v in states[0].items()}
    save_file(avg, str(out / shard), metadata={"format": "pt"})
    print(f"{shard}: {len(avg)} tensores promediados")

# config, tokenizer e índice de shards se copian del primer checkpoint
for f in ckpts[0].iterdir():
    if f.is_file() and f.suffix != ".safetensors":
        shutil.copy(f, out / f.name)

Prueba rápida de preparación para RL

El mejor checkpoint en benchmarks no siempre es el que mejor responde al RL. OctoThinker lo muestra con FineMath-4plus, y por eso Olmo 3 evalúa también la capacidad de post-entrenamiento. Una prueba barata consiste en correr el mismo GRPO corto sobre cada candidato y comparar las curvas de reward y el MGSM-es final. El código sigue la guía de GRPO. Revisa la firma de GRPOTrainer en tu versión de TRL, porque cambió entre versiones.

python — 07_rl_probe.py
import re
import sys
from pathlib import Path

from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer

CKPT = sys.argv[1] if len(sys.argv) > 1 else "ckpt/anneal-finemath4-10B-s0/final"
TRAIN = "openai/gsm8k"  # o "<TU_ORG>/gsm8k-es": traducción revisada del split train
NUM = re.compile(r"-?\d[\d.,]*\d|-?\d")


def parse_num(s: str) -> float | None:
    s = re.sub(r"[.,](?=\d{3}\b)", "", s).replace(",", ".")  # 1.000,5 / 1,000.5 -> 1000.5
    try:
        return float(s)
    except ValueError:
        return None


def to_prompt(ex: dict) -> dict:
    # Modelo base sin chat template: prompt en texto plano y en español
    return {"prompt": f"Pregunta: {ex['question']}\nRespuesta: Pensemos paso a paso.",
            "answer": ex["answer"].split("####")[-1].strip()}


def reward_correct(completions: list[str], answer: list[str], **kwargs) -> list[float]:
    rewards = []
    for completion, gold in zip(completions, answer):
        text = completion.split("\nPregunta:")[0]   # el base suele inventar otra pregunta
        nums = NUM.findall(text)
        pred = parse_num(nums[-1]) if nums else None
        ref = parse_num(gold)
        rewards.append(1.0 if pred is not None and ref is not None and abs(pred - ref) < 1e-6 else 0.0)
    return rewards


train = load_dataset(TRAIN, "main", split="train").map(to_prompt, remove_columns=["question"])

config = GRPOConfig(
    output_dir=f"rl-probe/{Path(CKPT).parent.name}",
    max_steps=200,
    learning_rate=1e-6,
    per_device_train_batch_size=8,
    gradient_accumulation_steps=4,   # 32 completions por paso: divisible por num_generations
    num_generations=8,
    max_completion_length=512,
    temperature=1.0,
    bf16=True,
    use_vllm=True, vllm_mode="colocate",
    logging_steps=5, report_to="wandb",
    run_name=f"rl-probe-{Path(CKPT).parent.name}",
)

trainer = GRPOTrainer(model=CKPT, reward_funcs=reward_correct, args=config, train_dataset=train)
trainer.train()
trainer.save_model(config.output_dir)
# Después: bash 06_eval.sh rl-probe/<run> y comparar mgsm_native_cot_es entre candidatos
Hardware de la prueba: con un modelo 1B y vLLM en modo colocate entra en 1×H100 80GB (estimación: 1-3 h para 200 pasos). Lo que importa es la diferencia relativa entre candidatos con la misma receta, no el número absoluto. Si la curva de reward del candidato sube más rápido y el MGSM-es final es mayor, esa mezcla deja un mejor punto de partida para el post-training.
